# Enumerating & Retrieving Password Policies

How we pull the password policy depends on whether we have valid domain credentials, and if not, whether the domain has legacy misconfigurations (SMB NULL sessions, LDAP anonymous bind) still enabled.

---
## Linux vs. Windows — Which Technique Goes Where

| Attack Host | Access Level                                | Technique                                                                       | Tool(s)                                                                                                |
| ----------- | ------------------------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| **Linux**   | Credentialed                                | Query password policy over SMB with valid creds                                 | `crackmapexec smb <ip> -u <user> -p <pass> --pass-pol`                                                 |
| **Linux**   | Unauthenticated (SMB NULL session)          | Connect to a Domain Controller with a blank username/password over SMB          | `rpcclient -U "" -N <ip>` (→ `getdompwinfo`), `enum4linux -P <ip>`, `enum4linux-ng -P <ip> -oA <name>` |
| **Linux**   | Unauthenticated (LDAP anonymous bind)       | Query LDAP directly without authenticating                                      | `ldapsearch -h <ip> -x -b "DC=...,DC=..." -s sub "*"`                                                  |
| **Windows** | Unauthenticated (NULL session, less common) | Same NULL session concept, but initiated from Windows                           | `net use \\DC01\ipc$ "" /u:""`                                                                         |
| **Windows** | Credentialed                                | Query policy using built-in Windows tooling — no external tools needed, net.exe | `net accounts`                                                                                         |
| **Windows** | Credentialed                                | Query policy using an offensive PowerShell toolkit                              | `Import-Module .\PowerView.ps1` → `Get-DomainPolicy`                                                   |

> [!tip] The core distinction
> - **Linux-side** techniques center on talking to the DC over **SMB (rpcclient/enum4linux/CrackMapExec)** or **LDAP (ldapsearch)** — useful whether or not you have credentials, since NULL sessions/anonymous binds don't require any.
> - **Windows-side** techniques rely on being logged into (or having a session on) a **Windows box already**, using `net.exe` (always available, no tooling needed) or **PowerView** (requires importing the module, more detailed output).
> - `net use` NULL sessions from Windows are the direct Windows equivalent of the Linux `rpcclient -U "" -N` NULL session — same underlying misconfiguration, different OS doing the asking.

## From Linux — SMB NULL Sessions (Unauthenticated)

Without credentials, we may still be able to pull the policy via an **SMB NULL session** or **LDAP anonymous bind**.

> [!info] What's an SMB NULL session?
> An unauthenticated connection that can retrieve domain info — full user/group/computer listings, account attributes, and the password policy — with **zero credentials**. Usually the result of legacy DCs upgraded in place, carrying forward insecure defaults from older Windows Server versions (anonymous access was granted to certain shares by default when domains were created in earlier Windows Server releases).

We can use [rpcclient](https://www.samba.org/samba/docs/current/man-html/rpcclient.1.html) to check a Domain Controller for SMB NULL session access.
### Checking Access with rpcclient

```shellsession
s0nam@htb[/htb]$ rpcclient -U "" -N 172.16.5.5

rpcclient $> querydominfo
Domain:     INLANEFREIGHT
Server:
Comment:
Total Users:    3650
Total Groups:   0
Total Aliases:  37
Sequence No:    1
Force Logoff:   -1
Domain Server State:    0x1
Server Role:    ROLE_DOMAIN_PDC
Unknown 3:  0x1
```

`-U ""` (blank username) + `-N` (no password prompt) = attempting a NULL session. A successful `querydominfo` response confirms NULL session access works.

### Pulling the Password Policy with rpcclient

```shellsession
rpcclient $> getdompwinfo
min_password_length: 8
password_properties: 0x00000001
    DOMAIN_PASSWORD_COMPLEX
```

Confirms a relatively weak policy: 8-character minimum.

### Using enum4linux

[enum4linux](https://github.com/portcullislabs/enum4linux) is a tool built around the [Samba suite of tools](https://www.samba.org/samba/docs/current/man-html/samba.7.html) (`nmblookup`, `net`, `rpcclient`, `smbclient`) for Windows host/domain enumeration. Pre-installed on many pentest distros (e.g. Parrot Security).

| Tool           | Purpose                                                        |
| -------------- | -------------------------------------------------------------- |
| **enum4linux** | Wrapper script that automates Windows/SMB enumeration          |
| **nmblookup**  | Finds NetBIOS names                                            |
| **rpcclient**  | Enumerates information through RPC                             |
| **smbclient**  | Lists and accesses SMB shares                                  |
| **net**        | Enumerates domain users, groups, and other network information |

**Ports used by common enumeration tools:**

| Tool        | Ports                                         |
| ----------- | --------------------------------------------- |
| `nmblookup` | 137/UDP                                       |
| `nbtstat`   | 137/UDP                                       |
| `net`       | 139/TCP, 135/TCP, TCP+UDP 135 and 49152–65535 |
| `rpcclient` | 135/TCP                                       |

## NULL Session — from Windows

**net use** : Windows command used to create, view, or remove connections to network resources (such as SMB shares, printers, or IPC$)
Less common to run this from Windows, but possible via `net use`:

```cmd
C:\htb> net use \\DC01\ipc$ "" /u:""
The command completed successfully.
```

# Why use `net use`?

On **Linux**, you would test a null session with:

```
smbclient -N -L //172.16.5.5
```

or

```
rpcclient -U "" -N 172.16.5.5
```

On **Windows**, there is no `rpcclient`, so `net use` is the built-in way to test whether an anonymous SMB connection is allowed.
### Common Authentication Errors (Useful for Diagnosing Account State)

**Account disabled:**
```cmd
C:\htb> net use \\DC01\ipc$ "" /u:guest
System error 1331 has occurred.

This user can't sign in because this account is currently disabled.
```

**Wrong password:**
```cmd
C:\htb> net use \\DC01\ipc$ "password" /u:guest
System error 1326 has occurred.

The user name or password is incorrect.
```

**Account locked out:**
```cmd
C:\htb> net use \\DC01\ipc$ "password" /u:guest
System error 1909 has occurred.

The referenced account is currently locked out and may not be logged on to.
```

> [!tip] Useful during spraying
> These specific error codes let you tell *why* a login attempt failed — e.g. distinguishing "wrong password" from "already locked out" helps avoid accidentally spraying a known-locked account further.

## From Linux — LDAP Anonymous Bind

> [!info] What's an LDAP anonymous bind?
> Like the SMB NULL session, but over LDAP — lets an unauthenticated attacker pull user/group/computer listings, attributes, and the password policy. Legacy configuration; since **Windows Server 2003**, only authenticated users are supposed to be permitted to issue LDAP requests by default. Still seen occasionally when an admin loosened LDAP access for some application and unintentionally over-granted anonymous access to all AD objects.

With an LDAP anonymous bind, we can use LDAP-specific enumerationTools: `windapsearch.py`, `ldapsearch`, `ad-ldapdomaindump.py`, etc.

### Using  [ldapsearch](https://linux.die.net/man/1/ldapsearch)

```shellsession
s0nam@htb[/htb]$ ldapsearch -h 172.16.5.5 -x -b "DC=INLANEFREIGHT,DC=LOCAL" -s sub "*" | grep -m 1 -B 10 pwdHistoryLength

forceLogoff: -9223372036854775808
lockoutDuration: -18000000000
lockOutObservationWindow: -18000000000
lockoutThreshold: 5
maxPwdAge: -9223372036854775808
minPwdAge: -864000000000
minPwdLength: 8
modifiedCountAtLastProm: 0
nextRid: 1002
pwdProperties: 1
pwdHistoryLength: 24
```

| Flag | Meaning |
|---|---|
| `-h` | target host (deprecated in newer versions — use `-H` instead) |
| `-x` | simple authentication (anonymous bind here since no `-D`/`-w` creds given) |
| `-b "DC=..."` | search base — the domain's distinguished name |
| `-s sub` | search scope: subtree |
| `"*"` | return all attributes |

Confirms: `minPwdLength: 8`, `lockoutThreshold: 5`, `pwdProperties: 1` (complexity enabled).

## From Windows

If authenticated to the domain from a Windows host, use built-in **`net.exe`**, or tools like **PowerView**, **CrackMapExec** (Windows port), **SharpMapExec**, **SharpView**.

> [!tip] Why built-ins matter
> Useful when you land on a Windows box and can't (or shouldn't) transfer external tools onto it, or the client positioned you on a host with no way to bring tooling in.

### Using net.exe

```cmd
C:\htb> net accounts

Force user logoff how long after time expires?:       Never
Minimum password age (days):                          1
Maximum password age (days):                          Unlimited
Minimum password length:                              8
Length of password history maintained:                24
Lockout threshold:                                    5
Lockout duration (minutes):                           30
Lockout observation window (minutes):                 30
Computer role:                                        SERVER
The command completed successfully.
```

**Reading this:**
- Passwords never expire (Maximum password age = Unlimited)
- Minimum length 8 → weak passwords likely exist
- Lockout threshold 5 wrong attempts
- Locked accounts auto-unlock after 30 minutes

> [!tip] What this means for spraying
> This policy is favorable for password spraying: try `Welcome1`-style weak passwords (8-char minimum satisfied), and spray **2–3 passwords every 31 minutes** to stay safely under the 5-attempt lockout threshold. Even with auto-unlock, **never intentionally lock out accounts.**

## Analyzing the Password Policy — INLANEFREIGHT.LOCAL

| Setting                   | Value      | Notes                                                                                                                                   |
| ------------------------- | ---------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| Minimum password length   | 8          | Common; more orgs now enforce 10–14 chars, which shrinks weak-password options but doesn't eliminate spraying as a vector               |
| Account lockout threshold | 5          | Some orgs set this lower (3), or don't lock out at all                                                                                  |
| Lockout duration          | 30 minutes | Varies by org                                                                                                                           |
| Auto-unlock               | Yes        | Some orgs require manual admin unlock instead — locking out accounts there is far more disruptive                                       |
| Password complexity       | Enabled    | Requires 3 of 4: uppercase, lowercase, number, special char — `Password1` or `Welcome1` technically satisfy this while still being weak |

### Default Windows Domain Password Policy (Out of the Box)

Many orgs never change this from the default:

| Policy                                      | Default Value |
| ------------------------------------------- | ------------- |
| Enforce password history                    | 24 days       |
| Maximum password age                        | 42 days       |
| Minimum password age                        | 1 day         |
| Minimum password length                     | 7             |
| Password must meet complexity requirements  | Enabled       |
| Store passwords using reversible encryption | Disabled      |
| Account lockout duration                    | Not set       |
| Account lockout threshold                   | 0             |
| Reset account lockout counter after         | Not set       |

## Next Steps

With the policy in hand, next is building the target user list for the spray. If the policy **can't** be obtained (common on external engagements, or internal ones where none of the above methods work), exercise extreme caution:

> [!warning] When you don't know the policy
> - Ask the client for their password policy if a comprehensive assessment is the goal
> - If that's not possible: run **one, at most two**, spray attempts total (internal or external), waiting **over an hour** between them if doing two
> - Don't assume every org uses the common "5 attempts / 30-min auto-unlock" default — some use a threshold of 3 and require **manual admin intervention** to unlock

**We never want to be the pentester who locks out an entire organization's accounts.**

## Key Takeaways

- [ ] Credentialed: `crackmapexec smb <ip> -u <user> -p <pass> --pass-pol`
- [ ] Unauthenticated (SMB NULL session): `rpcclient -U "" -N <ip>` → `getdompwinfo`, or `enum4linux -P <ip>` / `enum4linux-ng -P <ip> -oA <name>`
- [ ] Unauthenticated (LDAP anonymous bind): `ldapsearch -h <ip> -x -b "DC=...,DC=..." -s sub "*"`
- [ ] From Windows (authenticated): `net accounts` (built-in, no tooling needed) or PowerView's `Get-DomainPolicy`
- [ ] `net use` error codes reveal account state: 1331 = disabled, 1326 = wrong password, 1909 = locked out
- [ ] Default out-of-box policy: 7-char minimum, complexity on, no lockout threshold — many orgs never change this
- [ ] If the policy can't be obtained: max 1–2 spray attempts total, 1+ hour apart, or ask the client directly
- [ ] Goal throughout: **never** lock out real accounts
