# Password Spraying - Making a Target User List

Before spraying, we need a list of **valid domain usernames**. Four main ways to build one:

1. **SMB NULL session** → pull the full domain user list from the DC
2. **LDAP anonymous bind** → query LDAP anonymously for the user list
3. **Kerbrute** → validate candidate usernames from a wordlist (e.g. [statistically-likely-usernames](https://github.com/insidetrust/statistically-likely-usernames)) or from LinkedIn scraping ( [linkedin2username](https://github.com/initstring/linkedin2username))
4. **Valid credentials** (client-provided, or obtained via LLMNR/NBT-NS poisoning, or an earlier small-wordlist spray) → query AD directly

> [!tip] Always pair this with the password policy
> Whichever method you use, also try to enumerate the **password policy** (Section 9) at the same time if possible — an SMB NULL session, LDAP anonymous bind, or valid creds can usually get you both. Minimum length + complexity shapes which passwords are worth trying; lockout threshold + bad-password timer tells you how many attempts you can safely run and how long to wait between rounds.

> [!warning] No policy available?
> Ask the client. If they won't provide it: either one very targeted "hail mary" spray attempt if all other foothold options are exhausted, or one spray every few hours to stay safe.
> **Hail mary**: a last-resort attempt with a low probability of success, made when other options have been exhausted.

### Always Log Your Activity

Regardless of method or whether you have the policy, keep a record of:
- Accounts targeted
- Domain Controller used
- Time and date of the spray
- Password(s) attempted

This avoids duplicated effort and gives you something concrete to hand the client if they flag suspicious logons or a lockout — proof of exactly what you did and when.

## Linux vs. Windows — Where Each Technique Applies

| Situation | Platform | Technique |
|---|---|---|
| No creds, SMB NULL session available | Linux | `enum4linux -U`, `rpcclient enumdomusers`, `crackmapexec --users` |
| No creds, LDAP anonymous bind available | Linux | `ldapsearch`, `windapsearch.py` |
| No creds, no NULL session/anon bind at all | Linux | `kerbrute userenum` (pure network-based, no session required) |
| Have valid creds or SYSTEM on a domain-joined host | Linux **or** Windows | `crackmapexec --users` (Linux), or native AD queries (Windows — SYSTEM can impersonate the computer account, which AD treats like a domain user account) |
| No creds and none of the above work | Either | Fall back to external OSINT — email harvesting, `linkedin2username` |

> [!tip] Why CrackMapExec is extra useful here
> It shows `badpwdcount` (bad password attempts so far) and `baddpwdtime` (timestamp of the last bad attempt). Use this to **skip accounts already close to lockout** in your spray list. In a multi-DC environment, `badpwdcount` is tracked per-DC — for an accurate total, query every DC and sum the values, or query the DC holding the **PDC Emulator FSMO role** specifically.

## LDAP Anonymous Bind → Pull User List

Tools:  [windapsearch](https://github.com/ropnop/windapsearch) and [ldapsearch](https://linux.die.net/man/1/ldapsearch).. Requires a valid LDAP search filter (see the [Active Directory LDAP module](https://academy.hackthebox.com/) for more on filter syntax).

### ldapsearch

```shellsession
s0nam@htb[/htb]$ ldapsearch -h 172.16.5.5 -x -b "DC=INLANEFREIGHT,DC=LOCAL" -s sub "(&(objectclass=user))"  | grep sAMAccountName: | cut -f2 -d" "

guest
ACADEMY-EA-DC01$
ACADEMY-EA-MS01$
ACADEMY-EA-WEB01$
htb-student
avazquez
pfalcon
fanthony
wdillard
lbradford
sgage
asanchez
dbranch
<SNIP>
```

`"(&(objectclass=user))"` = LDAP filter for user objects (note: computer accounts show up too, e.g. `ACADEMY-EA-DC01$` — filter these out if only human accounts are needed). `grep`/`cut` extracts just the `sAMAccountName` values.

## Kerbrute — No Session Required

If there's **no** SMB NULL session and **no** LDAP anonymous bind available, [Kerbrute](https://github.com/ropnop/kerbrute) still works — it doesn't need any kind of session at all, just network reachability to the DC's Kerberos port.

**How it works:** sends TGT requests to the DC *without* Kerberos Pre-Authentication.
- KDC responds `PRINCIPAL UNKNOWN` → username is invalid
- KDC prompts for Kerberos Pre-Auth → username is **valid**

> [!tip] Why this is stealthier
> This method does **not** generate Windows Event ID `4625` (account failed to log on) — the event typically monitored for failed logins. It **does** generate Event ID `4768` (Kerberos TGT requested), but this is only logged if Kerberos event logging is enabled via Group Policy. If your assessment triggers this successfully, flagging the SIEM gap (or lack of alerting on 4768 spikes) is a solid report recommendation.

> [!warning] Enumeration ≠ spraying, risk-wise
> Username enumeration this way does **not** cause logon failures or lockouts. But once you switch Kerbrute to actually **spray passwords** against that valid username list, failed Kerberos Pre-Auth attempts **do** count toward the account's bad password counter and can cause lockout — same caution as any other spray.

## Key Takeaways

- [ ] Four ways to build a user list: SMB NULL session, LDAP anonymous bind, Kerbrute (no session needed), or credentialed queries
- [ ] Always try to get the password policy alongside the user list wherever possible
- [ ] Log every spray attempt: accounts, DC, date/time, passwords tried
- [ ] Linux tools: `enum4linux -U`, `rpcclient enumdomusers`, `ldapsearch`/`windapsearch`, `crackmapexec --users`, `kerbrute userenum`
- [ ] Windows equivalent path: SYSTEM on a domain-joined host can query AD the same way (computer account ≈ domain user account)
- [ ] Kerbrute enumeration alone is stealthy (no Event ID 4625) — but spraying passwords with it still risks lockouts like any method
- [ ] Use `badpwdcount`/`baddpwdtime` from CrackMapExec to filter out accounts already near lockout
- [ ] No valid list obtainable at all → fall back to OSINT (email harvesting, `linkedin2username`)
