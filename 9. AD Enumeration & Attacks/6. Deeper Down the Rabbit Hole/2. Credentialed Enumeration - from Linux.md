# Credentialed Enumeration - from Linux

With a foothold secured, it's time to dig deeper using low-privilege domain credentials. Interested in: user/computer attributes, group membership, GPOs, permissions, ACLs, trusts, and more.

> [!warning] Prerequisite
> Almost none of these tools work without **valid domain credentials at some level** — a cleartext password, an NTLM hash, or SYSTEM access on a domain-joined host.

**Lab creds used throughout this section:** `forend` / `Klmcargo2`

## CrackMapExec (CME / NetExec)

[CrackMapExec](https://github.com/byt3bl33d3r/CrackMapExec) (CME, now NetExec) Uses packages from **Impacket** and **PowerSploit**. See the [CME wiki](https://github.com/Porchetta-Industries/CrackMapExec/wiki) for full docs; use `-h` liberally.

## rpcclient
[rpcclient](https://www.samba.org/samba/docs/current/man-html/rpcclient.1.html)
Extra MS-RPC functionality for Samba protocol. Can enumerate, add, modify, or remove AD objects — extremely versatile (`man rpcclient` for the full command reference).

### NULL Session (Unauthenticated, if Available)

```bash
rpcclient -U "" -N 172.16.5.5
```

### Understanding RIDs

A  [Relative Identifier (RID)](https://docs.microsoft.com/en-us/windows/security/identity-protection/access-control/security-identifiers) is a unique identifier (represented in hexadecimal format) utilized by Windows to track and identify objects., combined with the domain SID to form a full object SID.

**Example:** Domain SID `S-1-5-21-3842939050-3880317879-2865463114` + user `htb-student` RID `0x457` (hex) = decimal `1111` → full SID `S-1-5-21-3842939050-3880317879-2865463114-1111`.

> [!info] Fixed well-known RIDs
> Some accounts always have the same RID regardless of domain — e.g. the built-in **Administrator** account is always RID `0x1f4` (decimal 500). This consistency makes it a reliable target for RID-based enumeration.

## Impacket Toolkit

Python-based toolkit for enumerating/interacting with/exploiting Windows protocols. Two modules highlighted:  [wmiexec.py](https://github.com/SecureAuthCorp/impacket/blob/master/examples/wmiexec.py) and [psexec.py](https://github.com/SecureAuthCorp/impacket/blob/master/examples/psexec.py).. Credentials for this part: `wley` / `transporter@4` (cracked earlier via Responder — this user turns out to be a local admin on `ACADEMY-EA-FILE`).

### psexec.py

Clone of the Sysinternals `psexec` executable, but works differently: uploads a randomly-named executable to the target's `ADMIN$` share, registers it as a service via RPC + the Windows Service Control Manager, then communicates over a named pipe — giving an **interactive SYSTEM shell**.

```bash
psexec.py inlanefreight.local/wley:'transporter@4'@172.16.5.125
```

Requires the account to have **local administrator privileges** on the target. Lands you in `system32`, running as **SYSTEM** — full capability for further enumeration, persistence, lateral movement.

### wmiexec.py

Semi-interactive shell via  [Windows Management Instrumentation](https://docs.microsoft.com/en-us/windows/win32/wmisdk/wmi-start-page) Drops no files, generates fewer logs than `psexec.py`.

```bash
wmiexec.py inlanefreight.local/wley:'transporter@4'@172.16.5.5
```

> [!note] Runs as the connecting user, not SYSTEM
> Unlike `psexec.py`, `wmiexec.py` executes as the **local admin account you connected with** — less obviously suspicious to a defender scanning for SYSTEM activity, but still likely caught by modern AV/EDR.

> [!warning] Not fully interactive
> Each command spawns a fresh `cmd.exe` via WMI. A vigilant defender watching **Event ID 4688** (new process created) will see repeated `cmd.exe` spawns tied to WMI — not always malicious (many orgs use WMI legitimately for admin) but a potential tip-off during an investigation.

## BloodHound.py (Ingestor)

BloodHound uses **graph theory** to map relationships and surface AD "attack paths" that would be extremely hard to find manually. Data collected: users, groups, computers, group membership, GPOs, ACLs, domain trusts, local admin access, user sessions, computer/user properties, RDP/WinRM access, etc.
 The tool consists of two parts:
**1. Two collector options:**
- **SharpHound** — C#, for Windows hosts (next section)( [SharpHound collector](https://github.com/BloodHoundAD/BloodHound/tree/master/Collectors))
- **BloodHound.py** — Python port (requires Impacket, ldap3, dnspython), usable straight from a Linux attack host
**2. BloodHound GUI**
> [!tip] Why the Python port matters
> Lets you collect data even without rights to access a domain-joined Windows host, or without a Windows attack box at all — and avoids running the collector *from* a domain host, which could get flagged/blocked. (Even running from your Linux attack host will likely trigger alerts in a well-defended environment.)

### Options

```shellsession
s0nam@htb[/htb]$ bloodhound-python -h
```

Key flag: `-c`/`--collectionmethod` — accepts `Group`, `LocalAdmin`, `Session`, `Trusts`, `Default`, `DCOnly`, `DCOM`, `RDP`, `PSRemote`, `LoggedOn`, `ObjectProps`, `ACL`, `All` (comma-separated for multiple).

### Run the Collector

```shellsession
s0nam@htb[/htb]$ sudo bloodhound-python -u 'forend' -p 'Klmcargo2' -ns 172.16.5.5 -d inlanefreight.local -c all
```

## Key Takeaways

- [ ] Nothing here works without valid creds (cleartext, NTLM hash, or SYSTEM on a domain-joined host)
- [ ] CME: `--users`, `--groups`, `--loggedon-users`, `--shares`, `-M spider_plus` — always run through `sudo`
- [ ] `badpwdcount` from CME output helps refine future spray target lists
- [ ] `(Pwn3d!)` in CME output = you're local admin on that host
- [ ] SMBMap: `-R <share> --dir-only` for a quick recursive directory map without file noise
- [ ] rpcclient: RIDs uniquely ID objects when combined with the domain SID; built-in Administrator is always RID 500 (`0x1f4`)
- [ ] Impacket `psexec.py` = SYSTEM shell (drops a service executable); `wmiexec.py` = stealthier, runs as connecting user, but generates Event ID 4688 spawns
- [ ] Windapsearch `-PU` finds privileged users via **nested** group membership — a very common, easy-to-miss finding
- [ ] BloodHound.py lets you collect from Linux without needing a Windows host or domain-joined access
