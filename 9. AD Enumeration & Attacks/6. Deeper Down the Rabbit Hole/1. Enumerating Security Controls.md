# Enumerating Security Controls

> **After getting a foothold on a Windows machine, identify what security controls are present so you know which tools and techniques will or won't work.**

|Security Control|Why we check it|
|---|---|
|**Windows Defender**|Is Defender running? Will it block tools like PowerView?|
|**AppLocker**|Are PowerShell, CMD, or other executables blocked?|
|**PowerShell Constrained Language Mode**|Is PowerShell restricted?|
|**LAPS**|Which computers use LAPS, and who can read their local admin passwords?|

---

## AppLocker

An **application whitelist** — a list of approved software/executables permitted to run. AppLocker is Microsoft's implementation, offering granular control over executables, scripts, MSI files, DLLs, packaged apps, and installers.

> [!warning] Common bypass gap
> Orgs commonly block `cmd.exe` and `PowerShell.exe`, but forget other PowerShell binary locations, e.g. `%SystemRoot%\SysWOW64\WindowsPowerShell\v1.0\powershell.exe` or `PowerShell_ISE.exe`. If only the 64-bit path is blocked `(%SystemRoot%\system32\WindowsPowerShell\v1.0\powershell.exe)`, calling PowerShell from an alternate path can bypass the rule entirely.

## PowerShell Constrained Language Mode

PowerShell [Constrained Language Mode](https://devblogs.microsoft.com/powershell/powershell-constrained-language-mode/) Locks down significant PowerShell functionality: blocks COM objects, only allowing approved .NET types, disables XAML-based workflows, PowerShell classes, and more.

### Check Current Language Mode

```powershell
PS C:\htb> $ExecutionContext.SessionState.LanguageMode

ConstrainedLanguage
```

`ConstrainedLanguage` = restricted. `FullLanguage` would mean no restriction.

## LAPS (Local Administrator Password Solution)

Microsoft's free tool ( [Local Administrator Password Solution (LAPS)](https://www.microsoft.com/en-us/download/details.aspx?id=46899)) to **randomize and rotate** local administrator passwords per host, preventing local-admin password reuse, lateral movement (see [[Internal Password Spraying - from Linux]] for the attack this defends against).

LAPS stores the password in an **attribute of the computer object in Active Directory**.

Enumeration goal: figure out **which domain users can read LAPS passwords**, and which machines don't have LAPS installed at all (still vulnerable to password reuse). The **[LAPSToolkit](https://github.com/leoloobeek/LAPSToolkit)** streamlines this.

**LAPS TOOLKIT**: **LAPSToolkit** is a PowerShell toolkit that helps enumerate LAPS. Instead of manually checking permissions on every computer, it automates the process.

> [!info] Why "All Extended Rights" matters
> An account that joins a computer to the domain automatically receives **All Extended Rights** over that host — which includes the ability to read its LAPS password. Enumerating 'which users hold this right' can reveal unexpected LAPS-read access.

### Find-AdmPwdExtendedRights

Checks per-computer for groups/users holding read rights (including that "All Extended Rights" edge case):

```powershell
PS C:\htb> Find-AdmPwdExtendedRights

ComputerName                Identity                    Reason
------------                --------                    ------
EXCHG01.INLANEFREIGHT.LOCAL INLANEFREIGHT\Domain Admins Delegated
EXCHG01.INLANEFREIGHT.LOCAL INLANEFREIGHT\LAPS Admins   Delegated
SQL01.INLANEFREIGHT.LOCAL   INLANEFREIGHT\Domain Admins Delegated
SQL01.INLANEFREIGHT.LOCAL   INLANEFREIGHT\LAPS Admins   Delegated
WS01.INLANEFREIGHT.LOCAL    INLANEFREIGHT\Domain Admins Delegated
WS01.INLANEFREIGHT.LOCAL    INLANEFREIGHT\LAPS Admins   Delegated
```

> [!tip] Why this matters for attack planning
> Accounts with "All Extended Rights" (rather than a formally delegated LAPS-reader group) may be **less protected/monitored** — worth specifically targeting these if trying to read a LAPS-managed password.

## Key Takeaways

- [ ] `Get-MpComputerStatus` → check `RealTimeProtectionEnabled` for Defender status
- [ ] `Get-AppLockerPolicy -Effective` → check for path-based rule gaps (e.g. only 64-bit PowerShell path blocked)
- [ ] `$ExecutionContext.SessionState.LanguageMode` → `ConstrainedLanguage` vs `FullLanguage`
- [ ] LAPSToolkit: `Find-LAPSDelegatedGroups`, `Find-AdmPwdExtendedRights`, `Get-LAPSComputers`
- [ ] "All Extended Rights" (via domain-join) can grant unexpected LAPS password read access — a good target to check
- [ ] Security controls aren't always applied uniformly across OUs — always re-check per host/segment
