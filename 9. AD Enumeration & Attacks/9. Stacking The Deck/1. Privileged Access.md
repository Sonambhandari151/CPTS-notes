# Privileged Access

Once we have a foothold, the goal shifts to moving laterally/vertically toward domain compromise. If we control a **local admin** account on a host, Pass-the-Hash over SMB is the classic move.

> [!question] But what if we have no local admin rights anywhere yet? Several other avenues exist for moving around a Windows domain even without local admin access.

---
There are several other ways we can move around a Windows domain:
## Remote Access Methods

| Method                                                                                                                                                     | Description                                                                                                                                                                     |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **RDP** (Remote Desktop Protocol)                                                                                                                          | Remote access/management protocol giving GUI access to a target host                                                                                                            |
| [PowerShell Remoting](https://docs.microsoft.com/en-us/powershell/scripting/learn/ps101/08-powershell-remoting?view=powershell-7.2)** (PSRemoting / WinRM) | Run commands or enter an interactive PowerShell session on a remote host                                                                                                        |
| **MSSQL Server**                                                                                                                                           | An account with `sysadmin` on a SQL instance can log in remotely, run queries, and — via various methods — execute OS commands in the context of the SQL Server service account |

### Enumerating These Rights with BloodHound

| BloodHound Edge                                                               | Meaning                                           |
| ----------------------------------------------------------------------------- | ------------------------------------------------- |
| [CanRDP](https://bloodhound.specterops.io/resources/edges/can-rdp)            | User can RDP to the target                        |
| [CanPSRemote](https://bloodhound.specterops.io/resources/edges/can-ps-remote) | User can PSRemote/WinRM to the target             |
| [SQLAdmin](https://bloodhound.specterops.io/resources/edges/sql-admin)        | User has sysadmin rights on a SQL Server instance |

These rights can also be enumerated with PowerView and built-in tools.

## Remote Desktop

> [!info] Why RDP access (without local admin) is still valuable A foothold user might have no local admin rights anywhere but still be able to RDP into one or more machines. That access alone can be used to:
> 
> - Launch further attacks
> - Escalate privileges / obtain higher-privileged credentials
> - Pillage the host for sensitive data or credentials

### Enumerating the Remote Desktop Users Group

Using PowerView's [Get-NetLocalGroupMember](https://powersploit.readthedocs.io/en/latest/Recon/Get-NetLocalGroupMember/):

```powershell
PS C:\htb> Get-NetLocalGroupMember -ComputerName ACADEMY-EA-MS01 -GroupName "Remote Desktop Users"

ComputerName : ACADEMY-EA-MS01
GroupName    : Remote Desktop Users
MemberName   : INLANEFREIGHT\Domain Users
SID          : S-1-5-21-3842939050-3880317879-2865463114-513
IsGroup      : True
IsDomain     : UNKNOWN
```

> [!warning] All Domain Users can RDP here Common on RDS hosts or jump hosts. These servers are often heavily used and can leak sensitive data (credentials) or offer a local privesc path to admin/credential theft for a more privileged user.

## WinRM

> [!info] Remote Management Users group Exists since Windows 8 / Server 2012 to grant WinRM access **without** granting local admin rights.
We can again use the PowerView function `Get-NetLocalGroupMember` to the `Remote Management Users` group. 

### Enumerating the Remote Management Users Group

```powershell
PS C:\htb> Get-NetLocalGroupMember -ComputerName ACADEMY-EA-MS01 -GroupName "Remote Management Users"

ComputerName : ACADEMY-EA-MS01
GroupName    : Remote Management Users
MemberName   : INLANEFREIGHT\forend
SID          : S-1-5-21-3842939050-3880317879-2865463114-5614
IsGroup      : False
IsDomain     : UNKNOWN
```

### Custom Cypher Query for CanPSRemote

Paste into BloodHound's **Raw Query** box:

```cypher
MATCH p1=shortestPath((u1:User)-[r1:MemberOf*1..]->(g1:Group))
MATCH p2=(u1)-[:CanPSRemote*1..]->(c:Computer)
RETURN p2
```

## SQL Server Admin

> [!info] Where SQL creds come from Kerberoasting is the most common route to SQL service account credentials, but LLMNR/NBT-NS spoofing and password spraying also work. [Snaffler](https://github.com/SnaffCon/Snaffler) can additionally find `web.config` or other config files containing SQL connection strings.

### Finding SQLAdmin Rights in BloodHound

Check **SQL Admin Rights** under a user's **Node Info** tab, or run this custom Cypher query:

```cypher
MATCH p1=shortestPath((u1:User)-[r1:MemberOf*1..]->(g1:Group))
MATCH p2=(u1)-[:SQLAdmin*1..]->(c:Computer)
RETURN p2
```

Example: `damundsen` has SQLAdmin rights over `ACADEMY-EA-DB01`.
![[Pasted image 20260727202652.png]]

> [!tip] Chaining with ACL abuse Use ACL rights (e.g. over `wley` → `damundsen`, as in the prior module section) to force-change `damundsen`'s password, then authenticate as `damundsen` against the SQL server. Here we assume the password was reset to `SQL1234!`.

## Moving On

> [!tip] Enumeration is iterative Every time you gain control of a new user/host, **repeat enumeration** — new rights and privileges may now be visible that weren't before. Never overlook remote access rights just because a user isn't local admin — you may still land somewhere with sensitive data or a privesc path.

> [!important] Always test found SQL credentials Whenever SQL credentials turn up (scripts, `web.config`, connection strings), test them against any MSSQL servers in the environment — this access is almost always **SYSTEM**-equivalent, since the account you authenticate as will almost always carry `SeImpersonatePrivilege`.

## Key Takeaways

- [ ] Without local admin, RDP/WinRM/SQL access can still provide a meaningful foothold for further attacks, privesc, or data pillaging
- [ ] `Get-NetLocalGroupMember -ComputerName <host> -GroupName "Remote Desktop Users"` / `"Remote Management Users"` enumerates who can RDP/WinRM to a host
- [ ] First BloodHound check: does `Domain Users` have CanRDP/CanPSRemote/local admin over any host? — common on RDS/jump hosts
- [ ] BloodHound edges: `CanRDP`, `CanPSRemote`, `SQLAdmin` — check Node Info → Execution Rights, or use custom Cypher queries
- [ ] `Enter-PSSession -ComputerName <host> -Credential <cred>` (Windows) / `evil-winrm -i <ip> -u <user>` (Linux) for WinRM access
- [ ] `PowerUpSQL`'s `Get-SQLInstanceDomain` + `Get-SQLQuery` (Windows) or `mssqlclient.py` (Linux) for MSSQL access
- [ ] `enable_xp_cmdshell` + `xp_cmdshell <command>` runs OS commands through a sysadmin SQL session
- [ ] Check `whoami /priv` after gaining SQL command execution — `SeImpersonatePrivilege` is common and combines with JuicyPotato/PrintSpoofer/RoguePotato for SYSTEM
- [ ] Snaffler is a good tool for hunting down SQL connection strings/credentials in config files across shares
