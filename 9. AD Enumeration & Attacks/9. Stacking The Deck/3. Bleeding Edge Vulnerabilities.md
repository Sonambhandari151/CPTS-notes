# Bleeding Edge Vulnerabilities

Many orgs are slow to patch — recently disclosed vulnerabilities can be quick wins for initial access or privesc. This section covers three techniques recent as of writing (~April 2022): **NoPac**, **PrintNightmare**, **PetitPotam**.

> [!warning] Advanced, high-caution territory
> These are complex topics only lightly covered here — deeper coverage exists in more advanced AD modules. **Never attempt these on a real client engagement without fully understanding how they work and the risk they pose.** These are relatively "safer"/less destructive than attacks like as [Zerologon](https://www.crowdstrike.com/blog/cve-2020-1472-zerologon-security-advisory/) or [DCShadow](https://stealthbits.com/blog/what-is-a-dcshadow-attack-and-how-to-defend-against-it/)., but every attack carries risk — e.g. PrintNightmare can crash the print spooler service, causing a service disruption. Practice in a controlled lab first.

Staying sharp on emerging techniques is part of the job — try these out and research further variations.

## NoPac (SamAccountName Spoofing)

Also known as **`Sam_The_Admin`** vulnerability — released late 2021. Combines two CVEs [2021-42278](https://msrc.microsoft.com/update-guide/vulnerability/CVE-2021-42278) and [2021-42287](https://msrc.microsoft.com/update-guide/vulnerability/CVE-2021-42287) to escalate from any standard domain user straight to **Domain Admin** in one command.

| CVE | What it provides |
|---|---|
| **CVE-2021-42278** | Bypass vulnerability with the Security Account Manager (SAM) |
| **CVE-2021-42287** | Vulnerability in the Kerberos PAC (Privilege Attribute Certificate) within AD DS |

**How it works:** exploits the ability to rename a computer account's `SamAccountName` to match a Domain Controller's. By default, authenticated users can add up to **10 computers to a domain**. After renaming the new computer to match a DC, requesting Kerberos tickets causes the KDC to issue tickets under the **DC's name** instead — because a TGS request matches the closest name. Result: access as that service, potentially a SYSTEM shell on a DC. Full attack flow: [SecureWorks blog post](https://www.secureworks.com/blog/nopac-a-tale-of-two-vulnerabilities-that-could-end-in-ransomware).

## Windows Defender & smbexec.py Considerations

If Defender/AV/EDR is active, the shell may still connect but every command may fail. `smbexec.py` creates services `BTOBTO` / `BTOBO`, and sends commands via SMB inside `.bat` files (`execute.bat`) — a new batch script per command and deleted afterwards. Defender flagged this in testing as **VirTool:Win32/MSPSEexecCommand** (severe, removed).

> [!warning] Not stealthy
> If OPSEC/quiet operation matters for the assessment, avoid `smbexec.py`-based tools.

## PetitPotam (MS-EFSRPC)

**[CVE-2021-36942](https://msrc.microsoft.com/update-guide/vulnerability/CVE-2021-36942)** — LSA spoofing vuln, patched Aug 2021. An **unauthenticated** attacker can coerce a DC to authenticate against an arbitrary host via NTLM over port 445, by abusing Microsoft’s [Encrypting File System Remote Protocol (MS-EFSRPC)](https://docs.microsoft.com/en-us/openspecs/windows_protocols/ms-efsr/08796ba8-01c8-4872-9221-1000ec2eff31)  through  [Local Security Authority Remote Protocol (LSARPC)](https://docs.microsoft.com/en-us/openspecs/windows_protocols/ms-lsad/1b5471ef-4c33-4a91-b079-dfcbb82f05cc). Allows unauthenticated attacker to domain takeovera window domain  where **AD CS** (Active Directory Certificate Services) is present: the DC's coerced auth is relayed to the CA's Web Enrollment page, requesting a **Certificate Signing Request (CSR)** for a new cert. That cert can then be used (via **Rubeus** or **gettgtpkinit.py**) to request a TGT for the DC → DCSync → domain compromise.

Background reading: [dirkjanm's NTLM relay to AD CS post](https://dirkjanm.io/ntlm-relaying-to-ad-certificate-services/).


We can also take an alternate route once we have the TGT for our target. ### DCSync via Mimikatz
since Domain Controllers have replication privileges in the domain, we can use the pass-the-ticket to perform a DCSync attack using Mimikatz from our Windows attack host. Here, we grab the NT hash for the KRBTGT account, which could be used to create a Golden Ticket and establish persistence. We could obtain the NT hash for any privileged user using DCSync and move forward to the next phase of our assessment.

```powershell

[DC] 'ACADEMY-EA-DC01.INLANEFREIGHT.LOCAL' will be the DC server
[DC] 'inlanefreight\krbtgt' will be the user account
```

## PetitPotam Mitigations

- Patch [CVE-2021-36942](https://msrc.microsoft.com/update-guide/vulnerability/CVE-2021-36942)
- To prevent NTLM relay attacks,  Enable [Extended Protection for Authentication](https://docs.microsoft.com/en-us/security-updates/securityadvisories/2009/973811) + [Require SSL](https://support.microsoft.com/en-us/topic/kb5005413-mitigating-ntlm-relay-attacks-on-active-directory-certificate-services-ad-cs-3612b773-4043-4aa9-b23d-b87910cd3429) to only allow HTTPS connections for Certificate Authority Web Enrollment & Certificate Enrollment Web Service
- [Disable NTLM authentication](https://docs.microsoft.com/en-us/windows/security/threat-protection/security-policy-settings/network-security-restrict-ntlm-ntlm-authentication-in-this-domain) for Domain Controllers
- Disable NTLM on AD CS servers via [Group Policy](https://docs.microsoft.com/en-us/windows/security/threat-protection/security-policy-settings/network-security-restrict-ntlm-incoming-ntlm-traffic)
- Disable NTLM for IIS where CA Web Enrollment/Enrollment Web Service is in use

> [!warning] Patching alone isn't enough
> The [Certified Pre-Owned](https://www.specterops.io/assets/resources/Certified_Pre-Owned.pdf) whitepaper shows AD CS remains attackable via authenticated API calls even after the CVE-2021-36942 patch — a standard domain user can often still find a path in. Worth reading for deeper AD CS hardening/detection guidance.

## Recap

Three recent attacks covered:
- **NoPac** (SamAccountName Spoofing) — standard user → Domain Admin
- **PrintNightmare** (remote) — standard user → SYSTEM on a DC
- **PetitPotam** (MS-EFSRPC) — **unauthenticated** → domain compromise (with AD CS present)

## Key Takeaways

- [ ] NoPac (CVE-2021-42278 + CVE-2021-42287): rename a computer account to a DC's SamAccountName → request tickets under the DC's identity. Check `ms-DS-MachineAccountQuota` isn't 0 first
- [ ] PrintNightmare (CVE-2021-34527 / CVE-2021-1675): needs cube0x0's Impacket fork, MS-RPRN/MS-PAR exposure check via `rpcdump.py`, DLL payload hosted via `smbserver.py`
- [ ] PetitPotam (CVE-2021-36942): unauthenticated NTLM coercion via MS-EFSRPC, relayed to AD CS Web Enrollment for a cert → TGT → DCSync
- [ ] smbexec.py-based shells are noisy and easily flagged by modern AV/EDR
- [ ] Every "bleeding edge" attack still needs lab practice first — never run untested attacks against production without deep understanding
- [ ] Even patched vulnerabilities (PetitPotam) may leave AD CS attackable via other authenticated paths — patching alone isn't full mitigation
