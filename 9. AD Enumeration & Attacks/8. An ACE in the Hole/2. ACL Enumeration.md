> [!tip] Targeted enumeration instead
> Better approach: start from a user you **already control** and search for rights that user has over other objects. Here, we use `wley`

### Getting the Target User's SID

```powershell
PS C:\htb> Import-Module .\PowerView.ps1
PS C:\htb> $sid = Convert-NameToSid wley
```

### Using Get-DomainObjectACL

Maps `wley`'s SID to the `SecurityIdentifier` property (which tells us *who* has the right over an object).

> [!note] Runtime
> This command can take 1–2 minutes in a large environment — be patient.

```powershell
PS C:\htb> Get-DomainObjectACL -Identity * | ? {$_.SecurityIdentifier -eq $sid}
```

### Resolving the GUID Manually

Option 1 — Google the GUID: leads to [this Microsoft page](https://docs.microsoft.com/en-us/windows/win32/adschema/r-user-force-change-password) confirming it's the right to **force change a user's password**.

Option 2 — reverse search with PowerShell (run in a **fresh** session if PowerView is already imported, or this will error):

```powershell
PS C:\htb> $guid= "00299570-246d-11d0-a768-00aa006e0529"
PS C:\htb> Get-ADObject -SearchBase "CN=Extended-Rights,$((Get-ADRootDSE).ConfigurationNamingContext)" -Filter {ObjectClass -like 'ControlAccessRight'} -Properties * |Select Name,DisplayName,DistinguishedName,rightsGuid| ?{$_.rightsGuid -eq $guid} | fl

Name              : User-Force-Change-Password
DisplayName       : Reset Password
DistinguishedName : CN=User-Force-Change-Password,CN=Extended-Rights,CN=Configuration,DC=INLANEFREIGHT,DC=LOCAL
rightsGuid        : 00299570-246d-11d0-a768-00aa006e0529
```

> [!question] Why walk through the manual method at all?
> Understanding what your tools actually do — and having a backup method — matters if a tool fails or gets blocked. Knowing how to enumerate ACLs without PowerView (using only built-in [Get-Acl](https://docs.microsoft.com/en-us/powershell/module/microsoft.powershell.security/get-acl?view=powershell-7.2) / [Get-ADUser](https://docs.microsoft.com/en-us/powershell/module/activedirectory/get-aduser?view=windowsserver2022-ps) cmdlets) can set you apart when restricted to only client-provided tooling.

> [!warning] Much slower
> This approach can take significantly longer than the PowerView equivalent, especially in a large environment.

## Following the Chain: wley → damundsen

> [!info] Recap so far
> We control `wley` and now have the `User-Force-Change-Password` extended right over `damundsen`.

### Further Enumeration Using damundsen

```powershell
PS C:\htb> $sid2 = Convert-NameToSid damundsen
PS C:\htb> Get-DomainObjectACL -ResolveGUIDs -Identity * | ? {$_.SecurityIdentifier -eq $sid2} -Verbose

AceType               : AccessAllowed
ObjectDN              : CN=Help Desk Level 1,OU=Security Groups,OU=Corp,DC=INLANEFREIGHT,DC=LOCAL
```

> [!success] `damundsen` has `GenericWrite` over the `Help Desk Level 1` group
> Meaning we could add any user (or ourselves) to this group and inherit its rights. A search for rights conferred by this group directly returns nothing interesting on its own — but check nested membership next.

### Checking Nested Group Membership

```powershell
PS C:\htb> Get-DomainGroup -Identity "Help Desk Level 1" | select memberof

memberof
--------
CN=Information Technology,OU=Security Groups,OU=Corp,DC=INLANEFREIGHT,DC=LOCAL
```

> [!important] `Help Desk Level 1` is nested inside `Information Technology`
> Any member of `Help Desk Level 1` inherits all rights granted to `Information Technology`.

### Recap of the Chain So Far

- Control over `wley` (hash from Responder, cracked with Hashcat)
- `wley` → `User-Force-Change-Password` over `damundsen`
- `damundsen` → `GenericWrite` over `Help Desk Level 1` group
- `Help Desk Level 1` → nested in `Information Technology` → inherits its rights

## Key Takeaways

- [ ] `Find-InterestingDomainAcl` is too broad for practical use — start from a controlled user instead and pivot outward
- [ ] `Convert-NameToSid <user>` gets the SID needed to filter `Get-DomainObjectACL -Identity * | ? {$_.SecurityIdentifier -eq $sid}`
- [ ] Without `-ResolveGUIDs`, `ObjectAceType` shows as a raw GUID — resolve manually via Google, `Get-ADObject` reverse lookup, or just use `-ResolveGUIDs`
- [ ] `Get-Acl` / `Get-ADUser` can replicate this enumeration without PowerView, just much slower — good to know when restricted to built-in tooling
- [ ] Always check for **nested group membership** — rights on a nested group cascade up from the parent group
- [ ] `DS-Replication-Get-Changes` + `DS-Replication-Get-Changes-In-Filtered-Set` (or `-All`) over the domain object = DCSync capability
- [ ] BloodHound's **Outbound Control Rights** (First Degree + Transitive Object Control) visualizes the exact same attack chain far more efficiently, with built-in abuse guidance per edge
