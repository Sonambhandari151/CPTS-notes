# LLMNR/NBT-NS Poisoning - from Windows

Same attack, different platform. Last section used **Responder** from Linux; this section uses **[Inveigh](https://github.com/Kevin-Robertson/Inveigh)** from Windows to capture another set of credentials.

---

## Inveigh — Overview

Useful whenever the attack box (or a compromised local admin foothold) is **Windows** — e.g. client-provided Windows box, or landing on a Windows host as local admin via another attack and wanting to expand access.

- Works like Responder, but written in **PowerShell** and **C#**
- Listens on IPv4 **and** IPv6
- Supports: `LLMNR`, `DNS`, `mDNS`, `NBNS`, `DHCPv6`, `ICMPv6`, `HTTP`, `HTTPS`, `SMB`, `LDAP`, `WebDAV`, `Proxy Auth`
- Pre-installed in `C:\Tools` on the provided Windows attack host
- Full parameter reference: [Inveigh Wiki](https://github.com/Kevin-Robertson/Inveigh/wiki)

## Remediation

MITRE ATT&CK: [T1557.001 — Adversary-in-the-Middle: LLMNR/NBT-NS Poisoning and SMB Relay](https://attack.mitre.org/techniques/T1557/001/)

> [!warning] Test before rolling out
> Disabling LLMNR/NBT-NS can break legacy name resolution dependencies. Recommend the change to clients, but stress they should test thoroughly before a full rollout.

### Disable LLMNR (via Group Policy)
`Computer Configuration → Administrative Templates → Network → DNS Client → enable "Turn OFF Multicast Name Resolution"`

### Disable NBT-NS (per-host, no GPO option)
`Control Panel → Network and Sharing Center → Change adapter settings → right-click adapter → Properties → Internet Protocol Version 4 (TCP/IPv4) → Properties → Advanced → WINS tab → Disable NetBIOS over TCP/IP`

### Disable NBT-NS at Scale (Startup Script via GPO)

Since NBT-NS has no direct GPO toggle, push a startup script instead:

```powershell
$regkey = "HKLM:SYSTEM\CurrentControlSet\services\NetBT\Parameters\Interfaces"
Get-ChildItem $regkey |foreach { Set-ItemProperty -Path "$regkey\$($_.pschildname)" -Name NetbiosOptions -Value 2 -Verbose}
```

Setup:
1. `Computer Configuration → Windows Settings → Script (Startup/Shutdown) → Startup`
2. In the Local Group Policy Editor, Double-click **Startup** → **PowerShell Scripts** tab → select "Run Windows PowerShell scripts first" → **Add** → choose the script
3. Reboot or restart the network adapter for the change to take effect

To deploy domain-wide: host the script on the DC's **SYSVOL** share (e.g. `\\inlanefreight.local\SYSVOL\INLANEFREIGHT.LOCAL\scripts`), reference it via GPO applied to the relevant OUs, and it runs at next reboot (as long as the script stays accessible on SYSVOL).

### Other Mitigations
- Filter network traffic to block LLMNR/NetBIOS traffic
- Enable **SMB Signing** to prevent NTLM relay attacks
- Network IDS/IPS to catch this activity
- Network segmentation to isolate hosts that genuinely require LLMNR/NetBIOS

## Detection

Since disabling LLMNR/NBT-NS isn't always feasible, detection matters too:

- **Canary technique**: inject LLMNR/NBT-NS requests for **non-existent hostnames** across subnets — any reply indicates an attacker is spoofing responses. See this technique explained in more depth: [this blog post](https://www.blackhillsinfosec.com/how-to-catch-a-poisoner-with-a-honey-file/) (referenced in the module as further reading on canary-based detection).
- Monitor traffic on **UDP 5355** (LLMNR) and **137** (NBT-NS)
- Monitor event IDs [4697](https://docs.microsoft.com/en-us/windows/security/threat-protection/auditing/event-4697) and [7045](https://www.manageengine.com/products/active-directory-audit/kb/system-events/event-id-7045.html)
- Watch registry key `HKLM\Software\Policies\Microsoft\Windows NT\DNSClient` for changes to the `EnableMulticast` DWORD — a value of `0` means LLMNR is disabled

## Key Takeaways

- [ ] Inveigh = Windows-side equivalent of Responder; PowerShell version is legacy, C# version (InveighZero) is actively maintained
- [ ] `Invoke-Inveigh Y -NBNS Y -ConsoleOutput Y -FileOutput Y` — quick start for LLMNR + NBT-NS spoofing (PowerShell)
- [ ] `.\Inveigh.exe` — quick start for the C# version; press **ESC** for the interactive console
- [ ] Console commands like `GET NTLMV2UNIQUE` and `GET NTLMV2USERNAMES` let you triage captured hashes before spending time cracking
- [ ] MITRE technique: **T1557.001**
- [ ] Remediation: disable LLMNR via GPO, disable NBT-NS per-host or via startup script + SYSVOL GPO push, enable SMB signing, segment networks
- [ ] Detection: canary/honeypot hostnames, monitor UDP 5355/137, Event IDs 4697/7045, registry key `EnableMulticast`
- [ ] After capturing hashes, use BloodHound to assess which accounts are worth cracking before investing Hashcat time
