# LLMNR/NBT-NS Poisoning - from Linux

> [!info] Where we're at
> Initial domain enumeration is done — we have basic user/group info, key hosts (including the DC), and the domain's naming scheme. Now we run two techniques side-by-side, **network poisoning** and **password spraying**, aiming to get valid cleartext credentials for a domain user — our first real foothold.

This section (and the next) covers a classic credential-gathering technique: a **Man-in-the-Middle attack** on **LLMNR** and **NBT-NS** broadcasts. Depending on the network, this can yield low-privileged or even administrative password hashes (crackable offline) or cleartext creds. These captured hashes can sometimes also be used for an **SMB Relay attack** (covered in a later Lateral Movement module) to authenticate without cracking anything offline.

---

## LLMNR & NBT-NS Primer

Both are Microsoft **fallback name resolution** methods used when DNS fails:
 - Microsoft Windows components that serve as alternate methods of host identification

| Protocol                                                                                                                                     | Full Name                            | Port       | Notes                                                                            |
| -------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------ | ---------- | -------------------------------------------------------------------------------- |
| [LLMNR](https://datatracker.ietf.org/doc/html/rfc4795)                                                                                       | Link-Local Multicast Name Resolution | UDP `5355` | DNS-format based; lets hosts on the same local link resolve names for each other |
| [NBT-NS](<https://docs.microsoft.com/en-us/previous-versions/windows/it-pro/windows-2000-server/cc940063(v=technet.10)?redirectedfrom=MSDN>) | NetBIOS Name Service                 | UDP `137`  | Identifies systems by NetBIOS name; used as fallback if LLMNR fails              |

**The flaw:** when a host broadcasts an LLMNR/NBT-NS request, **any host on the network can respond** — there's no built-in verification of who's allowed to answer. This is where [Responder](https://github.com/lgandx/Responder) comes in: we spoof an authoritative answer, pretending to be the host the victim is looking for.

If the victim then tries to authenticate to what it thinks is the real host, we capture its **NetNTLM hash**, which we can:
- Crack offline to recover the cleartext password
- Relay to another host, or to a different protocol like LDAP, on the same host

> [!warning] Common escalation path
> LLMNR/NBT-NS spoofing combined with a lack of **SMB signing** enforcement often leads to administrative access on domain hosts (via SMB Relay — covered in the Lateral Movement module).

## Quick Example — Attack Flow

1. A host tries to connect to `\\print01.inlanefreight.local` but mistypes it as `\\printer01.inlanefreight.local`
2. DNS responds: unknown host
3. The host broadcasts to the local network: "does anyone know `\\printer01.inlanefreight.local`?"
4. **The attacker (running Responder)** replies: "That's me!"
5. The victim believes it and sends an authentication request — username + NTLMv2 hash — straight to the attacker
6. That hash gets cracked offline, or used in an SMB Relay attack if conditions allow

---

## TTPs — What We're Actually Collecting

We're capturing **NTLMv1** and **NTLMv2** authentication hashes sent over the network (see [Introduction to Active Directory](https://academy.hackthebox.com/course/preview/introduction-to-active-directory) for background on LM/NT hashes). These get cracked offline using tools like [Hashcat](https://hashcat.net/hashcat/) or [John the Ripper](https://www.openwall.com/john/), aiming to recover a cleartext password for a foothold — or to escalate access if the captured account has more privilege than what we currently hold.

### Tools for LLMNR/NBT-NS Poisoning

| Tool                                                  | Description                                                                          |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------ |
| [Responder](https://github.com/lgandx/Responder)      | Purpose-built to poison LLMNR, NBT-NS, and MDNS; many functions                      |
| [Inveigh](https://github.com/Kevin-Robertson/Inveigh) | Cross-platform MITM tool for spoofing/poisoning (covered next section, Windows-side) |
| [Metasploit](https://www.metasploit.com/)             | Has built-in scanner/spoofing modules for poisoning attacks                          |

**Responder** — Python, typically run from Linux (an `.exe` version exists for Windows).
**Inveigh** — written in C# and PowerShell (PowerShell version considered legacy).

Both tools can attack:
`LLMNR`, `DNS`, `MDNS`, `NBNS`, `DHCP`, `ICMP`, `HTTP`, `HTTPS`, `SMB`, `LDAP`, `WebDAV`, `Proxy Auth`

Responder additionally supports: `MSSQL`, `DCE-RPC`, `FTP`, `POP3`, `IMAP`, `SMTP auth`

### Key Flags Explained

| Flag         | Purpose                                                                                                                                           |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `-A`         | Analyze (passive) mode — see requests without answering                                                                                           |
| `-I <iface>` | Network interface (required, or use `-i` for an IP on OSX)                                                                                        |
| `-e <ip>`    | Poison with a different IP than Responder's own                                                                                                   |
| `-w`         | Start the rogue WPAD proxy server — captures HTTP requests from IE/Edge users with **Auto-detect settings** enabled, very effective in large orgs |
| `-f`         | Fingerprint the OS/version of the host that issued the query                                                                                      |
| `-v`         | Verbose — useful for troubleshooting but noisy                                                                                                    |
| `-F` / `-P`  | Force NTLM/Basic auth or proxy auth — can trigger a visible login prompt, use sparingly                                                           |
| `--lm`       | Force LM hash downgrade (legacy XP/2003 targets)                                                                                                  |

> [!warning] Use `-r` and `-d` with caution
> Answering netbios wredir/domain suffix queries can break things on the live network — default is off for a reason.

### Required Ports on the Attack Host

```
UDP 137, UDP 138, UDP 53, UDP/TCP 389, TCP 1433, UDP 1434,
TCP 80, TCP 135, TCP 139, TCP 445, TCP 21, TCP 3141,
TCP 25, TCP 110, TCP 587, TCP 3128, Multicast UDP 5355 and 5353
```
Must run Responder as `root`/`sudo`. Individual rogue servers (e.g. SMB) can be disabled in `Responder.conf` if a port conflicts with something else running on your box.

### Starting Responder

```bash
sudo responder -I ens224
```

### Where Captured Hashes Go

Responder prints a captured hash to console and writes it to a per-host log file in:
```
/usr/share/responder/logs
```
Filename format: `(MODULE_NAME)-(HASH_TYPE)-(CLIENT_IP).txt`
Example: `SMB-NTLMv2-SSP-172.16.5.25`

Also stored in a SQLite database (configurable via `Responder.conf`, typically in `/usr/share/responder` unless cloned directly from GitHub).

### Example Log Directory

```shellsession
s0nam@htb[/htb]$ ls

Poisoners-Session.log               SMB-NTLMv2-SSP-172.16.5.50.txt
Proxy-Auth-NTLMv2-172.16.5.200.txt
```

> [!tip] Let it run
> Best practice: start Responder in a `tmux` window and leave it running in the background while you continue other enumeration — this maximizes the number of hashes captured over time.

## Cracking the Captured Hash

Once captured NetNTLMv2 hashes are ready, feed them to **Hashcat** using hash mode `5600` (NetNTLMv2). If a hash looks unfamiliar, check the [Hashcat example hashes page](https://hashcat.net/wiki/doku.php?id=example_hashes) to identify the correct mode. For deeper coverage of Hashcat, see the [Cracking Passwords With Hashcat](https://academy.hackthebox.com/course/preview/cracking-passwords-with-hashcat) module.

> [!note] NetNTLMv2 limitation
> These hashes are useful once **cracked**, but can't be used directly for pass-the-hash — cracking offline (Hashcat/John) is required to get a usable password.

## Moving On

We now have one cracked credential (`FOREND` / `Klmcargo2`) — our first real foothold. Best practice: try to capture and crack as many hashes as possible during this window, but don't burn assessment time cracking hashes for accounts that clearly won't help move things forward (check value before investing cracking time).

## Key Takeaways

- [ ] LLMNR (UDP 5355) and NBT-NS (UDP 137) are DNS fallback protocols — anyone on the network can answer their broadcast requests
- [ ] Responder exploits this by impersonating the host being asked about, tricking victims into authenticating to us
- [ ] Captured NetNTLMv2 hashes must be cracked offline (Hashcat mode `5600` / John) — not usable for pass-the-hash directly
- [ ] `sudo responder -I <iface>` for basic poisoning; `-A` for passive-only analyze mode
- [ ] `-w` (WPAD rogue proxy) is especially effective in orgs with IE/Edge auto-detect settings enabled
- [ ] Let Responder run in the background (tmux) while doing other enumeration to maximize captures
- [ ] LLMNR/NBT-NS poisoning + no SMB signing enforcement → potential path to SMB Relay and admin access (covered later, Lateral Movement)
- [ ] Weak passwords crack fast; complex ones may not crack at all in reasonable time
