## Introduction to Cross-Site Scripting (XSS)

### Core Concept

- **Definition:** A client-side vulnerability where a web application fails to properly sanitize user input, allowing an attacker to inject and execute malicious JavaScript code in a victim's browser.
    
- **Execution:** Code runs in the **client-side browser** (e.g., Chrome, Firefox), not on the back-end server.
    
- **Risk Level:** Medium (High probability + Low direct server impact).
    

---

### Potential Attacks

JavaScript execution within a browser allows for several malicious actions:

- **Session Hijacking:** Sending the target user's session cookies to an attacker-controlled server.
    
- **Unauthorized Actions:** Executing API calls (e.g., changing passwords) on behalf of the victim.
    
- **Malicious Content:** Displaying ads or using the victim's browser for Bitcoin mining.
    
- **Browser Exploitation:** Chaining XSS with binary vulnerabilities (like Heap Overflows) to break out of the browser sandbox and execute system-level code.
    

---

### Historical Examples

1. **Samy Worm (2005):** A Stored XSS worm on MySpace that infected 1 million users in one day by self-propagating through profile comments.
    
2. **TweetDeck (2014):** A self-retweeting XSS that forced Twitter to temporarily shut down the dashboard.
    
3. **Google (2019):** An XSS vulnerability identified within the search engine's XML library.
    

---

### Types of XSS

|**Type**|**Persistence**|**Description**|**Example**|
|---|---|---|---|
|**Stored (Persistent)**|**High**|Malicious script is permanently stored on the server (database). Executed when any user views the infected page.|Comments, forum posts, user profiles.|
|**Reflected (Non-Persistent)**|**Low**|Script is "reflected" off a web application to the victim. Usually delivered via a crafted link.|Search results, error messages.|
|**DOM-based**|**Low**|The vulnerability exists entirely in the client-side code (JavaScript). The payload never reaches the back-end server.|Handling anchor tags (`#`) or URL parameters via JS.|

---

### Limitations

- **Execution Environment:** Limited to the browser's JS engine (e.g., V8).
    
- **Same-Origin Policy (SOP):** Modern browsers restrict scripts to the domain of the vulnerable website.
