## XSS Discovery

### Discovery Methods
Finding XSS vulnerabilities ranges from automated scanning to manual source code analysis.

#### 1. Automated Discovery
* **Scanners:** Tools like **Nessus**, **Burp Suite Pro**, and **OWASP ZAP** perform two scan types:
    * **Passive Scan:** Analyzes client-side code for DOM-based flaws.
    * **Active Scan:** Injects various payloads into parameters to trigger execution.
* **Open-Source Tools:**
    * **XSStrike:** Powerful tool that analyzes reflections and generates custom payloads.
    * **XSSer & Brute XSS:** Other common discovery tools.
* **XSStrike Usage:** `python xsstrike.py -u "http://SERVER_IP:PORT/index.php?param=test"`

#### 2. Manual Discovery
* **Fuzzing with Payloads:** Manually entering scripts into fields. Resources like **PayloadAllTheThings** or **Payload-Box** offer extensive lists.
* **Beyond Input Fields:** XSS can be found in HTTP headers (User-Agent, Cookies) or any parameter that is eventually displayed on the page.

#### 3. Code Review (Whitebox)
* **Most Reliable Method:** Reviewing both front-end (JavaScript) and back-end code to track data from **Source** to **Sink**.
* **Effectiveness:** Manual review identifies complex vulnerabilities that automated tools often miss, especially in well-secured applications.

### Understanding Payload Efficiency
Many public payloads fail because they are designed for specific "contexts" or "security bypasses."
* **Context Examples:** Injecting inside a single quote `'`, after an attribute, or within a specific tag.
* **Evasion:** Using `<img>` tags or `CSS` attributes to bypass filters that specifically block `<script>` tags.

### Exercise Strategy: Identifying the Vulnerable Parameter
To answer the questions for the target server:

1.  **Spider/Browse the App:** Look for any input fields, search bars, or URL parameters.
2.  **Test for Reflection:** Type a unique string (e.g., `sonam_test`) into every field and check the page source (`CTRL+U`) to see if it appears.
3.  **Check the URL:** If you see a parameter like `?id=test` or `?name=test`, this is a primary candidate.
4.  **Verify with a Payload:** Once you find a reflection point, inject `<script>alert(1)</script>`.
    * If it alerts immediately: **Reflected XSS**.
    * If it alerts only after you refresh or revisit the page: **Stored XSS**.
    * If the parameter uses a `#` and doesn't show up in the network tab: **DOM XSS**.
