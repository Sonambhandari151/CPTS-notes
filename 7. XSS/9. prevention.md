
# 🔐 XSS Prevention – Detailed Notes

## 1. Core Concept

- XSS happens when:
    
    - **Source** → user-controlled input
        
    - **Sink** → where input is rendered in browser
        
- Goal: Prevent malicious JavaScript execution
    

✔ Focus on securing:

- Input handling
    
- Output rendering
    

---

# 🖥️ Front-End Protection

## 2. Input Validation

- Ensures input follows expected format
    
- Uses:
    
    - Regex
        
    - Built-in validation
        

### Example:

```javascript
function validateEmail(email) {
    const re = /.../;
    return re.test(email);
}
```

### Key Points:

- Reject invalid inputs before submission
    
- Helps reduce attack surface
    
- ❗ Not sufficient alone (can be bypassed)
    

---

## 3. Input Sanitization

- Removes/escapes dangerous characters like:
    
    - `<`, `>`, `"`, `'`, `/`
        

### Tool:

```javascript
DOMPurify.sanitize(dirty)
```

### Working:

- Converts:
    
    ```html
    <script>alert(1)</script>
    ```
    
    → harmless text
    

✔ Prevents DOM-based XSS

---

## 4. Avoid Direct Input in Sensitive Contexts

❌ Never insert user input directly into:

- `<script>` → executes JS
    
- `<style>` → CSS injection
    
- HTML attributes → e.g. `onerror`, `onclick`
    
- HTML comments → may break structure
    

✔ These contexts allow easy script execution

---

## 5. Dangerous JavaScript Functions

### ❌ Avoid:

- `innerHTML`
    
- `outerHTML`
    
- `document.write()`
    
- `document.writeln()`
    

### ❌ jQuery risky methods:

- `html()`
    
- `append()`
    
- `prepend()`
    
- `before()`
    
- `after()`
    

### Reason:

- These interpret input as **HTML**, not text
    
- If input contains `<script>` → executes immediately
    

✔ Prefer:

- `textContent`
    
- `innerText`
    

---

# 🗄️ Back-End Protection

## 6. Input Validation (Server-Side)

- Must validate again on server
    
- Prevents bypass using tools (Burp, curl)
    

### Example (PHP):

```php
filter_var($_GET['email'], FILTER_VALIDATE_EMAIL)
```

✔ Reject invalid/malicious inputs

---

## 7. Input Sanitization (Server-Side)

- Escape special characters
    

### Example:

```php
addslashes($_GET['input'])
```

✔ Prevents injection into HTML/JS

---

## 8. Output Encoding (MOST IMPORTANT)

### Concept:

- Convert special characters to safe HTML entities
    

### Example:

```php
htmlentities($_GET['input'])
```

### Conversion:

|Character|Encoded|
|---|---|
|`<`|`&lt;`|
|`>`|`&gt;`|
|`"`|`&quot;`|

✔ Browser displays as text, not code

---

## 9. Never Trust Direct Input

❌ Bad:

```php
echo $_GET['input'];
```

✔ Good:

```php
echo htmlentities($_GET['input']);
```

---

# ⚙️ Server-Side Security Measures

## 10. HTTPS

- Encrypts communication
    
- Prevents interception of data
    

---

## 11. Security Headers

### Important Headers:

- **X-Content-Type-Options=nosniff**
    
    - Prevents MIME-type sniffing
        
- **Content-Security-Policy (CSP)**
    

Example:

```text
script-src 'self'
```

✔ Only allows trusted scripts

---

## 12. Cookie Security

### Flags:

- **HttpOnly**
    
    - Prevents JavaScript access to cookies
        
    - Stops cookie stealing
        
- **Secure**
    
    - Sends cookies only over HTTPS
        

✔ Protects session data

---

## 13. Web Application Firewall (WAF)

- Detects malicious payloads
    
- Blocks suspicious requests automatically
    

✔ Adds extra protection layer

---

## 14. Framework-Level Protection

- Many frameworks provide built-in XSS defense:
    
    - Auto-escaping
        
    - Secure templating
        

✔ Example: ASP.NET, modern JS frameworks
