## Reflected (Non-Persistent) XSS

### Core Concept

- **Definition:** A vulnerability where a malicious script is "reflected" off a web application to the user's browser. The input is sent to the server and returned immediately in the HTTP response.
    
- **Non-Persistence:** The payload is **not stored** on the server. It only executes for the specific user who triggers the malicious request.
    
- **Reflection Points:** Found in elements that "echo" user input back to the page, such as search results, error messages, or confirmation text.
    

---

### Comparison: Stored vs. Reflected XSS

|**Feature**|**Stored XSS**|**Reflected XSS**|
|---|---|---|
|**Storage**|Back-end Database|Not stored (Temporary)|
|**Reach**|Every user visiting the page|Specific individuals (targeted)|
|**Persistence**|Permanent until manually deleted|Disappears after page refresh|

---

### Delivery Mechanisms

Because the payload is not saved, the attacker must entice the victim to send the payload to the server.

- **GET Requests:** The payload is part of the URL parameters.
    
    - _Mechanism:_ Attacker sends a link like `http://target.com/index.php?query=<script>alert(1)</script>`.
        
    - _Detection:_ Check the URL bar or use **Developer Tools (F12) > Network Tab**.
        
- **POST Requests:** The payload is in the request body.
    
    - _Mechanism:_ Requires a third-party site to automatically submit a hidden form to the vulnerable server.
        

---

### Detection & Verification

1. **Identify Echoes:** Find where your input appears on the page (e.g., `Task 'test' could not be added.`).
    
2. **Inject Payload:** Use a script like `<script>alert(window.origin)</script>`.
    
3. **Inspect DOM:** If the alert box pops up, the browser is executing your code.
    
4. **View Source (`CTRL+U`):** Confirm the script is rendered raw in the HTML:
    
    `<div>Task '<script>alert(window.origin)</script>' could not be added.</div>`
    

---

### Professional Tip: The `window.origin` Check

In modern web apps, forms are often isolated in **IFrames**. Using `alert(window.origin)` confirms if the vulnerability is on the main domain or a restricted sub-domain, which determines the actual impact of the attack (e.g., whether you can steal the main site's session cookies).
