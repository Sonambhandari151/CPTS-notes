## XSS Exploitation: Website Defacing

### Core Concept

**Defacing** is a visual attack where an attacker alters the appearance of a website to display a custom message, image, or propaganda. While it doesn't always involve data theft, it causes significant reputational damage.

- **Primary Vector:** **Stored XSS** is the most effective type for defacing because the changes are persistent and visible to every visitor.
    
- **Mechanism:** Injected JavaScript manipulates the **Document Object Model (DOM)** to overwrite existing styles and content.
    

---

### Key Defacement Elements

Hackers typically target four main JavaScript properties to hijack the visual experience:

|**Element**|**JavaScript Property**|**Effect**|
|---|---|---|
|**Background Color**|`document.body.style.background`|Changes the hex color of the page.|
|**Background Image**|`document.body.background`|Sets a URL as the full-page background.|
|**Page Title**|`document.title`|Changes the text shown in the browser tab.|
|**Page Content**|`document.body.innerHTML`|Overwrites the entire HTML of the page.|

---

### Step-by-Step Exploitation

#### 1. Changing the Background

To set a dark, "hacker-style" background, you can inject:

HTML

```
<script>document.body.style.background = "black"</script>
```

#### 2. Changing the Tab Title

To make the breach obvious in the user's browser tabs:

HTML

```
<script>document.title = 'Hacked by [Name]'</script>
```

#### 3. Overwriting the Entire Page

The most dramatic impact comes from replacing the `<body>` content. This removes the original site features and replaces them with your message.

**Payload Template:**

HTML

```
<script>document.body.innerHTML = '<center><h1>Site Under Maintenance</h1><img src="URL_TO_IMAGE"></center>'</script>
```

---

### Technical Considerations

- **Minification:** When injecting HTML into the `innerHTML` property, you must "minify" the HTML code into a single line to ensure the JavaScript string doesn't break due to line breaks.
    
- **Execution Order:** Since the malicious scripts are usually added at the end of the original source code, they execute _after_ the legitimate page loads, effectively "painting over" the original design.
    
- **jQuery:** If the site uses jQuery, you can achieve the same results more concisely:
    
    `$('body').html('<h1>Hacked</h1>');`
    

### Defense Impact

Defacement through Stored XSS is often harder to fix than simple Reflected XSS because the payload resides in the **database**. Admins must identify the specific database entry containing the script and delete it to restore the site.
