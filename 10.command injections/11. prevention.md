# Command Injection Prevention (Section 11 Notes)

## 1. Avoid System Command Execution

- The safest way to prevent command injection is to avoid using system commands with user input.
    
- Functions like `system()`, `exec()`, and `shell_exec()` are risky when combined with user input.
    

### Better approach

- Use built-in secure functions instead of system commands.
    

Example (PHP):

- Instead of using OS commands for network checks, use:
    
    - `fsockopen()` (safer alternative)
        

Key idea:

- Never directly pass user input into system-level commands.
    

---

## 2. Input Validation

- Input validation ensures the data matches the expected format before processing.
    
- It should be done on both:
    
    - Front-end (client side)
        
    - Back-end (server side, most important)
        

### PHP example:

```php
if (filter_var($_GET['ip'], FILTER_VALIDATE_IP)) {
    // valid input, proceed
} else {
    // reject request
}
```

Key idea:

- Only allow correctly formatted input (e.g., valid IP addresses).
    
- Reject everything else.
    

---

## 3. Input Sanitization

- Sanitization removes unwanted or dangerous characters from input after validation.
    
- It is critical for preventing injection attacks.
    

### PHP sanitization example:

```php
$ip = preg_replace('/[^A-Za-z0-9.]/', '', $_GET['ip']);
```

This allows only:

- Alphabets (A–Z, a–z)
    
- Numbers (0–9)
    
- Dot (.)
    

Everything else is removed:

- Special characters like `;`, `|`, `&`, `$`, spaces, etc.
    

### JavaScript example:

```javascript
var ip = ip.replace(/[^A-Za-z0-9.]/g, '');
```

Key idea:

- Validation checks correctness.
    
- Sanitization removes harmful content.
    

---

## 4. Use Secure Libraries

- Prefer trusted libraries over custom filtering logic.
    
- Example in NodeJS:
    
    - `DOMPurify.sanitize()`
        

Key idea:

- Built-in or tested libraries reduce security mistakes.
    

---

## 5. Escaping Special Characters

- Escaping prevents special characters from being interpreted as commands.
    
- Example in PHP:
    
    - `escapeshellcmd()` or similar functions
        

Limitation:

- Escaping alone is not fully secure and can sometimes be bypassed.
    

Key idea:

- Use only as an additional layer, not a primary defense.
    

---

## 6. Server-Side Security Configuration

Important protections:

- Use Web Application Firewall (WAF)
    
    - Apache mod_security
        
    - Cloudflare, Imperva, etc.
        
- Run web server with least privilege
    
    - Example: `www-data` user
        
- Disable dangerous functions in PHP:
    
    - `system`, `exec`, etc.
        
- Restrict file system access:
    
    - `open_basedir = /var/www/html`
        
- Block:
    
    - Double encoded input
        
    - Non-ASCII characters in URLs
        
- Avoid outdated or vulnerable libraries
