
# **Command Injection

## **1. Introduction**

- **Command Injection** is a critical vulnerability.
    
- It allows attackers to **execute OS-level commands** on the backend server.
    
- Impact:
    
    - Full system compromise
        
    - Data theft
        
    - Privilege escalation
        
    - Network compromise
        

---

## **2. What are Injection Vulnerabilities**

- Injection is when:
    
    - **User input is treated as part of code/query**
        
    - Instead of just data
        
- Ranked **#3 in OWASP Top 10**
    
- Root cause:
    
    - Lack of **input validation/sanitization**
        

### **Key Idea**

- Attacker **breaks out of input context**
    
- Modifies original query behavior
    

---

## **3. Types of Injection Attacks**

|Injection Type|Description|
|---|---|
|OS Command Injection|User input used in system commands|
|Code Injection|Input executed as code|
|SQL Injection|Input used in SQL queries|
|XSS / HTML Injection|Input rendered in browser|

### **Other Types**

- LDAP Injection
    
- NoSQL Injection
    
- XPath Injection
    
- HTTP Header Injection
    
- IMAP Injection
    
- ORM Injection
    

---

## **4. Core Concept of Injection**

- Happens when:
    
    - Input is **unsanitized**
        
    - Directly used in:
        
        - Commands
            
        - Queries
            
        - Code execution functions
            

### **General Flow**

```
User Input → Application → Command/Query Execution → Vulnerability
```

---

## **5. OS Command Injection**

- Occurs when:
    
    - User input is used in **system-level commands**
        
- Requirement:
    
    - Input must affect **command execution**
        

### **Why it is dangerous**

- Direct interaction with OS
    
- Can:
    
    - Create/delete files
        
    - Run scripts
        
    - Open shells
        

---

## **6. Backend Command Execution Functions**

### **In PHP**

Common dangerous functions:

- `exec()`
    
- `system()`
    
- `shell_exec()`
    
- `passthru()`
    
- `popen()`
    

---

## **7. Vulnerable PHP Example**

```php
<?php
if (isset($_GET['filename'])) {
    system("touch /tmp/" . $_GET['filename'] . ".pdf");
}
?>
```

### **Explanation**

- User controls `filename`
    
- Used directly in command:
    
    ```
    touch /tmp/<input>.pdf
    ```
    
- No sanitization → vulnerable
    

### **Attack Idea**

- Inject command separators:
    
    ```
    filename=test; whoami
    ```
    
- Result:
    
    ```
    touch /tmp/test.pdf; whoami
    ```
    

---

## **8. NodeJS Example**

```javascript
app.get("/createfile", function(req, res){
    child_process.exec(`touch /tmp/${req.query.filename}.txt`);
})
```

### **Explanation**

- Uses `child_process.exec`
    
- Input directly embedded in command
    
- No validation → vulnerable
