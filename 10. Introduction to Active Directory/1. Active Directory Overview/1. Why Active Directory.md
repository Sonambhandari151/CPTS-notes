# Why Active Directory?

## What Is Active Directory?
Active Directory (AD) is Microsoft's **directory service** for Windows network environments — a distributed, hierarchical structure for **centralized management** of an organization's resources:
- Users, computers, groups
- Network devices, file shares
- Group policies, trusts

AD provides **authentication and authorization** across an entire Windows domain.

> [!info] Structure at a glance
> Domain Policy (enterprise-wide policy/licensing) → Group Policy Objects (application/settings management) → Organizational Units (e.g. Marketing, Sales) containing the actual users/resources. AD Server + Application Library/File Share sit alongside this hierarchy.

## Why It's a High-Value Attack Target

### 1. Backward Compatibility = Weak Defaults
AD is designed to be backward-compatible, which means many features are **not secure by default** and are easy to misconfigure. These weaknesses enable lateral and vertical movement within a network.

### 2. It's a Giant Readable Database
> [!warning] Key insight
> AD is essentially a large **read-only database accessible to all domain users**, regardless of privilege level. A basic, unprivileged domain user account can enumerate most objects in AD.

This means:
- **Any** compromised account — even a low-privilege one — can be used to fully map the domain and hunt for misconfigurations.
- Multiple real attacks require **nothing more than a standard domain user account** (e.g. the **noPac** attack, first released December 2021).
- This is exactly why **defense-in-depth** matters: careful hardening, network segmentation, and least privilege are essential — not optional.

### 3. Massive Adoption
- ~**95% of Fortune 500 companies** run Active Directory.
- Microsoft holds a near-complete monopoly in the directory services space.
- Even as orgs shift to cloud/hybrid, **on-prem AD isn't going away** — expect to encounter it on nearly every internal network pentest.

### 4. Ransomware Targets AD Directly
**Conti Ransomware** (400+ attacks worldwide) has leveraged critical AD flaws to escalate privileges and move laterally:

| CVE            | Name           | Use by Attackers                         |
| -------------- | -------------- | ---------------------------------------- |
| CVE-2021-34527 | PrintNightmare | Privilege escalation                     |
| CVE-2020-1472  | Zerologon      | Privilege escalation / domain compromise |

> [!danger] Why this matters for pentesters
> Researchers regularly find new high-risk AD attacks requiring **only a standard domain user** to gain **full administrative control of the domain**. Understanding AD structure is the first step toward finding — and fixing — these flaws before attackers do.

## History of Active Directory

| Year      | Milestone                                                                                                                                                  |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1971      | LDAP's roots appear in early RFCs                                                                                                                          |
| 1993      | Novell Directory Services released (based on the X.500 org-unit concept) — earliest true directory system                                                  |
| 1990      | Microsoft's first directory attempt: Windows NT 3.0 (combined LAN Manager + OS/2 features)                                                                 |
| Mid-1990s | Active Directory concept first introduced                                                                                                                  |
| 1997      | First AD beta release                                                                                                                                      |
| 2000      | AD becomes part of the OS with Windows Server 2000                                                                                                         |
| 2003      | Server 2003 adds the **Forest** feature — "containers" grouping multiple domains/users/computers                                                           |
| 2008      | **ADFS** (Active Directory Federation Services) introduced — enables SSO (single sign on) across organizational boundaries via claims-based access control |
| 2016      | Server 2016 adds cloud migration support, user access monitoring, and **gMSA** (Group Managed Service Accounts)                                            |
| 2016      | **Azure AD Connect** released — SSO bridge for Office 365 migration                                                                                        |

> [!tip] gMSA note
> Group Managed Service Accounts are a recommended mitigation against **Kerberoasting** — worth remembering when this comes up again later in the module.

### The NT Lineage
Windows NT 3.0 was built by combining LAN Manager protocol features with OS/2 — a joint Microsoft/IBM effort led by **Ed Iacobucci** (who also helped design IBM DOS and later co-founded Citrix). The NT line evolved through the 90s, adapting **LDAP** and **Kerberos** alongside Microsoft's own proprietary additions — this lineage is the direct ancestor of modern AD.

### ADFS in Plain Terms
ADFS lets users access applications **across organizational boundaries** with a single set of credentials, using a **claims-based Access Control Authorization model** — the identity provider packages a set of identity-related "claims" into a security token, which applications then trust.
