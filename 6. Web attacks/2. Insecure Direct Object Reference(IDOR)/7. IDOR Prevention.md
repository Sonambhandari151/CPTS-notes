

## 1. Object-Level Access Control

- Main cause of IDOR = weak or missing access control.
    
- Server must verify whether a user is allowed to access a resource.
    

### RBAC (Role-Based Access Control)

- Users get roles like:
    
    - employee
        
    - manager
        
    - admin
        
- Every request is checked against permissions.
    

### Example

```javascript
match /api/profile/{userId} {
    allow read, write: if user.isAuth == true
    && (user.uid == userId || user.roles == 'admin');
}
```

### Meaning

Access allowed only if:

- user is logged in
    
- AND:
    
    - user accesses own profile
        
    - OR user is admin
        

---

## Important Security Point

Do NOT trust user-controlled values like:

- Cookies
    
- Hidden fields
    
- JSON role parameters
    

Bad example:

```json
{
  "role": "admin"
}
```

User can modify this manually.

Instead:

- server should get role from backend session/RBAC system.

# 2. Secure Object Referencing

Bad practice:

```bash
uid=1
uid=2
uid=3
```

Easy to enumerate.

---

## Better Approach

Use:

- UUIDs
    
- Random IDs
    
- Salted hashes
    

Example UUID:

```text
89c9b29b-d19f-4515-b2dd-abb6e693eb20
```

Hard to guess.

---

## Example PHP Code

```php
$uid = intval($_REQUEST['uid']);
$query = "SELECT url FROM documents where uid=" . $uid;
$result = mysqli_query($conn, $query);
$row = mysqli_fetch_array($result);
echo "<a href='" . $row['url'] . "' target='_blank'></a>";
```

### Meaning

- App gets user id
    
- Fetches matching document URL from database
    
- Returns correct document
    

---

# Important Points

## Never Generate Hashes on Frontend

Bad:

```javascript
CryptoJS.MD5(btoa(uid))
```

Reason:

- attacker can view JS code
    
- attacker can reproduce hashes
    

---

## Correct Method

- Generate UUID/hash on backend
    
- Store in database
    
- Map UUID → actual object internally
    

---

# Best Protection Against IDOR

Use BOTH:

1. Strong Access Control (RBAC)
    
2. Strong Random Object References (UUIDs)
    

Only UUIDs are NOT enough if access control is broken.
