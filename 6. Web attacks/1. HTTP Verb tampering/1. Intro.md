# I

## HTTP Methods (Verbs)

HTTP requests use methods called verbs.

Common verbs:

|Verb|Purpose|
|---|---|
|GET|Retrieve data|
|POST|Send data|
|HEAD|Same as GET but returns headers only|
|PUT|Upload/write data|
|DELETE|Delete resource|
|OPTIONS|Show allowed methods|
|PATCH|Modify resource partially|

---

# HTTP Verb Tampering

Changing the HTTP method to:

- bypass security
    
- access restricted functionality
    
- bypass filters/authentication
    

---

# Cause of Vulnerability

Occurs due to:

1. Insecure web server configuration
    
2. Insecure coding practices
    

---

# 1. Insecure Web Server Configuration

Example:

```xml
<Limit GET POST>
    Require valid-user
</Limit>
```

### Issue

Authentication only protects:

- GET
    
- POST
    

Other methods like:

- HEAD
    
- PUT
    

may bypass authentication.

---

# Example Attack

Blocked:

```http
GET /admin
```

Try:

```http
HEAD /admin
```

If HEAD is unrestricted:

- authentication bypass possible
    

---

# 2. Insecure Coding

Developers apply security filters only to one HTTP method.

Example:

```php
$pattern = "/^[A-Za-z\s]+$/";

if(preg_match($pattern, $_GET["code"])) {
    $query = "Select * from ports where port_code like '%" . $_REQUEST["code"] . "%'";
}
```

---

# Vulnerability Explanation

### Filter checks:

```php
$_GET["code"]
```

### But query uses:

```php
$_REQUEST["code"]
```

`$_REQUEST` includes:

- GET
    
- POST
    
- COOKIE
    

---

# Attack Logic

Attacker sends:

- empty GET request
    
- malicious POST parameter
    

Filter checks only GET:

- passes validation
    

But SQL query uses POST value:

- SQL Injection succeeds
