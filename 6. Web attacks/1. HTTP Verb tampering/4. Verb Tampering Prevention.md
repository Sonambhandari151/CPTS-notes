# Verb Tampering Prevention – Short Notes

# HTTP Verb Tampering

Occurs when:

- security checks apply only to specific HTTP methods
    
- attacker changes request method to bypass filters/authentication
    

Example:

```http
GET → POST
```

---

# Causes

1. Insecure Configuration
    
2. Insecure Coding
    

---

# Insecure Apache Config

```xml
<Directory "/var/www/html/admin">
    <Limit GET>
        Require valid-user
    </Limit>
</Directory>
```

Problem:

- only GET protected
    
- POST/HEAD/OPTIONS bypass protection
    

Secure alternative:

```xml
LimitExcept
```

---

# Insecure Tomcat Config

```xml
<http-method>GET</http-method>
```

Problem:

- only GET restricted
    

Secure alternative:

```xml
http-method-omission
```

---

# Insecure ASP.NET Config

```xml
<allow verbs="GET" roles="admin">
```

Problem:

- other methods bypass authorization
    

Secure alternative:

```text
add/remove
```

---

# Important Prevention

- never secure only one HTTP method
    
- validate all HTTP methods
    
- disable HEAD if unnecessary
    

---

# Vulnerable PHP Code

```php
if (isset($_REQUEST['filename'])) {

    if (!preg_match('/[^A-Za-z0-9. _-]/',
        $_POST['filename'])) {

        system("touch " . $_REQUEST['filename']);
    }
}
```

---

# Vulnerability

Filter checks:

```php
$_POST['filename']
```

But command uses:

```php
$_REQUEST['filename']
```

Attacker sends malicious payload through GET:

```http
GET /?filename=file;id
```

Filter bypass occurs because:

- POST is empty
    
- REQUEST accepts GET values
    

---

# Prevention

Use same method everywhere.

Validate all request sources:

- GET
    
- POST
    
- REQUEST
    

---

# Safe Functions

| Language | Function                        |
| -------- | ------------------------------- |
| PHP      | `$_REQUEST['param']`            |
| Java     | `request.getParameter('param')` |
| C#       | `Request['param']`              |
