
# 1. Purpose

SQLMap must send requests correctly to:

- detect SQL Injection
    
- exploit vulnerabilities
    

Small mistakes can cause failure:

- missing cookies
    
- wrong POST data
    
- incorrect headers
    
- wrong HTTP method
    

---

# 2. Using cURL Requests

Modern browsers allow copying requests as cURL.

## Steps

1. Open Developer Tools → Network tab
    
2. Capture request
    
3. Right-click request
    
4. Select:
    

```text
Copy as cURL
```

---

# Example cURL Command

```bash
curl 'http://www.example.com/?id=1'
```

---

# Convert to SQLMap

Replace:

```text
curl
```

with:

```text
sqlmap
```

---

# Example

```bash
sqlmap 'http://www.example.com/?id=1' -H 'User-Agent: Mozilla/5.0'
```

---

# Advantage

- Exact browser request reproduced
    
- Easier setup
    
- Fewer configuration mistakes
    

---

# 3. GET Requests

GET parameters are passed in URL.

## Example

```bash
sqlmap -u "http://site.com?id=1"
```

---

# Meaning

Parameter:

```text
id=1
```

will be tested for SQL Injection.

---

# 4. POST Requests

POST data is sent in request body.

## Example

```bash
sqlmap 'http://www.example.com/' --data 'uid=1&name=test'
```

---

# Meaning

SQLMap tests:

- `uid`
    
- `name`
    

for SQL Injection.

---

# 5. Using `-p`

Used to test only selected parameter.

## Example

```bash
sqlmap --data 'uid=1&name=test' -p uid
```

---

# Meaning

Only:

```text
uid
```

is tested.

---

# Advantage

- Faster scans
    
- Fewer requests
    
- Better targeting
    

---

# 6. Using `*` Injection Marker

## Example

```bash
sqlmap --data 'uid=1*&name=test'
```

---

# Meaning

```text
Inject payload exactly here
```

SQLMap injects inside:

```text
uid
```

---

# Difference Between `-p` and `*`

|Option|Purpose|
|---|---|
|`-p uid`|Select parameter|
|`*`|Select exact injection position|

---

# 7. Full HTTP Requests with `-r`

Complex requests may contain:

- many headers
    
- cookies
    
- tokens
    
- large POST bodies
    

---

# Solution

Use:

```bash
-r
```

---

# Request File Example

```http
GET /?id=1 HTTP/1.1
Host: www.example.com
User-Agent: Mozilla/5.0
Cookie: PHPSESSID=test
```

---

# Running SQLMap

```bash
sqlmap -r req.txt
```

---

# Meaning

SQLMap reads:

- URL
    
- headers
    
- cookies
    
- method
    
- parameters
    

directly from file.

---

# Benefits

- Easier for complex requests
    
- More accurate
    
- Useful with Burp Suite
    

---


# 9. Injection Marker Inside Request File

Example:

```http
GET /?id=* HTTP/1.1
```

---

# Meaning

SQLMap injects payload at:

```text
id
```

---

# 10. Using Cookies

## Option

```bash
--cookie
```

---

# Example

```bash
sqlmap --cookie='PHPSESSID=abcd123'
```

---

# Purpose

Use authenticated session.

---

# Why Important

Many pages require login access.

Without valid cookie:

- redirected to login
    
- no vulnerability detection
    

---

# 11. Custom Headers

## Option

```bash
-H
```

or

```bash
--header
```

---

# Example

```bash
sqlmap -H='Cookie:PHPSESSID=abcd123'
```

---

# Purpose

Add custom HTTP headers manually.

---

# Common Headers

|Header|Purpose|
|---|---|
|Cookie|Session management|
|User-Agent|Browser identity|
|Referer|Referring page|
|Host|Host name|

---

# 12. User-Agent Randomization

# Problem

Default SQLMap User-Agent:

```http
User-Agent: sqlmap/1.x
```

may be blocked by WAF/firewall.

---

# Solution

Use:

```bash
--random-agent
```

---

# Meaning

Random browser User-Agent is used.

---

# Benefit

Helps bypass basic protections.

---

# 13. Mobile User-Agent

## Option

```bash
--mobile
```

---

# Meaning

Pretends request comes from mobile device.

---

# Use Case

Some websites:

- behave differently for mobile
    
- apply weaker protections
    

---

# 14. Testing Headers for SQL Injection

SQLMap normally tests:

- URL parameters
    
- POST parameters
    

But SQLi may exist inside:

- cookies
    
- headers
    

---

# Example

```bash
--cookie="id=1*"
```

---

# Meaning

Inject SQL payload into cookie value.

---

# 15. Custom HTTP Methods

By default SQLMap uses:

- GET
    
- POST
    

Some APIs use:

- PUT
    
- DELETE
    
- PATCH
    

---

# Option

```bash
--method
```

---

# Example

```bash
sqlmap -u www.target.com --data='id=1' --method PUT
```

---

# Meaning

Send request using:

```text
PUT
```

method.

---

# 16. JSON Requests

SQLMap supports JSON formatted requests.

---

# Example

```json
{"id":1}
```

---

# Example Command

```bash
sqlmap --data='{"id":1}'
```

---

# Purpose

Useful for:

- APIs
    
- modern web applications
    

---

# 17. XML Requests

SQLMap also supports XML requests.

---

# Example

```xml
<id>1</id>
```

---

# 18. Complex JSON/XML Requests

Large requests are better handled using:

```bash
-r req.txt
```

---

# Example JSON Request File

```json
{
  "id":"1",
  "title":"Example"
}
```

---

# Running SQLMap

```bash
sqlmap -r req.txt
```

---

# SQLMap Detection Example

```text
JSON data found in HTTP body
```

SQLMap automatically detects JSON format.

---

# Important Concepts Summary

|Option|Purpose|
|---|---|
|`-u`|URL testing|
|`--data`|POST data|
|`-p`|Select parameter|
|`*`|Injection marker|
|`-r`|Read full request|
|`--cookie`|Send cookies|
|`-H`|Add headers|
|`--random-agent`|Random User-Agent|
|`--mobile`|Mobile User-Agent|
|`--method PUT`|Custom HTTP method|
|JSON/XML support|API testing|

---

# Quick Flow

```text
1. Capture request
2. Save request
3. Add injection marker if needed
4. Run SQLMap
5. Detect SQL Injection
```
