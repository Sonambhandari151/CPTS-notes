#
## 1. Display Errors

### Option

```bash
--parse-errors
```

### Purpose

Parses and displays DBMS error messages during SQLMap execution.

### Example

```bash
sqlmap -u "http://target.com?id=1" --parse-errors
```

### Example Output

```text
parsed DBMS error message:
SQLSTATE[42000]: Syntax error...
```

### Benefit

- Helps identify SQL syntax problems
    
- Helps determine DBMS type
    
- Makes debugging easier

# 2. Store the Traffic

### Option

```bash
-t
```

### Example

```bash
sqlmap -u "http://www.target.com/vuln.php?id=1" --batch -t /tmp/traffic.txt
```

### Purpose

Stores:

- all HTTP requests
    
- all HTTP responses
    

inside a file.

### Traffic File Contains

- request headers
    
- request body
    
- response headers
    
- response body
    

### Benefit

Allows manual investigation of requests and responses.

---

# 3. Verbose Output

### Option

```bash
-v
```

### Example

```bash
sqlmap -u "http://www.target.com/vuln.php?id=1" -v 6 --batch
```

### Purpose

Increases verbosity level of console output.

### `-v 6` Shows

- debug information
    
- HTTP requests
    
- HTTP responses
    
- headers
    
- payload activity
    

### Benefit

Lets us monitor everything SQLMap does in real time.

---

# 4. Using Proxy

### Option

```bash
--proxy
```

### Purpose

Routes SQLMap traffic through a proxy such as Burp Suite.

### Benefit

Allows:

- manual request inspection
    
- replaying requests
    
- modifying traffic
    
- using Burp features with SQLMap traffic
    

### Traffic Flow

```text
SQLMap → Burp Proxy → Target
```
