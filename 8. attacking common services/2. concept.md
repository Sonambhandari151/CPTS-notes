
## ** Pattern Template (Core Idea)**

Every attack is divided into **4 categories**:

1. **Source**
    
2. **Process**
    
3. **Privileges**
    
4. **Destination**
    
![[Pasted image 20260427215158.png]]
### **Flow**

```
Source → Process → Privileges → Destination
```

- This is a **linear cycle**
    
- Destination does not always become a new source
    

---

## **3. Source**

- Source = **origin of information**
    
- It is what gets **exploited**
    

### **Types of Sources**

| Source     | Description                        |
| ---------- | ---------------------------------- |
| Code       | Output from program functions      |
| Libraries  | Prebuilt code, configs, classes    |
| Config     | Static values controlling behavior |
| APIs       | Interface to send/receive data     |
| User Input | Data entered by user               |

---

## **4. Process**

- Process = **how information is handled**
    
- Defined by program logic
    

### **Components of Process**

| Component       | Description             |
| --------------- | ----------------------- |
| PID             | Identifies process      |
| Input           | Data given to process   |
| Data Processing | Functions handling data |
| Variables       | Store temporary data    |
| Logging         | Stores events/data      |

---

## **5. Privileges**

- Privileges = **permissions of process**
    
- Control what actions are allowed
    

### **Types of Privileges**

| Type     | Description                            |
| -------- | -------------------------------------- |
| System   | Highest (Windows: SYSTEM, Linux: root) |
| User     | Assigned to specific users             |
| Groups   | Set of users with permissions          |
| Policies | Control execution rules                |
| Rules    | App-level permissions                  |

---

## **6. Destination**

- Destination = **final goal/output**
    
- Result is:
    
    - Stored OR
        
    - Sent somewhere
        

### **Types**

| Type    | Description                   |
| ------- | ----------------------------- |
| Local   | Stored or processed in system |
| Network | Sent to remote system         |

---

# **7. Log4j Example (CVE-2021-44228)**

## **Source**

- Attacker manipulates:
    
    - **HTTP User-Agent**
        
- Inserts:
    
    ```
    JNDI lookup command
    ```
    

---

## **Process**

- Log4j:
    
    - Logs User-Agent as string
        
- Vulnerability:
    
    - Misinterprets input
        
    - Executes it instead of logging
        

---

## **Privileges**

- Logging runs with:
    
    - **Administrator privileges**
        
- Reason:
    
    - Logs contain sensitive data
        

---

## **Destination**

- JNDI lookup:
    
    - Connects to attacker server
        
- Downloads:
    
    - Malicious Java class
        
- Executes:
    
    - Leads to **Remote Code Execution (RCE)**
        

---

# **8. Attack Flow (Step-wise)**

## **Phase 1: Initiation**

| Step | Action                           | Category    |
| ---- | -------------------------------- | ----------- |
| 1    | User-Agent manipulated with JNDI | Source      |
| 2    | Process misinterprets input      | Process     |
| 3    | Command runs with admin rights   | Privileges  |
| 4    | Connects to attacker server      | Destination |

---

## **Phase 2: Remote Code Execution**

| Step | Action                             | Category    |
| ---- | ---------------------------------- | ----------- |
| 5    | Malicious class becomes new source | Source      |
| 6    | Code is read and processed         | Process     |
| 7    | Executed with admin privileges     | Privileges  |
| 8    | Attacker gains control remotely    | Destination |
