
---

## 1. What is Client-Side Validation?

- File type validation is done using **front-end JavaScript**
    
- Example checks:
    
    - Only images allowed (.jpg, .jpeg, .png)
        
    - File picker restricts file types
        
    - Upload button disabled for invalid files
        

---

## 2. Key Weakness

- All validation happens in the **browser**
    
- Browser is under attacker control
    
- Therefore:
    
    - Validation can be **bypassed completely**
        

---

## 3. Typical Scenario

- Profile image upload feature
    
- File selector shows only:
    
    - jpg, jpeg, png
        
- PHP files:
    
    - hidden or greyed out
        
- Error message shown:
    
    - “Only images are allowed!”
        
- Upload button gets disabled
    

---

## 4. Why Attack Still Works

- No HTTP request is sent when validation fails
    
- Backend never enforces file type restriction
    
- So attacker can bypass frontend logic
    

---

## 5. Method 1 — Modify HTTP Request (Burp Suite)

### Idea:

Intercept upload request and modify it before sending.

### Steps:

1. Select a valid image (e.g., HTB.png)
    
2. Capture request in Burp
    
3. Modify:
    
    - `filename="HTB.png"` → `filename="shell.php"`
        
    - Replace file content with PHP code
        

### Example PHP shell:

```php
<?php system($_REQUEST['cmd']); ?>
```

### Result:

- Server stores `.php` file
    
- File executes when accessed
    
- Leads to **Remote Code Execution (RCE)**
    

---

## 6. Important Request Parts

- `filename` → controls stored file name
    
- File content → actual uploaded data
    
- `Content-Type` → usually not reliable for security
    

---

## 7. Method 2 — Disable Front-End Validation

### HTML input example:

```html
<input type="file" name="uploadFile" id="uploadFile"
onchange="checkFile(this)" accept=".jpg,.jpeg,.png">
```

### Key parts:

- `accept=` → limits file selection UI
    
- `onchange="checkFile(this)"` → runs validation function
    

---

## 8. JavaScript Validation Function

Example:

```javascript
function checkFile(File) {
    if (extension !== 'jpg' &&
        extension !== 'jpeg' &&
        extension !== 'png') {

        $('#error_message').text("Only images are allowed!");
        File.form.reset();
        $("#submit").attr("disabled", true);
    }
}
```

### What it does:

- Checks file extension
    
- If invalid:
    
    - Shows error message
        
    - Resets form
        
    - Disables upload button
        

---

## 9. Bypass via DevTools (DOM Manipulation)

### Steps:

1. Open DevTools:
    
    - `CTRL + SHIFT + C`
        
2. Inspect file input element
    
3. Remove or modify:
    
    - `onchange="checkFile(this)"` → delete it
        
    - `accept=".jpg,.jpeg,.png"` → optional removal
        
4. Result:
    
    - No validation runs
        

---

## 10. Outcome after bypass

- PHP file can now be selected and uploaded
    
- File stored on server (e.g., `/profile_images/shell.php`)
    
- Accessing it executes code:
    

```
http://SERVER_IP/profile_images/shell.php?cmd=id
```

---

## 11. Important Concept

|Layer|Security|Control|
|---|---|---|
|Front-end|UI validation only|Attacker can modify|
|Back-end|Real security check|Must enforce properly|

---

## 12. Key Takeaways

- Client-side validation is **not security**
    
- It is only for user experience
    
- Can be bypassed by:
    
    - Burp request modification
        
    - DevTools HTML/JS editing
        
- Proper security must always be **server-side validation**
    

---

## One-line summary

> Anything validated in the browser can be changed or removed by the attacker.
