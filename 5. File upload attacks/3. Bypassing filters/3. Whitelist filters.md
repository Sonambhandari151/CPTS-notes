

### 1. What is a Whitelist Filter?

- A **whitelist filter** allows only specific file extensions (e.g., `.jpg`, `.png`, `.gif`).
    
- Everything else is automatically rejected.
    
- It is generally **more secure than blacklist filtering** because:
    
    - It does not try to block “bad” extensions.
        
    - Instead, it explicitly allows only known safe ones.
        

---

### 2. Whitelist vs Blacklist (Concept Difference)

**Blacklist**

- Blocks known dangerous extensions (e.g., `.php`, `.jsp`)
    
- Weak because attackers can use unknown or new extensions
    

**Whitelist**

- Only allows approved extensions
    
- Stronger security model
    

**In practice**

- Blacklist → used when many file types must be allowed (file managers)
    
- Whitelist → used when only few file types are needed (profile images, uploads)
    
- Both can also be used together for layered security
    

---

### 3. Basic Whitelist Validation Example

#### Example logic:

```php
$fileName = basename($_FILES["uploadFile"]["name"]);

if (!preg_match('^.*\.(jpg|jpeg|png|gif)', $fileName)) {
    echo "Only images are allowed";
    die();
}
```

### Key idea:

- The server checks if the filename contains allowed extensions.
    
- If not, upload is rejected.
    

---

### 4. Weakness in Regex-Based Whitelist

#### Problem:

- The regex only checks **if extension exists somewhere in filename**
    
- It does NOT strictly ensure it is the final extension
    

So this becomes dangerous:

```
shell.jpg.php
```

Why it works:

- Regex sees `.jpg` → allows file
    
- But server may still execute `.php` part
    

---

### 5. Bypass Technique: Double Extensions

#### Example:

```
shell.jpg.php
```

How it works:

- Passes whitelist check (`jpg`)
    
- Still executes as PHP (`.php` at end or server misconfiguration)
    

---

### 6. Server Misconfiguration Risk

Even strict validation can fail if server config is weak:

Example Apache config:

```xml
<FilesMatch ".+\.ph(ar|p|tml)">
    SetHandler application/x-httpd-php
</FilesMatch>
```

### Issue:

- If regex is not anchored properly (`$`)
    
- Any filename containing `.php` may execute
    

Example:

```
shell.php.jpg   → may execute PHP code
```

---

### 7. Reverse Double Extension

- Happens when:
    
    - App blocks `.php`
        
    - But server still executes based on substring match
        

Example:

```
shell.php.jpg
```

Result:

- Upload passes whitelist (`.jpg`)
    
- Server executes `.php` inside filename
    

---

### 8. Character Injection Bypass

Attackers inject special characters to confuse validation.

Common payload characters:

```
%20  %0a  %00  %0d0a  /  .\  .  …  :
```

### Why it works:

- File systems / parsers interpret filenames differently
    
- Server may truncate or ignore parts after special characters
    

---

### 9. Example Attacks (Concept)

#### Null byte injection (older systems):

```
shell.php%00.jpg
```

- File saved as `shell.php`
    
- Whitelist sees `.jpg`
    

---

#### Windows-based trick:

```
shell.aspx:.jpg
```

- Windows may treat it as `.aspx`
    

---

### 10. Fuzzing for Allowed Extensions

- Use wordlists (like SecLists)
    
- Try many extensions:
    
    - `.jpg`
        
    - `.png`
        
    - `.php5`
        
    - `.phtml`
        
    - `.phar`
        

### Goal:

- Identify weak validation logic
    
- Find bypassable extension
