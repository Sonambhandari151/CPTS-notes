
- File upload features allow users to upload images, documents, etc., but can introduce security risks if not properly handled.
    
- Main risk: if uploaded files are not properly validated or filtered, attackers can upload malicious files and gain control of the server.
    
- File upload vulnerabilities are common and often rated **High or Critical severity** in CVE reports.
    
- **Types of issues:**
    
    - Weak or missing file validation
        
    - Improper extension/content checks
        
    - Outdated libraries used for upload handling
        
- **Most dangerous case:**
    
    - **Unauthenticated arbitrary file upload**
        
    - Allows any user to upload any file type → can lead to **Remote Code Execution (RCE)**
        
- **Common exploitation method:**
    
    - Uploading a **web shell** to execute server commands
        
    - Uploading a script that triggers a **reverse shell** to attacker’s machine
        
- **Even restricted uploads can be dangerous:**
    
    - Can lead to:
        
        - XSS (Cross-Site Scripting)
            
        - XXE (XML External Entity attacks)
            
        - Denial of Service (DoS)
            
        - Overwriting system files/configurations
            
- **Key takeaway:**
    
    - File upload vulnerabilities are often caused by poor validation or insecure/outdated implementation and can lead to full system compromise.
