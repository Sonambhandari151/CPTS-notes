# Preventing File Upload Vulnerabilities

# Overview

File upload functionality is highly dangerous if not securely implemented.

Attackers may abuse uploads to perform:

- Remote Code Execution (RCE)
    
- XSS
    
- XXE
    
- SSRF
    
- DoS
    
- Path Disclosure
    

Secure upload handling requires:

- extension validation
    
- content validation
    
- upload isolation
    
- strict access control
    

---

# Extension Validation

# Why Extension Validation Matters

Web servers often decide:

- how files execute
    
- how files are processed
    

based on:

```text
file extension
```

Example:

```text
.php
```

may execute as PHP.

---

# Recommended Approach

Use BOTH:

- whitelist
    
- blacklist
    

---

# Why Use Both?

## Whitelist

Allows only safe extensions.

---

## Blacklist

Blocks dangerous extensions if whitelist is bypassed.

Example:

```text
shell.php.jpg
```

---

# Secure Example

```php
$fileName = basename($_FILES["uploadFile"]["name"]);

// blacklist test
if (preg_match('/^.*\.ph(p|ps|ar|tml)/', $fileName)) {
    echo "Only images are allowed";
    die();
}

// whitelist test
if (!preg_match('/^.*\.(jpg|jpeg|png|gif)$/', $fileName)) {
    echo "Only images are allowed";
    die();
}
```

---

# Blacklist Explanation

```php
preg_match('/^.*\.ph(p|ps|ar|tml)/', $fileName)
```

Blocks:

```text
.php
.phps
.phar
.phtml
```

even if embedded inside filename.

---

# Example Blocked

```text
shell.php.jpg
```

contains:

```text
.php
```

---

# Whitelist Explanation

```php
preg_match('/^.*\.(jpg|jpeg|png|gif)$/', $fileName)
```

Allows only filenames ending with:

```text
.jpg
.jpeg
.png
.gif
```

---

# Important Security Point

## Backend validation is mandatory

Frontend validation alone is NOT secure.

Attackers can bypass:

- JavaScript checks
    
- browser restrictions
    

using:

- Burp Suite
    
- curl
    
- custom requests
    

---

# Frontend Validation Still Helps

Although bypassable, it:

- prevents accidental uploads
    
- reduces false security alerts
    

---

# Content Validation

# Why Extension Validation Is Not Enough

Attackers can rename:

```text
shell.php
```

to:

```text
shell.png
```

So application must verify:

- actual file content
    

---

# What Should Be Validated

1. File extension
    
2. Content-Type header
    
3. MIME type / file signature
    

---

# Secure Content Validation Example

```php
$fileName = basename($_FILES["uploadFile"]["name"]);
$contentType = $_FILES['uploadFile']['type'];
$MIMEtype = mime_content_type($_FILES['uploadFile']['tmp_name']);

// whitelist test
if (!preg_match('/^.*\.png$/', $fileName)) {
    echo "Only PNG images are allowed";
    die();
}

// content test
foreach (array($contentType, $MIMEtype) as $type) {
    if (!in_array($type, array('image/png'))) {
        echo "Only PNG images are allowed";
        die();
    }
}
```

---

# Extension Validation

```php
preg_match('/^.*\.png$/', $fileName)
```

Allows only:

```text
.png
```

files.

---

# Content-Type Validation

```php
$contentType = $_FILES['uploadFile']['type'];
```

Checks HTTP header:

```http
Content-Type: image/png
```

---

# MIME Validation

```php
mime_content_type()
```

Checks:

- magic bytes
    
- real file structure
    

---

# Why MIME Validation Is Stronger

Because:

```text
server checks actual file content
```

instead of trusting browser.

---

# Important Security Rule

Extension AND content must match.

Example:

```text
shell.php
```

with:

```http
Content-Type: image/png
```

should still fail.

---

# Upload Disclosure Prevention

# Problem

Direct access to uploaded files is dangerous.

Example:

```text
/uploads/shell.php
```

may execute malicious code.

---

# Recommended Solution

Do NOT expose uploads directory directly.

---

# Use Controlled Download Script

Example:

```text
download.php
```

instead of:

```text
/uploads/file.jpg
```

---

# How It Works

Script:

1. verifies permissions
    
2. locates file securely
    
3. serves file safely
    

---

# Benefits

Users:

- cannot access uploads directly
    
- do not know upload paths
    

Attackers:

- cannot easily execute uploaded scripts
    

---

# Authorization Checks

Download script must verify:

```text
user owns or can access requested file
```

---

# Preventing IDOR

Without checks:

```text
download.php?id=5
```

may expose another user's file.

---

# Preventing LFI

Never use unsanitized user input in file paths.

---

# Dangerous Example

```php
$file = $_GET['file'];
include($file);
```

May lead to:

- Local File Inclusion (LFI)
    

---

# Safer Approach

Use:

- strict allowlists
    
- fixed directories
    
- randomized filenames
    

---

# Restrict Direct Upload Access

Direct requests to uploads directory should return:

```http
403 Forbidden
```

---

# Important HTTP Security Headers

# 1. Content-Disposition

```http
Content-Disposition: attachment
```

Forces browser to:

- download file
    
- not render inline
    

Helps prevent:

- XSS
    
- HTML execution
    

---

# 2. Content-Type

```http
Content-Type: image/png
```

Tells browser actual file type.

---

# 3. X-Content-Type-Options

```http
X-Content-Type-Options: nosniff
```

Prevents browser MIME sniffing.

Browser must obey:

```text
specified Content-Type
```

Helps prevent:

- MIME confusion attacks
    

---

# Randomized Filenames

# Why Important

Original filenames may contain:

- injections
    
- collisions
    
- sensitive info
    

---

# Recommended Approach

Store:

```text
random filename
```

on disk.

Store:

```text
sanitized original filename
```

inside database.

---

# Example

Real stored filename:

```text
8f4e2a91.png
```

Displayed to user as:

```text
cat.png
```

---

# Benefits

Prevents:

- guessing filenames
    
- filename injections
    
- collisions
    

---

# Upload Isolation

# Recommended Practice

Store uploads:

- on separate server
    
- or separate container
    

---

# Why?

If attacker gains RCE:

- only upload server compromised
    

instead of:

- main backend server
    

---

# Restrict File Access

PHP configuration:

```ini
open_basedir
```

limits filesystem access.

---

# Example

Application can only access:

```text
/var/www/uploads/
```

and nothing else.

---

# Further Security Measures

# Disable Dangerous Functions

PHP dangerous functions:

```text
exec
shell_exec
system
passthru
```

---

# Disable Using php.ini

```ini
disable_functions = exec,shell_exec,system,passthru
```

---

# Why?

Prevents:

- command execution
    
- shell spawning
    

even if attacker uploads malicious script.

---

# Disable Detailed Errors

# Problem

Server errors may reveal:

- paths
    
- filenames
    
- stack traces
    
- technologies
    

---

# Bad Example

```text
Warning:
move_uploaded_file()
failed in /var/www/html/upload.php
```

---

# Recommended Practice

Show:

```text
simple generic errors
```

instead of raw backend errors.

---

# Additional Security Recommendations

# 1. Limit File Size

Prevents:

- storage exhaustion
    
- DoS attacks
    

---

# 2. Update Libraries

Outdated libraries may contain:

- RCE
    
- XXE
    
- parser vulnerabilities
    

---

# 3. Malware Scanning

Scan uploads for:

- malware
    
- web shells
    
- malicious strings
    

---

# 4. Use WAF

Web Application Firewall provides:

- additional protection layer
    
- malicious request filtering
