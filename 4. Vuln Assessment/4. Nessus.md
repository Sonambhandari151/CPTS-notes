## 🔹 What is Vulnerability Scanning?

- **Purpose:** Identify potential vulnerabilities in:
    
    - Network devices (routers, firewalls, switches)
        
    - Servers & workstations
        
    - Applications (web, desktop, etc.)
        
- **Automated process** → fast, wide coverage.
    
- **Does not usually exploit** vulnerabilities (exceptions exist).
    
- Requires **human validation** to filter:
    
    - ✅ Real issues that need fixing
        
    - ❌ False positives to be ignored/excluded in future scans
        

---

## 🔹 Vulnerability Scanning vs Penetration Testing

- **Vulnerability Scan**
    
    - Automated
        
    - Finds potential issues (static/dynamic checks)
        
    - Quick coverage
        
    - Part of a pentest but not equal to it
        
- **Penetration Test**
    
    - Manual + automated
        
    - Goes beyond scanning (exploitation, privilege escalation, impact analysis)
        
    - Simulates real attackers
        

👉 Scanning = wide net; Pentest = deep attack.

---

## 🔹 Types of Vulnerability Tests

1. **Static Tests**
    
    - Check **asset version** vs known CVEs.
        
    - Example: If a server is running **Apache 2.x**, scanner matches it to a CVE.
        
    - ❗ Problem: May flag issues even if the patch is applied → **false positives**.
        
2. **Dynamic Tests**
    
    - Use **benign payloads** against the target:
        
        - Weak/default credentials
            
        - SQL Injection probes
            
        - Command Injection probes
            
    - If the system responds, scanner confirms vulnerability.
        
    - More accurate but still may need manual confirmation.
        

---

## 🔹 Authenticated vs Unauthenticated Scans

- **Unauthenticated Scan:**
    
    - Tests from an **outsider’s perspective**.
        
    - Finds publicly exposed weaknesses.
        
- **Authenticated Scan:**
    
    - Scanner logs in with credentials.
        
    - Gives **insider’s perspective**.
        
    - More accurate: detects missing patches, weak configs, outdated software.
        

📌 Best practice → run **both** continuously.

---

## 🔹 Why Continuous Scanning?

- New vulnerabilities are discovered all the time.
    
- New assets (servers, apps, devices) may be added without proper security.
    
- Scanning should feed into the **Patch Management Program** to keep environment secure.

## 🔹 Popular Vulnerability Scanners

### 1. **Nessus (by Tenable)**

- **Nessus Essentials** = Free version.
    
    - Limit: **16 hosts only**.
        
    - Best for learning / small environments.
        
- Features:
    
    - Identifies vulnerabilities automatically.
        
    - Includes CVSS scoring (v3.0).
        
- Example: Windows Basic Authed Scan →
    
    - **349 vulnerabilities** detected.
        
    - Critical ones: Apache Log4j, Oracle Java JRE.
        
    - Scan took 23 minutes.

    - **Tasks by Status:** e.g., 5 completed.
        
    - **CVEs by Creation Time:** trending graph.
