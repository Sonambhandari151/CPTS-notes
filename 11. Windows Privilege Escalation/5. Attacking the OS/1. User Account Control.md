# Section 16: User Account Control (UAC)

---

## Overview

> [!info] What is UAC?
> **User Account Control (UAC)** is a Windows security feature that enables a consent prompt for elevated activities. It requires users to confirm administrative actions, preventing unauthorized system changes. **Not considered a security boundary**, but adds a layer of protection and can slow attackers down.

### Key Characteristics

- Applications have different **integrity levels**
- High-level programs can potentially compromise the system
- When UAC is enabled, applications run under **non-administrator security context** by default
- Administrator explicitly authorizes elevated access when needed
- Users can log in with standard accounts and gain elevated rights when needed

---

## UAC Architecture & Configuration

### How UAC Works

1. User logs in with standard user account
2. Processes launched with standard user token have limited rights
3. Applications requiring additional permissions trigger UAC prompts
4. Administrator approval grants elevated access rights
This [page](https://docs.microsoft.com/en-us/windows/security/identity-protection/user-account-control/how-user-account-control-works) discusses how UAC works in great depth and includes the logon process, user experience, and UAC architecture.

> [!warning] Configuration Notes
> - Administrators can configure UAC locally using **secpol.msc**
> - Organizations can push UAC policies via **Group Policy Objects (GPO)** in AD environments
> - **10 Group Policy settings** can be configured for UAC
> - Source: HTB Academy

### Admin Approval Mode (AAM)

- **RID 500** administrator account always operates at **high mandatory level**
- With AAM enabled, new admin accounts operate at **medium mandatory level** by default
- Admin accounts receive **two separate access tokens** upon login:
  - One for regular operations
  - One for elevated operations

## UAC Bypass Techniques

### Overview of Bypasses

- UAC bypasses exploit flaws or unintended functionality in Windows builds
- Different techniques work on different Windows versions/builds
- [UACME](https://github.com/hfiref0x/UACME) project maintains comprehensive list of UAC bypasses with:
  - Affected Windows build numbers
  - Techniques used
  - Available security updates

### DLL Hijacking via SystemPropertiesAdvanced.exe

#### Technique Details

- **Technique Number:** 54 (UACME)
- **Affected Builds:** Windows 10 build 14393+
- **Target:** 32-bit version of `SystemPropertiesAdvanced.exe`
- **Mechanism:** Auto-elevating binary attempts to load non-existent DLL `srrstr.dll`

#### Windows DLL Search Order

Windows searches for DLLs in this order:

1. Directory from which the application loaded
2. System directory (`C:\Windows\System32` for 64-bit systems)
3. 16-bit system directory (`C:\Windows\System` - not supported on 64-bit)
4. Windows directory
5. Directories listed in PATH environment variable
