# SeDebugPrivilege

Sometimes assigned to a user (rather than adding them to Administrators) to run a specific application/service or assist troubleshooting. Assignable via local or domain GPO under `Computer Settings > Windows Settings > Security Settings`. By default only Administrators get it — this privilege can capture sensitive info directly from system memory, or access/modify kernel and application structures. Common assignment: developers debugging system components as part of daily work.

> [!warning] Should be given out sparingly
> Any account holding it has access to critical OS components.

> [!tip] OSINT angle for engagements
> When cracking a batch of NTLMv2 hashes captured via Responder/Inveigh, prioritize cracking hashes for likely high-value accounts — e.g. **developers**, identified via LinkedIn/OSINT — since they're more likely to carry `SeDebugPrivilege`. A user might not be a local admin (invisible to BloodHound-style remote enumeration) but still hold this right locally. Worth checking whenever multiple user creds + RDP access exist but no obvious elevated privileges are apparent yet.

After logging on as a user assigned the `Debug programs` right and opening an elevated shell, we see `SeDebugPrivilege` is listed.
### Confirm the Privilege

```cmd
C:\htb> whoami /priv

PRIVILEGES INFORMATION
----------------------

Privilege Name                            Description                                                        State
========================================= ================================================================== ========
SeDebugPrivilege                          Debug programs                                                     Disabled
SeChangeNotifyPrivilege                   Bypass traverse checking                                           Enabled
SeIncreaseWorkingSetPrivilege             Increase a process working set                                     Disabled
```

## Dumping LSASS with ProcDump

We can use [ProcDump](https://docs.microsoft.com/en-us/sysinternals/downloads/procdump) from the [SysInternals](https://docs.microsoft.com/en-us/sysinternals/downloads/sysinternals-suite) suite to leverage this privilege and dump process memory. a prime target: **LSASS**, which stores post-logon user credentials.

```cmd
C:\htb> procdump.exe -accepteula -ma lsass.exe lsass.dmp

ProcDump v10.0 - Sysinternals process dump utility
Copyright (C) 2009-2020 Mark Russinovich and Andrew Richards
Sysinternals - www.sysinternals.com

[15:25:45] Dump 1 writing: Estimated dump file size is 42 MB.
[15:25:45] Dump 1 complete: 43 MB written in 0.5 seconds
[15:25:46] Dump count reached.
```

## Remote Code Execution as SYSTEM

`SeDebugPrivilege` can also drive RCE directly — launch a child process, use the elevated rights to alter normal system behavior and **inherit the token of a parent process**, impersonating it. Target a process already running as SYSTEM (by PID) to escalate quickly.

> [!info] PoC reference
> Uses a PoC script (kept updated at [decoder-it/psgetsystem](https://github.com/decoder-it/psgetsystem) — check the repo for current usage since the script has been updated over time).

### Syntax

```
[MyProcess]::CreateProcessFromParent(<system_pid>,<command_to_execute>,"")
```

> [!warning] Don't forget the third argument
> The trailing blank `""` argument is required for the PoC to work correctly.

### Steps

1. Open an **elevated** PowerShell console (right-click → Run as admin, enter `jordan`'s creds)
2. List running processes/PIDs:

```powershell
PS C:\htb> tasklist

Image Name                     PID Session Name        Session#    Mem Usage
========================= ======== ================ =========== ============
System Idle Process              0 Services                   0          4 K
System                           4 Services                   0        116 K
smss.exe                       340 Services                   0      1,212 K
csrss.exe                      444 Services                   0      4,696 K
wininit.exe                    548 Services                   0      5,240 K
csrss.exe                      556 Console                    1      5,972 K
winlogon.exe                   612 Console                    1     10,408 K
```

3. Target `winlogon.exe` (PID 612 here) — a process reliably running as **SYSTEM** on Windows hosts
4. ![[Pasted image 20260815181029.png]]

Running the PoC against this PID spawns `cmd.exe` running as `NT AUTHORITY\SYSTEM`.

---

> [!tip] Faster PID targeting
> `Get-Process` can grab the PID of any well-known SYSTEM-running process (e.g. **LSASS**) directly and feed it straight to the script, skipping the manual `tasklist` scan step.

![[Pasted image 20260815181058.png]]

> [!tip] Adapting when there's no interactive session
> Without RDP/interactive access — e.g. command injection or a web shell/reverse shell as the `SeDebugPrivilege` user — modify the PoC to instead return a reverse shell as SYSTEM, or perform another action like adding an admin user. Other similar SYSTEM-popping tools exist beyond this one PoC — worth experimenting.

> [!note] Fallback if LSASS yields nothing useful
> Even without any usable plaintext/NTLM creds in the dump, obtaining just the machine account's NTLM hash can still lead to SYSTEM access via other techniques — outside this module's scope, but worth remembering as a fallback path.

## Key Takeaways

- [ ] `SeDebugPrivilege` is normally admin-only, but can be assigned individually — worth checking on users who "shouldn't" have privileged access, especially developers
- [ ] `procdump.exe -accepteula -ma lsass.exe lsass.dmp` + Mimikatz `sekurlsa::minidump` / `sekurlsa::logonpasswords` = classic credential extraction path
- [ ] Task Manager's "Create dump file" on `lsass.exe` is a tool-free alternative when file transfer/loading is restricted
- [ ] Always run `log` first in Mimikatz to capture full output to a text file
- [ ] The privilege can also drive direct RCE as SYSTEM by inheriting a SYSTEM process's token (e.g. `winlogon.exe`, LSASS) via a PoC like [psgetsystem](https://github.com/decoder-it/psgetsystem)
- [ ] Adapt PoCs for non-interactive access (reverse shell, admin user creation) when a full RDP session isn't available
