# Windows Privileges Overview

[Privileges](https://docs.microsoft.com/en-us/windows/win32/secauthz/privileges) are rights an account can be granted to perform system-level operations — managing services, loading drivers, shutting down the system, debugging applications, etc. **Different from access rights**, which govern access to securable objects specifically. Privileges live in a database and get granted via an access token at logon. An account can hold different privileges on different systems if it's part of an AD domain. Every privileged action check reviews the access token for the required privilege **and** whether it's currently enabled — most privileges are **disabled by default**, some enabled via an admin cmd/PowerShell console, others manually.

> [!important] Why this matters offensively
> Logging in as a user with a specific privilege set can mean directly escalating privileges, or leveraging that account's assigned privileges to further access toward the ultimate goal.

---

## Windows Authorization Process

**Security principals** — anything the OS can authenticate: user/computer accounts, processes running in a user/computer's security context, or security groups. Every principal has a unique [Security Identifier (SID)](https://docs.microsoft.com/en-us/troubleshoot/windows-server/identity/security-identifiers-in-windows), assigned for life at creation.

**The access check flow** (e.g. a user opening a folder on a file share):
1. The user's **access token** (user SID, group SIDs, privilege list, other access info) gets compared against the object's [Access Control Entries (ACEs)](https://docs.microsoft.com/en-us/windows/win32/secauthz/access-control-entries)
2. ACEs live in the object's [security descriptor](https://docs.microsoft.com/en-us/windows/win32/secauthz/security-descriptors) (contains access rights info for that object)
3. System evaluates and grants/denies access — near-instant, happens on every resource access attempt

## Rights and Privileges in Windows — Key Groups

| Group                           | Description                                                                                                                                                                                                                                                                                       |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Default Administrators**      | Domain Admins and Enterprise Admins — "super" groups                                                                                                                                                                                                                                              |
| **Server Operators**            | Can modify services, access SMB shares, back up files                                                                                                                                                                                                                                             |
| **Backup Operators**            | Members are allowed to log onto DCs locally and should be considered Domain Admins. They can make shadow copies of the SAM/NTDS database, read the registry remotely, and access the file system on the DC via SMB. This group is sometimes added to the local Backup Operators group on non-DCs. |
| **Print Operators**             | Can log on to DCs locally and trick Windows into loading a malicious driver                                                                                                                                                                                                                       |
| **Hyper-V Administrators**      | If any DCs are virtualized, virtualization admins here should be treated as **Domain Admins**                                                                                                                                                                                                     |
| **Account Operators**           | Can modify non-protected accounts and groups in the domain                                                                                                                                                                                                                                        |
| **Remote Desktop Users**        | No inherent useful permissions by default, but often granted `Allow Login Through Remote Desktop Services` — lateral movement via RDP                                                                                                                                                             |
| **Remote Management Users**     | Can log on to DCs via PSRemoting (sometimes added to the local remote management group on non-DCs)                                                                                                                                                                                                |
| **Group Policy Creator Owners** | Can create new GPOs — needs additional delegation to actually link them to a domain/OU                                                                                                                                                                                                            |
| **Schema Admins**               | Can modify the AD schema structure — can backdoor any *future* Group/GPO by adding a compromised account into the default object ACL                                                                                                                                                              |
| **DNS Admins**                  | Can load a DLL on a DC (persistence — service often crashes when loaded, so wait for reboot), but can't restart DNS themselves. More reliable exploit: [create a WPAD record](https://web.archive.org/web/20231115070425/https://cube0x0.github.io/Pocing-Beyond-DA/)                             |

## Checking Your Own Privileges

`whoami /priv` lists all rights assigned to the current user. Some rights only surface/work from an **elevated** session — a core [User Account Control (UAC)](https://docs.microsoft.com/en-us/windows/security/identity-protection/user-account-control/how-user-account-control-works) behavior since Windows Vista, restricting apps from running full-permission unless explicitly elevated.

### Local Admin — Elevated Console

```powershell
PS C:\htb> whoami

winlpe-srv01\administrator

PS C:\htb> whoami /priv

PRIVILEGES INFORMATION
----------------------

Privilege Name                            Description                                                        State
========================================= ================================================================== ========
SeIncreaseQuotaPrivilege                  Adjust memory quotas for a process                                 Disabled
SeSecurityPrivilege                       Manage auditing and security log                                   Disabled
SeTakeOwnershipPrivilege                  Take ownership of files or other objects                           Disabled
SeLoadDriverPrivilege                     Load and unload device drivers                                     Disabled
SeSystemProfilePrivilege                  Profile system performance                                         Disabled
SeSystemtimePrivilege                     Change the system time                                             Disabled
SeProfileSingleProcessPrivilege           Profile single process                                             Disabled
SeIncreaseBasePriorityPrivilege           Increase scheduling priority                                       Disabled
SeCreatePagefilePrivilege                 Create a pagefile                                                  Disabled
SeBackupPrivilege                         Back up files and directories                                      Disabled
SeRestorePrivilege                        Restore files and directories                                      Disabled
SeShutdownPrivilege                       Shut down the system                                               Disabled
SeDebugPrivilege                          Debug programs                                                     Disabled
SeSystemEnvironmentPrivilege              Modify firmware environment values                                 Disabled
SeChangeNotifyPrivilege                   Bypass traverse checking                                           Enabled
SeRemoteShutdownPrivilege                 Force shutdown from a remote system                                Disabled
SeUndockPrivilege                         Remove computer from docking station                               Disabled
SeManageVolumePrivilege                   Perform volume maintenance tasks                                   Disabled
SeImpersonatePrivilege                    Impersonate a client after authentication                          Enabled
SeCreateGlobalPrivilege                   Create global objects                                              Enabled
SeIncreaseWorkingSetPrivilege             Increase a process working set                                     Disabled
SeTimeZonePrivilege                       Change the time zone                                               Disabled
SeCreateSymbolicLinkPrivilege             Create symbolic links                                              Disabled
SeDelegateSessionUserImpersonatePrivilege Obtain an impersonation token for another user in the same session Disabled
```

> [!important] "Disabled" ≠ "not assigned"
> A privilege listed as `Disabled` means the account **has** it assigned but it's not currently usable in the access token until enabled. Windows has **no built-in command/cmdlet** to enable privileges directly — scripting is required. Two useful references: [Enable-Privilege.ps1](https://www.powershellgallery.com/packages/PoshPrivilege/0.3.0.0/Content/Scripts%5CEnable-Privilege.ps1) and [Lee Holmes' token privilege adjustment post](https://www.leeholmes.com/adjusting-token-privileges-in-powershell/).

### Standard User

```powershell
PS C:\htb> whoami

winlpe-srv01\htb-student

PS C:\htb> whoami /priv

PRIVILEGES INFORMATION
----------------------

Privilege Name                Description                    State
============================= ============================== ========
SeChangeNotifyPrivilege       Bypass traverse checking       Enabled
SeIncreaseWorkingSetPrivilege Increase a process working set Disabled
```

Drastically fewer rights than the elevated admin example above.

### Backup Operators Group Member

```powershell
PS C:\htb> whoami /priv

PRIVILEGES INFORMATION
----------------------

Privilege Name                Description                    State
============================= ============================== ========
SeShutdownPrivilege           Shut down the system           Disabled
SeChangeNotifyPrivilege       Bypass traverse checking       Enabled
SeIncreaseWorkingSetPrivilege Increase a process working set Disabled
```

> [!warning] Even "minor" rights carry real risk
> Members here also hold rights UAC currently restricts. Notably, they carry [`SeShutdownPrivilege`](https://docs.microsoft.com/en-us/windows/security/threat-protection/security-policy-settings/shut-down-the-system) — if logged onto a Domain Controller **locally** (not via RDP/WinRM), this account could shut it down, causing a major service interruption.

## Detection

Recommended reading: [Palantir's Windows Privilege Abuse post](https://blog.palantir.com/windows-privilege-abuse-auditing-detection-and-defense-3078a403d74e) — covers detecting/preventing abuse via **Event ID [4672](https://docs.microsoft.com/en-us/windows/security/threat-protection/auditing/event-4672)** (Special privileges assigned to new logon), fired when sensitive privileges get assigned to a new logon session. Can be fine-tuned by monitoring for privileges that should **never** be assigned, or that should only ever appear on specific known accounts.

## Key Takeaways

- [ ] Privileges (system operations) are distinct from access rights (object access) — both flow through the same access token
- [ ] Security principals always carry a unique SID; access checks compare the token against an object's ACEs/security descriptor
- [ ] Backup Operators, Print Operators, DNS Admins, Hyper-V Administrators — all effectively "Domain Admin adjacent" via indirect abuse paths
- [ ] `whoami /priv` shows assigned privileges and their enabled/disabled state — "Disabled" still means assigned, just not currently active
- [ ] No built-in Windows tool enables a privilege directly — requires scripting (PoshPrivilege, custom PowerShell)
- [ ] Event ID 4672 is the key detection signal for sensitive privilege assignment on new logons
