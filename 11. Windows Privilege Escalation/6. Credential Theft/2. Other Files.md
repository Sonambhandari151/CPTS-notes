# Section 22: Other Files

---


### Common Valuable File Types to Hunt

| Extension         | What It Could Contain                                |
| ----------------- | ---------------------------------------------------- |
| `.kdbx`           | KeePass password database                            |
| `.vmdk` / `.vhdx` | Virtual hard drives (extractable local admin hashes) |
| `.ppk`            | PuTTY private SSH keys → access to other systems     |
| `.rdp`            | Saved RDP connection files (may store credentials)   |
| `.vnc`            | VNC config files with saved passwords                |
| `.config`         | App config files with plaintext credentials          |
| `.cred`           | Saved credential files                               |
| `.xlsx` / `.docx` | Excel/Word docs with embedded passwords              |
| `.txt`            | Classic `passwords.txt` files                        |
| `.xml`            | PowerShell credential exports, app configs           |
| `.ini`            | App initialization files with credentials            |

> [!tip] Real-World Context
> Many companies give each employee a personal folder on a file share (e.g., `\\FILE01\users\bjones`). These are often accessible to **all Domain Users** with read access. Users routinely save sensitive personal data in these folders, unaware they are readable by everyone on the network — not just local to their workstation.
>
> Tools like **Snaffler** can crawl network share drives automatically for these interesting file extensions.

## Manually Searching the File System
 [cheatsheet](https://swisskyrepo.github.io/InternalAllTheThings/redteam/escalation/windows-privilege-escalation/)
### findstr — Searching File Contents

Three useful variations for finding passwords in file contents:

#### Example 1 — Search and Return Filenames Only (`/M`)

```cmd
C:\htb> cd c:\Users\htb-student\Documents & findstr /SI /M "password" *.xml *.ini *.txt

stuff.txt
```

> Flags: `/S` = Subdirectories, `/I` = Case-insensitive, `/M` = Print filename only (no matching line)

#### Example 2 — Search and Return Filename + Matching Line

```cmd
C:\htb> findstr /si password *.xml *.ini *.txt *.config

stuff.txt:password: l#-x9r11_2_GL!
```

> Flags: `/s` = Subdirectories, `/i` = Case-insensitive (lowercase flags work the same)

#### Example 3 — Search All Files, All Extensions (`*.*`)

```cmd
C:\htb> findstr /spin "password" *.*

stuff.txt:1:password: l#-x9r11_2_GL!
```

> Flags: `/s` = Subdirectories, `/p` = Skip files with non-printable characters, `/i` = Case-insensitive, `/n` = Print line numbers

---

### PowerShell — Searching File Contents

```powershell
PS C:\htb> select-string -Path C:\Users\htb-student\Documents\*.txt -Pattern password

stuff.txt:1:password: l#-x9r11_2_GL!
```

> [!note] `select-string` is PowerShell's equivalent of Linux `grep`
> Output format: `filename:linenumber:matching line`

---

### Searching by File Extension / Name Pattern

#### Example 1 — Search for Files by Name Pattern (`dir`)

```cmd
C:\htb> dir /S /B *pass*.txt == *pass*.xml == *pass*.ini == *cred* == *vnc* == *.config*

c:\inetpub\wwwroot\web.config
```

> Flags: `/S` = Recurse subdirectories, `/B` = Bare format (paths only)

#### Example 2 — Search for Files by Extension (`where`)

```cmd
C:\htb> where /R C:\ *.config

c:\inetpub\wwwroot\web.config
```

> `/R C:\` = Recursively search from `C:\`

#### PowerShell — Search for Specific File Extensions

```powershell
PS C:\htb> Get-ChildItem C:\ -Recurse -Include *.rdp, *.config, *.vnc, *.cred -ErrorAction Ignore


    Directory: C:\inetpub\wwwroot


Mode                 LastWriteTime         Length Name
----                 -------------         ------ ----
-a----         5/25/2021   9:59 AM            329 web.config

<SNIP>
```

> [!tip] Combine Techniques
> Use findstr to find files first, then `cat` / `gc` / `type` to read their contents.
> Use `Get-ChildItem` to discover files by extension and feed results into `Select-String` to filter content.

## Sticky Notes

### Overview

> [!danger] Common Misconception
> People often use the **StickyNotes** app on Windows workstations to save passwords and other sensitive information, not realizing it stores everything in a **SQLite database file** — not encrypted, not protected, sitting in a known location.

### Database File Location

```
C:\Users\<user>\AppData\Local\Packages\Microsoft.MicrosoftStickyNotes_8wekyb3d8bbwe\LocalState\plum.sqlite
```

### What Each File May Contain

| File / Path                               | Why It's Interesting                                                      |
| ----------------------------------------- | ------------------------------------------------------------------------- |
| `%SYSTEMDRIVE%\pagefile.sys`              | Memory pages swapped to disk — may contain cleartext credentials from RAM |
| `%WINDIR%\debug\NetSetup.log`             | Domain join credentials, machine account info                             |
| `%WINDIR%\repair\sam`                     | Backup copy of SAM database (local account hashes)                        |
| `%WINDIR%\repair\system`                  | Registry hive backup                                                      |
| `%WINDIR%\repair\software`                | Registry hive backup — may contain cached credentials                     |
| `%WINDIR%\repair\security`                | Security registry hive backup                                             |
| `%WINDIR%\iis6.log`                       | IIS access logs — may reveal credentials in URLs or POST data             |
| `%WINDIR%\system32\config\AppEvent.Evt`   | Application event log                                                     |
| `%WINDIR%\system32\config\SecEvent.Evt`   | Security event log — logon events, privilege use                          |
| `%WINDIR%\system32\config\*.sav`          | Registry hive backups — older credential stores                           |
| `%WINDIR%\system32\CCM\logs\*.log`        | SCCM/Configuration Manager logs — may reveal credentials                  |
| `%USERPROFILE%\ntuser.dat`                | User registry hive — recent files, stored credentials                     |
| `%USERPROFILE%\...\Content.IE5\index.dat` | IE browsing history, cached form data                                     |
| `%WINDIR%\System32\drivers\etc\hosts`     | Custom DNS entries → internal infrastructure mapping                      |
| `C:\ProgramData\Configs\*`                | Application configs — third-party software often stores credentials here  |
| `C:\Program Files\Windows PowerShell\*`   | PowerShell profiles and scripts that may contain hardcoded credentials    |

## Credential Hunting Quick Reference

### findstr Cheatsheet

```cmd
# Search file contents — filenames only
findstr /SIM /C:"password" *.xml *.ini *.txt *.config

# Search file contents — show matching lines
findstr /si password *.xml *.ini *.txt *.config

# Search all files — show filename, line number, and match
findstr /spin "password" *.*

# Search for specific string in all files
findstr /si "connectionString" *.config
findstr /si "pwd=" *.xml
findstr /si "pass=" *.ini
```

### PowerShell Cheatsheet

```powershell
# Search file contents
Select-String -Path C:\Users\*\Documents\*.txt -Pattern "password"

# Search recursively across all text files
Get-ChildItem C:\ -Recurse -Include *.txt,*.xml,*.ini,*.config -ErrorAction Ignore |
    Select-String -Pattern "password" | Select-Object Path, LineNumber, Line

# Find files by extension
Get-ChildItem C:\ -Recurse -Include *.rdp,*.config,*.vnc,*.cred -ErrorAction Ignore

# Find files by name pattern
Get-ChildItem C:\ -Recurse -Filter "*pass*" -ErrorAction Ignore
Get-ChildItem C:\ -Recurse -Filter "*cred*" -ErrorAction Ignore
Get-ChildItem C:\ -Recurse -Filter "*kdbx*" -ErrorAction Ignore
```

### dir / where Cheatsheet

```cmd
# Find files matching multiple name patterns
dir /S /B *pass*.txt == *pass*.xml == *pass*.ini == *cred* == *vnc* == *.config*

# Find all files with a specific extension recursively
where /R C:\ *.config
where /R C:\ *.kdbx
where /R C:\ *.ppk
```
