# Introduction to Windows Privilege Escalation

After gaining a foothold, elevating privileges opens up more persistence options and often reveals locally-stored info that furthers access. The general goal: escalate to a member of **Local Administrators** or the [`NT AUTHORITY\SYSTEM`](https://docs.microsoft.com/en-us/windows/win32/services/localsystem-account) (LocalSystem) account. Sometimes just escalating to a **different user** on the system is enough. Privilege escalation is often the vital step that unlocks access or data (e.g. credentials) only reachable from an elevated session — and for some engagements ("gold image" or "workstation breakout" assessments), it's the entire goal.

## Why We Escalate Privileges

| #   | Reason                                                                                                                                                                               |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | Testing a client's [gold image](https://www.redhat.com/en/topics/linux/what-is-a-golden-image) Windows workstation/server build for flaws                                            |
| 2   | Escalating locally to access a local resource (e.g. a database)                                                                                                                      |
| 3   | Gaining [NT AUTHORITY\System](https://docs.microsoft.com/en-us/windows/win32/services/localsystem-account) on a domain-joined machine as a foothold into the client's AD environment |
| 4   | Obtaining credentials to move laterally or escalate elsewhere in the network                                                                                                         |

> [!warning] Don't rely solely on tools
> Many tools exist to assist here, but understanding **manual** privilege escalation checks matters — sometimes a client places you on a managed workstation with no internet, heavily firewalled, USB ports disabled, and no way to load tools/scripts. A firm grasp of manual checks using both PowerShell and cmd is essential in that scenario.

### The Attack Surface

- Abusing Windows **group** privileges
- Abusing Windows **user** privileges
- Bypassing **User Account Control**
- Abusing **weak service/file permissions**
- Leveraging **unpatched kernel exploits**
- **Credential theft**
- **Traffic capture**
- ...and more

## Real-World Scenarios

### Scenario 1 — Overcoming Network Restrictions

Client-provided system, no internet, USB ports blocked, network access control preventing a direct attack machine connection. A network flaw was found: the printer VLAN allowed outbound traffic on ports 80/443/445. Manual enumeration surfaced a permissions flaw enabling privilege escalation and a manual **LSASS** memory dump. The dump was exfiltrated over an SMB share mounted on the attack machine via the printer VLAN. Offline **Mimikatz** analysis of the dump recovered a Domain Admin's NTLM hash, cracked offline, and used to access a domain controller from the client-provided system.

### Scenario 2 — Pillaging Open Shares

Well-monitored, locked-down environment with no obvious vulnerabilities. A wide-open file share was found hosting VM backups — specifically `.VMDK` and `.VHDX` virtual hard drive files. Mounted a `.VHDX` as a local drive from a Windows VM, browsed the filesystem, and pulled the **SYSTEM**, **SAM**, and **SECURITY** registry hives. Moved them to a Linux attack box and extracted the local administrator hash with [secretsdump.py](https://github.com/SecureAuthCorp/impacket/blob/master/examples/secretsdump.py). The org used a gold image, so this hash enabled admin access to nearly every Windows system via pass-the-hash.

### Scenario 3 — Hunting Credentials and Abusing Account Privileges

Locked-down network, goal was accessing critical database servers. Client provided a laptop with a standard domain account and tool-loading capability. [Snaffler](https://github.com/SnaffCon/Snaffler) hunted file shares for sensitive info and found `.sql` files containing low-privileged database credentials. Used a local MSSQL client to connect, enabled the [xp_cmdshell](https://docs.microsoft.com/en-us/sql/relational-databases/system-stored-procedures/xp-cmdshell-transact-sql?view=sql-server-ver15) stored procedure for local command execution as the service account. Confirmed [SeImpersonatePrivilege](https://docs.microsoft.com/en-us/troubleshoot/windows-server/windows-security/seimpersonateprivilege-secreateglobalprivilege) was held, leveraged a custom-compiled [Juicy Potato](https://github.com/ohpe/juicy-potato) to add a local admin user (reverse shell attempts had failed, so a local admin add was the fallback). Used that access to remote in and gain full control of a client database.

## Why Does Privilege Escalation Happen?

No single cause — but personnel and budget constraints are common underlying factors. Many orgs lack the staff to keep up with patching, vulnerability management, periodic self-assessments, continuous monitoring, and larger resource-intensive initiatives like workstation/server upgrades or file share audits (locking down directories, removing sensitive scripts/config files with embedded credentials).

---

## Moving On

Real engagements rarely involve attacking a single host — creative, on-the-fly privilege escalation thinking is a core skill, not just a checklist exercise.

## Key Takeaways

- [ ] Goal: Local Administrators or NT AUTHORITY\SYSTEM — sometimes just a different user is the actual win
- [ ] Manual enumeration skills (PowerShell + cmd) matter for locked-down environments with no tool access
- [ ] Real scenarios rarely involve a single obvious flaw — creative chaining (network quirks, open shares, credential hunting) is often required
- [ ] Root causes are usually organizational: understaffing, budget, lack of patching/monitoring/audit cadence
- [ ] `C:\Tools` on lab targets has most needed utilities pre-staged; still worth practicing manual upload/compilation
