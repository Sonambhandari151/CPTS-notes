# Communication with Processes

One of the best places to look for privilege escalation is the processes running on the system. Even a non-admin process can lead to additional privileges.

> [!info] The classic example
> Discover a web server (IIS, XAMPP) running on the box → drop an `.aspx`/`.php` shell → land a shell as the user running the web server. Usually not an admin, but often holds the `SeImpersonate` token — which enables Rogue/Juicy/Lonely Potato-style attacks to reach SYSTEM.

---

## Access Tokens

> [!info] What's an access token?
> [Access tokens](https://docs.microsoft.com/en-us/windows/win32/secauthz/access-tokens) describe the security context (attributes/rules) of a process or thread — the user account's identity and privileges tied to that process/thread. When a user authenticates, their password is checked against a security database; on success they're issued an access token. Every time a user interacts with a process, a copy of this token is presented to determine their privilege level.

## Enumerating Network Services

> [!info] Most common interaction method
> Processes are most commonly reached through a network socket (DNS, HTTP, SMB, etc.). [`netstat`](https://docs.microsoft.com/en-us/windows-server/administration/windows-commands/netstat) shows active TCP/UDP connections — what's listening where, locally and externally. A vulnerable service bound only to localhost can still be an escalation path once you're already logged onto the host.

> [!important] What to look for
> Entries listening **only on loopback** (`127.0.0.1` / `::1`) rather than the host IP or a broadcast address (`0.0.0.0`, `::/0`). Localhost-only sockets are frequently left insecure under the assumption that "they aren't accessible to the network."
>
> Port **14147** here is FileZilla's administrative interface — connecting to it may allow extracting FTP passwords or creating an FTP share at `c:\` as the FileZilla Server user (potentially Administrator).

### More Examples

> [!warning] Splunk Universal Forwarder
> Installed on endpoints to ship logs to Splunk. Its default configuration had **no authentication**, letting anyone deploy applications → code execution. Default run context: **SYSTEM**, not a low-priv user. More info: [Splunk Universal Forwarder Hijacking](https://airman604.medium.com/splunk-universal-forwarder-hijacking-5899c3e0e6b2), [SplunkWhisperer2](https://clement.notin.org/blog/2019/02/25/Splunk-Universal-Forwarder-Hijacking-2-SplunkWhisperer2/).

> [!warning] Erlang Port (25672)
> Erlang (a distributed-computing language) exposes a port allowing other Erlang nodes to join a cluster, gated by a shared secret called a **cookie**. Many apps either use a weak default cookie (RabbitMQ defaults to `rabbit`) or store it in a poorly-protected config file. Example Erlang-based apps: SolarWinds, RabbitMQ, CouchDB. More info: [Erlang-arce blogpost (Mubix)](https://malicious.link/post/2018/erlang-arce/).

## Named Pipes

> [!info] What are named pipes?
> Files stored in memory, cleared after being read — used for inter-process communication via shared memory. Cobalt Strike uses named pipes for nearly every command (except [BOF](https://www.cobaltstrike.com/help-beacon-object-files)):
> 1. Beacon starts a named pipe, e.g. `\.\pipe\msagent_12`
> 2. Beacon starts a new process, injects the command into it, directs output to that pipe
> 3. The C2 server reads the pipe for output
>
> This isolates command execution failures/AV flags from the beacon process itself. Operators often rename pipes to masquerade as legitimate software (`mojo` instead of `msagent` is a common Chrome-themed disguise) — a mismatch (e.g. a `mojo`-named pipe on a host with no Chrome installed) can be a strong detection signal, occasionally even revealing an internal red team's activity to an external assessor.

### More on Named Pipes

[Named pipes](https://docs.microsoft.com/en-us/windows/win32/ipc/named-pipes) vs. anonymous pipes — Windows uses a client-server model: the process that **creates** the pipe is the server, the process communicating with it is the client. Example: `\\.\PipeName\\ExampleNamedPipeServer`.

- **Half-duplex** — one-way channel, client can only write to the server
- **Duplex** — two-way channel, client writes and server responds over the same pipe

Every active connection to a named pipe server creates a **new** named pipe instance — same name, separate data buffer.

> [!success] Expected/secure result
> Only `BUILTIN\Administrators` gets `FILE_ALL_ACCESS` on the LSASS pipe — as it should be. This is the baseline to compare misconfigured pipes against.

Enumerate **all** named pipe DACLs at once with:
```cmd
C:\htb> .\accesschk.exe /accepteula \pipe\
```

## Named Pipes Attack Example — WindscribeService

> [!warning] Real-world case: WindscribeService Named Pipe Privilege Escalation
> Reference: [Exploit-DB #48021](https://www.exploit-db.com/exploits/48021)

**Search for all writable named pipes:**
```cmd
accesschk.exe -w \pipe\* -v
```
This surfaces `WindscribeService` as a pipe allowing `READ`/`WRITE` to the `Everyone` group — i.e., any authenticated user.

**Confirm with accesschk:**
```cmd
C:\htb> accesschk.exe -accepteula -w \pipe\WindscribeService -v

Accesschk v6.13 - Reports effective permissions for securable objects
Copyright (c) 2006-2020 Mark Russinovich
Sysinternals - www.sysinternals.com

\\.\Pipe\WindscribeService
  Medium Mandatory Level (Default) [No-Write-Up]
  RW Everyone
        FILE_ALL_ACCESS
```

> [!danger] The finding
> `Everyone` has `FILE_ALL_ACCESS` — full control — over this pipe. Since the service on the other end of the pipe runs with elevated privileges, this lax permission set can be leveraged to escalate to **SYSTEM**.

## Key Takeaways

- [ ] Access tokens carry a process/thread's security context — every process interaction presents a copy of this token
- [ ] `netstat -ano` reveals listening services — prioritize ports bound to `127.0.0.1`/`::1` only, since localhost-only services are often left insecure
- [ ] Known real-world examples: FileZilla admin interface (port 14147), unauthenticated Splunk Universal Forwarder (runs as SYSTEM), weak/exposed Erlang cookies (port 25672, RabbitMQ/CouchDB/SolarWinds)
- [ ] Named pipes are in-memory, cleared-after-read IPC objects; creator = server, connector = client; half-duplex (one-way) or duplex (two-way)
- [ ] Enumerate pipes with `pipelist.exe /accepteula` or PowerShell's `gci \\.\pipe\`
- [ ] Check pipe permissions (DACLs) with `accesschk.exe /accepteula \\.\Pipe\<name> -v`, or all at once with `accesschk.exe /accepteula \pipe\`
- [ ] Search specifically for writable pipes with `accesschk.exe -w \pipe\* -v` — a pipe granting `Everyone`/`FILE_ALL_ACCESS` tied to a privileged service is a direct SYSTEM escalation path (e.g. WindscribeService, EDB-48021)
