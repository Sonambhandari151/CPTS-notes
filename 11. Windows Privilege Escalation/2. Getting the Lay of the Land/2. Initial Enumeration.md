# Initial Enumeration

Landing a low-privileged shell on a Windows host (domain-joined or not) — full compromise could yield sensitive files/shares, traffic capture capability, or credentials furthering access (possibly all the way to Domain Admin in AD). Escalation targets, depending on config/data found:

- `NT AUTHORITY\SYSTEM` / [LocalSystem](https://docs.microsoft.com/en-us/windows/win32/services/localsystem-account) — more privileged than local admin, runs most Windows services
- The built-in local **administrator** account — often not disabled, and frequently reused across systems
- Another local **Administrators** group member — same privilege level as built-in administrator
- A **standard domain user** who happens to be in the local Administrators group
- A **Domain Admin** who happens to be in the local Administrators group

> [!important] Enumeration is the key
> Situational awareness after initial access — OS version, patch level, installed software, current privileges, group memberships, etc. — drives everything that follows. Manual technique matters especially when tools can't be loaded (network restrictions, no internet, active protections).

Handy reference: [Windows commands reference](https://docs.microsoft.com/en-us/windows-server/administration/windows-commands/windows-commands).

---

## Key Data Points

| Point                                                                             | Why it matters                                                                                                                                                                                         |
| --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **OS name**                                                                       | Workstation vs. server, version level (Win 7/10, Server 2008/2012/2016/2019) — indicates available tooling (e.g. PowerShell version) and public exploit availability                                   |
| [Version](https://en.wikipedia.org/wiki/Comparison_of_Microsoft_Windows_versions) | Public exploits often target specific version vulnerabilities. **Windows exploits can cause instability or crashes** — be careful on production systems, fully understand an exploit before running it |
| **Running Services**                                                              | Especially those running as SYSTEM/admin — a misconfigured or vulnerable privileged service can be an easy privesc win                                                                                 |

> [!important] PATH is easy to overlook
> Windows looks for a program in the **CWD first**, then `PATH` left-to-right. Admins/applications sometimes prepend custom entries (e.g. Python, Java) to allow executing `.py`/`.jar` files directly. If a **writable** folder ends up placed **before** `C:\Windows\System32` in the PATH, that's a real DLL-injection/hijack opportunity — far more dangerous than a writable folder placed after it.

> [!tip] HOMEDRIVE often points to a file share
> Worth navigating to directly — may expose other accessible directories (e.g. an "IT Directory" with a password spreadsheet). Shares also back [Roaming Profiles](https://docs.microsoft.com/en-us/windows-server/storage/folder-redirection/folder-redirection-rup-overview) — meaning a file dropped in `USERPROFILE\AppData\Microsoft\Windows\Start Menu\Programs\Startup` will follow the user (and execute) on whatever machine they next log into.

## User & Group Information

> [!important] Users are often the weakest link
> Even a well-patched system can fall to a browsable admin user directory containing something like `logins.xlsx`.

### Logged-In Users


> [!tip] Consider the human element
> Active vs. idle sessions matter. On evasive engagements, tread lightly around actively-used hosts to avoid detection — direct user targeting is possible but riskier/harder to pull off cleanly.

## Key Takeaways

- [ ] `tasklist /svc` — spot non-standard processes/services fast by knowing the standard ones cold
- [ ] `set` — check `PATH` for writable directories placed before `System32` (DLL hijack risk), and `HOMEDRIVE` for accessible file shares
- [ ] `systeminfo` / `wmic qfe` / `Get-HotFix` — three ways to check patch level; boot time is a useful proxy signal
- [ ] `wmic product get name` / `Get-WmiObject -Class Win32_Product` — installed software, correlate with LaZagne for stored app credentials
- [ ] `netstat -ano` — locally-bound-only services are still exploitable once you're on the host
- [ ] `query user` / `echo %USERNAME%` / `whoami /priv` / `whoami /groups` — check current session context and privileges immediately after landing access
- [ ] `net user` / `net localgroup` / `net localgroup administrators` / `net accounts` — full user/group/policy picture, watch for naming patterns suggesting credential reuse
