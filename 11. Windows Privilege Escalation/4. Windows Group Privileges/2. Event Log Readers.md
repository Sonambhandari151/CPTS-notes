# Event Log Readers

## Background

If  [auditing of process creation](https://docs.microsoft.com/en-us/windows/security/threat-protection/auditing/audit-process-creation) (Event ID  [4688: A new process has been created](https://docs.microsoft.com/en-us/windows/security/threat-protection/auditing/event-4688).) and **command line logging** are enabled, every command run on the box — including any passwords passed as CLI arguments — gets written to the **Security** event log.

> [!tip] Why This Matters
> Defenders use this to catch attacker recon/lateral movement (`whoami`, `tasklist`, `netstat`, `net view`, `wmic`, etc. — see [Red Canary's Threat Detection Report](https://redcanary.com/threat-detection-report/) for common attacker commands). But the same logging that helps blue teams can leak plaintext creds to anyone who can read the log — including low-priv users who type passwords into commands like `net use`.

> [!warning] Real-World Note
> Command-line auditing + a competent SOC *will* catch noisy commands like `tasklist` run from an unusual context (e.g., after a Responder capture + offline crack). Don't assume "living off the land" commands are invisible.

## Event Log Readers Group

Members of this **built-in local group** can read the event logs (Security, System, Application, etc.) on a machine **without needing full local admin**. Admins sometimes add power users/developers to this group so they can troubleshoot without elevated rights — which becomes a privesc/info-disclosure vector if the logs contain credentials.

### Confirm Group Membership

```shellsession
C:\htb> net localgroup "Event Log Readers"

Alias name     Event Log Readers
Comment        Members of this group can read event logs from local machine

Members
-------------------------------------------------------------------------------
logger
The command completed successfully.
```

## Hunting for Credentials in Logs

Microsoft maintains a [reference list of built-in Windows commands](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/windows-commands). Many of these accept passwords as plaintext parameters (`/user:`, `/p:`, etc.) — if those get logged via 4688, they're recoverable.

### Method 1 — `wevtutil`
 [wevtutil](https://docs.microsoft.com/en-us/windows-server/administration/windows-commands/wevtutil)
Query the Security log as text and filter for `/user`:

```powershell
PS C:\htb> wevtutil qe Security /rd:true /f:text | Select-String "/user"

        Process Command Line:   net use T: \\fs01\backups /user:tim MyStr0ngP@ssword
```

**Flag breakdown:**

| Flag | Meaning |
|------|---------|
| `qe` | Query events |
| `Security` | Target log name |
| `/rd:true` | Read direction — most recent first |
| `/f:text` | Output format as plain text |

Pass alternate creds remotely with `/u` and `/p`:

```cmd
C:\htb> wevtutil qe Security /rd:true /f:text /r:share01 /u:julie.clay /p:Welcome1 | findstr "/user"
```

### Method 2 — `Get-WinEvent`

Filter specifically for Event ID `4688` where the command-line property contains `/user`:

```powershell
PS C:\htb> Get-WinEvent -LogName security | where { $_.ID -eq 4688 -and $_.Properties[8].Value -like '*/user*'} | Select-Object @{name='CommandLine';expression={ $_.Properties[8].Value }}

CommandLine
-----------
net use T: \\fs01\backups /user:tim MyStr0ngP@ssword
```

> [!danger] Permissions Gotcha
> `Get-WinEvent` against the **Security** log requires **local admin**, OR permissions manually adjusted on:
> `HKLM\System\CurrentControlSet\Services\Eventlog\Security`
> Being in **Event Log Readers alone is NOT sufficient** for `Get-WinEvent` — but `wevtutil` works fine for that group.

`Get-WinEvent` also supports the `-Credential` parameter to run as another user.

### Other Logs Worth Checking

| Log                                                                                                                                                     | Notes                                                                                                                      |
| ------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| **Security**                                                                                                                                            | Process creation (4688) + command lines if auditing enabled                                                                |
|  [PowerShell Operational](https://docs.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_logging_windows?view=powershell-7.1) | Script block / module logging — can contain full script contents & creds. **Accessible to unprivileged users** by default. |

## Comparison: wevtutil vs Get-WinEvent

| Tool | Min. Privilege Needed | Remote Support | Notes |
|------|-----------------------|-----------------|-------|
| `wevtutil` | Event Log Readers membership | Yes (`/r`, `/u`, `/p`) | Text output easy to grep |
| `Get-WinEvent` | Local Admin (or registry ACL tweak) | Yes (`-ComputerName`, `-Credential`) | Richer object filtering via `Properties[]` |
