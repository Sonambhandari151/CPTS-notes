# Windows Hardening

> [!info] Purpose
> Proper hardening can eliminate most, if not all, opportunities for local privilege escalation. The following steps should be taken, at a minimum, to reduce the risk of an attacker gaining system-level access.

## Secure Clean OS Installation

Developing a custom image for the environment saves significant troubleshooting time later. Use a clean ISO of the required OS version, a Windows Deployment Server (WDS) or equivalent application for pushing images, and System Center Configuration Manager (SCCM) if applicable. Windows OS copies can be obtained [here](https://www.microsoft.com/) or via the Microsoft Media Creation Tool.

The image should, at minimum, include:
- Any applications required for employees' daily duties
- Configuration changes needed to ensure functionality and security of the host in the environment
- Current major and minor updates already tested for the environment and deemed safe for deployment

> [!tip] Benefit
> This clears out bloatware/unwanted preinstalled software, ensures all enterprise hosts start with the same base configuration, and makes troubleshooting, changes, and updates much easier.

## Updates and Patching

[Microsoft's Update Orchestrator](https://docs.microsoft.com/en-us/windows/deployment/update/how-windows-update-works) runs updates in the background per configured settings — downloading and installing the most recent updates automatically. Some updates require a restart to take effect, so restart hosts regularly. In an enterprise environment, set up a **WSUS** server so hosts don't each reach out individually — they instead pull updates from the WSUS server.

### Update Process
![[Pasted image 20261002004657.png]]
1. Windows Update Orchestrator checks in with Microsoft Update servers or the WSUS server for new updates.
2. This happens at random intervals so hosts don't flood the update server with simultaneous requests.
3. The Orchestrator checks the update list against host configuration to pull appropriate updates.
4. Once decided, downloads begin in the background.
5. Updates are stored in the temp folder; manifests are checked, and only needed files are pulled.
6. Update Orchestrator calls the installer agent and passes it the necessary action list.
7. The installer agent applies the updates (not yet finalized).
8. Once done, Orchestrator finalizes updates with a host reboot — ensuring modifications to services or critical settings take effect.

> [!warning] Rollout practice
> Manage updates via WSUS or Group Policy. Always test the rollout in a development setting (a few hosts) before pushing enterprise-wide, to avoid accidentally breaking a critical app or function.

## Configuration Management

Achieved in Windows primarily through **Group Policy** — centrally manage user and computer settings/preferences across the environment via the Group Policy Management Console (GPMC) or PowerShell.

> [!tip] Scope
> Group Policy works best in an Active Directory environment, but local computer/user settings can also be managed via local group policy — from user backgrounds and browser settings to when/how Windows Defender scans and updates the host. This can be very granular — have a plan for implementing any new or modified group policies.

## User Management

- Limit the number of user and admin accounts on each system.
- Ensure login attempts (valid and invalid) are logged and monitored.
- Enforce a strong password policy and two-factor authentication.
- Rotate passwords periodically and restrict reuse of old passwords via Group Policy Password Policy settings, found at:
  `Computer Configuration\Windows Settings\Security Settings\Account Policies\Password Policy`
- Check that users aren't placed into groups granting excessive rights unnecessary for daily tasks (e.g. a regular user with Domain Admin rights).
- Enforce login restrictions for administrator accounts.


> [!tip] Two-Factor Authentication (2FA)
> Requires something you know (password/PIN) and something you have (token, ID card, authenticator app key code). Significantly reduces the risk of accounts being used maliciously.

## Audit

Perform periodic security and configuration checks of all systems. Reference security baselines:
- [DISA Security Technical Implementation Guides (STIGs)](https://public.cyber.mil/stigs/)
-  Microsoft's [Security Compliance Toolkit](https://docs.microsoft.com/en-us/windows/security/threat-protection/windows-security-configuration-framework/security-compliance-toolkit-10)
- Compliance frameworks:  [ISO27001](https://www.iso.org/isoiec-27001-information-security.html), [PCI-DSS](https://www.pcisecuritystandards.org/pci_security/), and [HIPAA](https://www.hhs.gov/hipaa/for-professionals/security/index.html)

> [!warning] Baselines are reference guides, not the program itself
> A strong security program should have controls tailored to the organization's needs, operating environment, and types of data stored/processed (PHI, financial data, trade secrets, or public information) — not just baseline compliance.


> [!warning] Limitation
> An audit/configuration review is not a replacement for a penetration test or other hands-on technical assessment, and is often seen as a "box-checking" exercise where an organization "passes" by performing the bare minimum. These reviews supplement — not replace — regular vulnerability scans, penetration tests, and strong patch/vulnerability/configuration management programs.

## Logging

Proper logging and log correlation can make all the difference when troubleshooting an issue or hunting a potential threat in your network. Below we will discuss some apps and logs that can help improve your security posture on a Windows host.

### Sysmon

> [!info] What it is
> [Sysmon](https://learn.microsoft.com/en-us/sysinternals/downloads/sysmon) is a Microsoft tool (part of Sysinternals Suite) that enhances logging and event collection on Windows — detailed info on processes, network connections, file reads/writes, login attempts/successes, and much more. Logs can be correlated and shipped to a SIEM for analysis. Sysmon persists on the host and begins writing logs at startup.

Sysmon logs are stored at:
`Applications and Service Logs\Microsoft\Windows\Sysmon\Operational` (viewable via Event Viewer).

### Network and Host Logs

Tools like [PacketBeat](https://www.elastic.co/beats/packetbeat), IDS/IPS implementations (e.g. Security Onion sensors), and other network monitoring solutions collect and ship network traffic logs to monitoring solutions and SIEMs, completing the visibility picture for administrators.

## Key Hardening Measures

> [!danger] Checklist (non-exhaustive)
> - Secure boot and disk encryption with BitLocker should be enabled and in use.
> - Audit writable files and directories, and any binaries able to launch other apps.
> - Ensure scheduled tasks and scripts running with elevated privileges specify binaries/executables using absolute paths.
> - Do not store credentials in cleartext in world-readable files on the host or shared drives.
> - Clean up home directories and PowerShell history.
> - Ensure low-privileged users cannot modify custom libraries called by programs.
> - Remove unnecessary packages and services that increase the attack surface.
> - Utilize Device Guard and Credential Guard (built into Windows 10 and most new Server OS).
> - Utilize Group Policy to enforce configuration changes needed across company systems.

> [!tip] Note
> Many of these measures appear in STIG checklists. Be mindful of what environments use, and how measures affect the ability to accomplish the mission — do not blindly implement widespread hardening measures across the network, as what works for one organization may not work for another. Know what you're protecting, then apply appropriate measures per business requirements.

## Conclusion

As covered throughout this module, there are many ways to escalate privileges on Windows systems — from simple misconfigurations and public exploits for known vulnerable services, to exploit development based on custom libraries and executables. Once administrator or SYSTEM access is obtained, it becomes a pivot point for further network exploitation.

> [!info] Takeaways
> - System hardening is equally critical for small companies and large enterprises.
> - Attackers no longer care who the victim is, as long as they get what they want out of the exchange.
> - Reviews should mix hands-on manual testing and automated configuration scanning (e.g. Nessus), followed by validation of results.
> - While patching for the latest attacks and implementing sophisticated monitoring, don't forget the basics and "low hanging fruit" covered throughout this module.
> - Ensure staff is constantly challenged and trained, staying at the forefront of new vulnerabilities and exploit PoCs, so the organization can remain protected as researchers continue discovering new avenues of attack.
