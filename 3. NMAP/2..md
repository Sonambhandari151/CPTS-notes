# 🔎 Service Enumeration 

### Why Important

- Identifies **services & versions** running on target.
    
- Helps find **known vulnerabilities** & match **exploits**.
    
- Banners often reveal OS & application details.
    

---

### Nmap Basics

- **Quick scan first** → low traffic, less chance of detection.
    
- **Full scan (-p-)** → all 65,535 ports, but slower.
    

**Key Options:**

- `-p-` → scan all ports.
    
- `-sV` → detect service versions.
    
- `-v / -vv` → verbose, shows results as they are found.
    
- `--stats-every=5s` → periodic scan progress updates.
    
- `-Pn` → skip host discovery (no ping).
    
- `-n` → skip DNS resolution.
    
- `--disable-arp-ping` → don’t use ARP ping.
    
- `--packet-trace` → show all packets sent/received.
    

---

### Scan Examples

```bash
sudo nmap 10.129.2.28 -p- -sV         # Full service version scan
sudo nmap 10.129.2.28 -p- -sV -v      # Verbose mode
sudo nmap 10.129.2.28 -p- -sV --stats-every=5s
sudo nmap 10.129.2.28 -p- -sV -Pn -n --disable-arp-ping --packet-trace
```

---

### Banner Grabbing

- Nmap uses **banners** + **signature matching** to identify versions.
    
- Sometimes Nmap misses info → manual banner grabbing needed.
    
- Use **nc (netcat)** to connect & grab banner:
    
    ```bash
    nc -nv 10.129.2.28 25
    ```
    
- Use **tcpdump** to capture traffic:
    
    ```bash
    sudo tcpdump -i eth0 host <your-ip> and <target-ip>
    ```
    

---

### TCP Handshake & Banner Flow

1. **SYN** → Client → Server
    
2. **SYN-ACK** → Server → Client
    
3. **ACK** → Client → Server (handshake complete)
    
4. **PSH-ACK** → Server sends banner (e.g., `220 inlane ESMTP Postfix (Ubuntu)`)
    
5. **ACK** → Client acknowledges
    

---

### Key Takeaways

- **Service enumeration = foundation** for exploitation.
    
- Nmap is powerful but can miss details → use manual tools.
    
- Banners often leak **OS & version info** → valuable for vulnerability research.
    
- Combine **Nmap + nc + tcpdump** for full visibility.

# ⚡ Nmap Scripting Engine (NSE) — Short Notes

### 📌 What is NSE?

- Allows Nmap to run **Lua scripts** for deeper interaction with services.
    
- Useful for **service discovery, vulnerability detection, brute-forcing, exploitation, and enumeration**.
    

---

### 📂 NSE Script Categories (14)

- **auth** → authentication credentials.
    
- **broadcast** → host discovery via broadcasts.
    
- **brute** → brute-force login attempts.
    
- **default** → run with `-sC`.
    
- **discovery** → gather more info about services.
    
- **dos** → check DoS vulnerabilities (use with caution).
    
- **exploit** → exploit known vulnerabilities.
    
- **external** → use external services/APIs.
    
- **fuzzer** → send malformed input to test stability.
    
- **intrusive** → may disrupt target.
    
- **malware** → detect malware infections.
    
- **safe** → non-intrusive, safe to run.
    
- **version** → extend version detection.
    
- **vuln** → check for known vulnerabilities.
    

---

### 🔧 Usage

- **Default scripts:**
    
    ```bash
    nmap <target> -sC
    ```
    
- **Specific category:**
    
    ```bash
    nmap <target> --script <category>
    ```
    
- **Specific scripts:**
    
    ```bash
    nmap <target> --script banner,smtp-commands
    ```
    

---

### 🛠 Examples

- **SMTP Enumeration:**
    
    ```bash
    nmap 10.129.2.28 -p 25 --script banner,smtp-commands
    ```
    
    → Shows banner (`Postfix on Ubuntu`) + supported SMTP commands.
    
- **Aggressive Scan (-A):**
    
    ```bash
    nmap 10.129.2.28 -p 80 -A
    ```
    
    → Runs `-sV -O --traceroute -sC` together (service detection, OS detection, traceroute, default scripts).
    
- **Vulnerability Scan:**
    
    ```bash
    nmap 10.129.2.28 -p 80 -sV --script vuln
    ```
    
    → Finds **WordPress version, users, possible admin paths, and CVEs** for Apache.
    

---

### 🚀 Key Takeaways

- NSE makes Nmap much more powerful for **enumeration + vuln assessment**.
    
- Choose script **categories carefully** (safe vs intrusive).
    
- Use **-A** for quick recon, but **--script vuln** for security testing.
    
- Full NSE documentation: [nmap.org/nsedoc](https://nmap.org/nsedoc/index.html)

### 🔹 Nmap Performance Options

- **Why important?** → Big networks or low bandwidth need optimized scanning.
    

**Key Options:**

- `-T <0-5>` → Timing templates (scan aggressiveness).
    
- `--min-parallelism <num>` → Min # of parallel probes.
    
- `--max-rtt-timeout <time>` → Max round-trip-time allowed.
    
- `--min-rate <num>` → Min packets sent per second.
    
- `--max-retries <num>` → Retry attempts per port (default: 10).
    

---

### 🔹 Timeouts (RTT)

- **Default**: `--initial-rtt-timeout 100ms`.
    
- Reducing (`--initial-rtt-timeout 50ms`) → faster but may miss hosts.
    

---

### 🔹 Retries

- **Default**: `--max-retries 10`.
    
- Reducing (`--max-retries 0`) → faster, but may skip open ports.
    

---

### 🔹 Rates

- Control packet sending speed.
    
- `--min-rate <num>` → forces Nmap to send at least `<num>` packets/sec.
    
- Example: `--min-rate 300` greatly speeds up scans.
    

---

### 🔹 Timing Templates (`-T <0-5>`)

- `-T0` → Paranoid (very slow, IDS evasion).
    
- `-T1` → Sneaky.
    
- `-T2` → Polite (slower, less bandwidth).
    
- `-T3` → Normal (default).
    
- `-T4` → Aggressive (fast, can trigger defenses).
    
- `-T5` → Insane (very fast, noisy, may miss results).
    

---

### ⚖️ Trade-off:

- Faster scans → risk missing hosts/services.
    
- Slower scans → more accurate, stealthier.

# 🔥 Firewall & IDS/IPS Evasion with Nmap 

### 🔹 Firewalls

- Control traffic by **allow/deny rules** (drop or reject packets).
    
- Dropped → no reply.
    
- Rejected → RST/ICMP error returned.
    

### 🔹 IDS / IPS

- **IDS** → Detects & reports suspicious traffic.
    
- **IPS** → Detects + blocks automatically.
    
- Both rely on **signatures & patterns** (e.g., SYN scans).
    

---

## 🛠 Evasion Techniques

### 1. **ACK Scan (-sA)**

- Sends TCP packets with **ACK flag**.
    
- Often bypasses firewalls (since ACKs look like part of existing sessions).
    
- Response:
    
    - RST = port unfiltered.
        
    - No response = filtered.
        

---

### 2. **Decoys (-D)**

- Adds fake IPs in the source field to **hide real scanner IP**.
    
- Example:
    
    ```bash
    nmap -sS -p 80 10.10.10.5 -D RND:5
    ```
    
- Logs show multiple attackers → difficult to trace real source.
    

---

### 3. **Source IP Spoofing (-S)**

- Fakes packets as if coming from another IP.
    
- Example:
    
    ```bash
    sudo nmap -sS -p 445 10.10.10.5 -S 192.168.1.50 -e tun0
    ```
    
- Useful if firewall **allows only certain IPs**.
    
- Limitation → replies go to spoofed IP, not you (unless you control it).
    

---

### 4. **Source Port Manipulation (--source-port)**

- Sends traffic from trusted ports (e.g., **53/DNS**, **20/FTP**).
    
- Example:
    
    ```bash
    nmap -sS -p 50000 10.10.10.5 --source-port 53
    ```
    
- May bypass firewall/IPS if those ports are allowed.
    

---

### 5. **Packet Fragmentation (-f)**

- Splits packets into smaller fragments.
    
- Helps bypass filters that fail to reassemble packets properly.
    

---

### 6. **DNS Proxying (--dns-server)**

- Use custom DNS servers for reverse lookups.
    
- Can bypass restrictions in **DMZ/internal DNS policies**.
    

---

## ⚡ Key Takeaways

- **Firewalls** block/allow connections.
    
- **IDS** = detection only, **IPS** = detection + prevention.
    
- Use **ACK scans** to probe firewall rules.
    
- Use **decoys** to hide your IP.
    
- Use **source spoofing** to impersonate allowed hosts.
    
- Use **trusted ports (53, 20, 443)** to sneak traffic through.
    
- Be **quiet & stealthy** → aggressive scans trigger IPS.
