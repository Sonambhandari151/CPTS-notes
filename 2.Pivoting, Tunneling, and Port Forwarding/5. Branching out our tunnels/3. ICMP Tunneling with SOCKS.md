
# 1. Concept (clear)

ICMP tunneling = **send your traffic inside ping packets**

Normal blocked case:

```text
Attack → SSH/RDP → ❌ blocked by firewall
```

ICMP tunnel:

```text
Attack → ICMP (ping) → Pivot → Internal service
```

---

## Why we use this

- Firewall blocks TCP (22, 3389, etc.)
    
- But allows **ICMP (ping)**
    
- So we:
    
    - Hide SSH inside ICMP
        
    - Bypass firewall

# 5. Transfer to Pivot

## WHERE: attack host

```bash
scp -r ptunnel-ng ubuntu@10.129.202.64:~/
```

---

## WHY

- Pivot host must run **server part**
    

---

# 6. Start Server (Pivot Host)

## WHERE: pivot machine

```bash
ssh ubuntu@10.129.202.64
cd ptunnel-ng/src
```

Run:

```bash
sudo ./ptunnel-ng -r10.129.202.64 -R22
```

---

## Meaning (IMPORTANT)

```text
-r 10.129.202.64 → bind on pivot (its reachable IP)
-R 22            → forward to SSH service
```

---

## WHY

- Pivot listens for ICMP packets
    
- Extracts data
    
- Sends to:
    

```text
localhost:22 (SSH)
```

---

# 7. Start Client (Attack Host)

## WHERE: your machine

```bash
sudo ./ptunnel-ng -p10.129.202.64 -l2222 -r10.129.202.64 -R22
```

---

## Meaning

```text
-p → pivot IP (where ICMP goes)
-l → local port (2222)
-r → destination host (pivot again)
-R → destination port (22)
```

---

## Result

```text
127.0.0.1:2222 → ICMP → pivot → SSH (22)
```

---

# 8. Use Tunnel (SSH)

## WHERE: attack host

```bash
ssh -p2222 ubuntu@127.0.0.1
```

---

## WHY

- You are not connecting directly
    
- You are using:
    

```text
local port → ICMP tunnel → pivot → SSH
```

---

# 9. Create SOCKS Proxy (IMPORTANT)

## WHERE: attack host

```bash
ssh -D 9050 -p2222 ubuntu@127.0.0.1
```

---

## Meaning

```text
-D 9050 → create SOCKS proxy on localhost
```

---

## WHY

- Convert SSH tunnel into **proxy**
    
- So tools can use it
    

---

# 10. Configure Proxychains

## WHERE: attack host

```bash
nano /etc/proxychains.conf
```

Add:

```text
socks5 127.0.0.1 9050
```

---

## WHY

- Tell tools to route via tunnel

# 13. IP Understanding (VERY IMPORTANT)

|Component|IP used|
|---|---|
|Attack host|your VPN (10.10.x.x)|
|Pivot|10.129.202.64|
|Internal target|172.16.5.x|
|Local tunnel|127.0.0.1|

---

# 14. Why each IP used

- `-p 10.129.202.64`  
    → where ICMP packets go
    
- `-r 10.129.202.64`  
    → pivot forwards internally
    
- `127.0.0.1`  
    → local tunnel endpoint
    
- `172.16.5.x`  
    → actual internal target
    

---

# 15. Key Understanding

```text
You NEVER directly access 172.16.5.x

You always go through:
localhost → tunnel → pivot → internal
```

---

# 16. When to use

Use ICMP tunneling when:

- SSH blocked ❌
    
- HTTP blocked ❌
    
- Only ping works ✅
