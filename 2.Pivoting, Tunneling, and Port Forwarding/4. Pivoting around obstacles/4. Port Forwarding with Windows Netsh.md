

---

## 1. Concept (core idea)

- You have a **Windows pivot** inside network
    
- Internal systems (172.16.x.x) are **not directly reachable**
    
- Pivot **can reach them**
    

👉 So we make Windows act as a **port forwarder**

```text
Attack Host → Windows Pivot (open port) → Internal Target (real service)
```

---

## 2. Scenario Understanding

- Pivot machine has **2 networks**:
    
    - External: `10.129.15.150` (you can access)
        
    - Internal: `172.16.5.19` (you cannot access directly)
        
- Target service:
    
    - Internal server: `172.16.5.25`
        
    - Service: RDP (port 3389)
        

---

## 3. Goal

> Access internal RDP service via pivot

---

## 4. Step-by-Step Execution

---

### STEP 1 — Access Pivot Machine

📍 Run on **Attack Machine**

```bash
xfreerdp /v:10.129.15.150 /u:htb-student /p:HTB_@cademy_stdnt!
```

### Why:

- You need access to pivot to configure forwarding
    

---

### STEP 2 — Create Port Forward Rule

📍 Run inside **Windows Pivot (CMD as Administrator)**

```cmd
netsh interface portproxy add v4tov4 listenport=8080 listenaddress=10.129.15.150 connectport=3389 connectaddress=172.16.5.25
```

---

### Why this command:

|Part|Meaning|
|---|---|
|listenport=8080|Open port on pivot|
|listenaddress=10.129.15.150|Pivot’s reachable IP|
|connectaddress=172.16.5.25|Internal target|
|connectport=3389|RDP service|

👉 Meaning:

> “If traffic comes to me on 8080 → send it to 172.16.5.25:3389”

---

### STEP 3 — Verify Rule (optional)

📍 Run on **Windows Pivot**

```cmd
netsh interface portproxy show v4tov4
```

---

### STEP 4 — Connect to Internal Target

📍 Run on **Attack Machine**

```bash
xfreerdp /v:10.129.15.150:8080 /u:victor /p:pass@123
```

---

## 5. Execution Flow (very important)

```text
1. You connect → 10.129.15.150:8080
2. Windows pivot receives request
3. Netsh rule triggers
4. Traffic forwarded → 172.16.5.25:3389
5. Internal RDP session opens
6. Response comes back same path
```
