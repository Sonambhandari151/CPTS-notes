# 🔹 PORT FORWARDING – THEORY

Port forwarding = redirect traffic from one port → another

- Uses TCP for communication
    
- Helps access **internal / restricted services**
    
- Can bypass firewall restrictions using allowed services (like SSH)
    

---

# 🔹 LOCAL PORT FORWARDING (SSH -L)

### Theory

Used when:

- Service runs on **remote localhost**
    
- You want to access it from your machine
    

Flow:

```text
Your Machine → SSH Tunnel → Remote Server → Local Service
```

---

### Command

```bash
ssh -L 1234:localhost:3306 ubuntu@10.129.202.64
```

### Meaning

- `1234` → local port (your machine)
    
- `localhost:3306` → remote MySQL service
    
- Traffic forwarded through SSH
    

---

### Verification

```bash
netstat -antp | grep 1234
```

```bash
nmap -v -sV -p1234 localhost
```

---

### Multiple Port Forwarding

```bash
ssh -L 1234:localhost:3306 -L 8080:localhost:80 ubuntu@10.129.202.64
```

---

# 🔹 INITIAL SCAN (DISCOVER SERVICES)

```bash
nmap -sT -p22,3306 10.129.202.64
```

### Result

- 22 → open (SSH)
    
- 3306 → closed (local only)
    

---

# 🔹 PIVOTING – THEORY

Pivoting = using compromised host to access another network

Condition:

- Host has **multiple NICs**
    

---

### Check Interfaces

```bash
ifconfig
```

### Example Output Insight

- `ens192` → external network
    
- `ens224` → internal network (172.16.5.0/23)
    
- `lo` → loopback
    

👉 This host becomes **pivot host**

---

# 🔹 LIMITATION OF LOCAL FORWARDING

- Works only for **known ports**
    
- Cannot scan internal network
    
- Not scalable
    

---

# 🔹 DYNAMIC PORT FORWARDING (SSH -D)

### Theory

Creates a **SOCKS proxy** to route all traffic
![[Pasted image 20260503210729.png]]
Flow:

```text
Tool → SOCKS Proxy → SSH → Pivot Host → Internal Network
```

---

### Command

```bash
ssh -D 9050 ubuntu@10.129.202.64
```

### Result

- SOCKS proxy on `127.0.0.1:9050`
    

---

# 🔹 SOCKS PROXY – THEORY

- Routes traffic through proxy server
    
- Helps bypass firewall
    
- Used for pivoting
    

Types:

- SOCKS4 → no auth
    
- SOCKS5 → auth + UDP
    

---

# 🔹 PROXYCHAINS – THEORY

Used to force tools to use proxy

Config file:

```bash
/etc/proxychains.conf
```

---

### Configure Proxychains

```bash
tail -4 /etc/proxychains.conf
```

Add:

```text
socks4 127.0.0.1 9050
```

---

# 🔹 INTERNAL NETWORK SCANNING

### Theory

- Cannot scan directly
    
- Use pivot host via SOCKS
    

---

### Command

```bash
proxychains nmap -v -sn 172.16.5.1-200
```

---

# 🔹 NMAP OVER PROXYCHAINS

### Important Theory

- Only **TCP connect scan (-sT)** works
    
- No SYN scan (raw packets not supported)
    

---

### Scan Command

```bash
proxychains nmap -v -Pn -sT 172.16.5.19
```

### Flags

- `-Pn` → skip ping
    
- `-sT` → full TCP scan
    

---

### Result (important ports)

- 445 → SMB
    
- 135 → RPC
    
- 139 → NetBIOS
    
- 3389 → RDP

---

```text
Your Machine → SOCKS Proxy → Ubuntu Pivot → Windows Target
```

---

# 🔹 CORE CONCEPT (IMPORTANT)

You are NOT directly inside network

Actual path:

```text
You → Proxychains → SOCKS (9050) → Pivot Host → Internal Target
```

---

# 🔹 FIREWALL BYPASS

- SSH (port 22) allowed
    
- Traffic hidden inside SSH tunnel
    
- Internal network becomes reachable
    

---

# 🔹 LIMITATIONS

- Slow scanning
    
- No raw packet scans
    
- ICMP often blocked
    
- Large scans take time
