## Password Security Fundamentals: Technical Notes

Password security is the primary barrier against brute-force attacks. The difficulty of a successful attack is directly proportional to the **entropy** (randomness and complexity) of the target credentials.

---

### 1. The Anatomy of a Strong Password (NIST Guidelines)

Modern security standards, particularly from **NIST**, emphasize length and usability over frequent rotations.

* **Length:** This is the most critical factor. Each additional character increases the "keyspace" exponentially.
    * *6 characters (lowercase):* $26^6 \approx 300$ million combinations.
    * *8 characters (lowercase):* $26^8 \approx 200$ billion combinations.
* **Complexity:** Using different character sets (Uppercase, Lowercase, Numbers, Symbols) increases the pool of possibilities for each slot ($52$ vs. $26$ vs. $95+$).
* **Uniqueness:** Prevents **Credential Stuffing**. If one service is breached, unique passwords ensure other accounts remain secure.
* **Randomness:** Passwords should avoid predictable strings, dictionary words, or personal information (PII) that can be found via OSINT.



---

### 2. Common Weaknesses & Patterns

Attackers exploit human psychology and laziness to bypass security.

| Weakness | Description | Attack Method |
| :--- | :--- | :--- |
| **Short Passwords** | Fewer than 8 characters. | Simple Brute Force |
| **Dictionary Words** | Using "password," "admin," or "winter." | Dictionary Attack |
| **PII** | Birthdays, pet names, or addresses. | Targeted Guessing / OSINT |
| **Predictable Patterns** | "123456," "qwerty," or "P@ssw0rd1!." | Rule-based / Hybrid Attack |
| **Password Reuse** | Using the same password everywhere. | Credential Stuffing |

---

### 4. Password Policies: Enforcement vs. Usability

Organizations use policies to force better habits, but they must balance security with user frustration.

* **Minimum Length:** Usually enforced at 12+ characters.
* **Complexity Requirements:** Forcing at least one of each character type.
* **Password History:** Preventing users from switching between "Password1" and "Password2."
* **The Downside:** Overly strict policies (like forcing changes every 30 days) often lead to users writing passwords on sticky notes or using easily guessable increments.

---

### 5. Brute-Forcing for Pentesters

For a penetration tester, understanding these fundamentals is a roadmap:
1.  **Evaluate Policy:** Determine if the target enforces complexity or allows weak passwords.
2.  **Tool Selection:** Choose **Hydra** for service brute-forcing, **Hashcat** for offline cracking, or **Burp Suite** for web forms.
3.  **Default Check:** Always attempt common manufacturer credentials first.
4.  **Resource Management:** Estimate the time required based on the keyspace. If a password is 15 characters and random, a brute-force attack is likely unfeasible within the engagement timeframe.
