## Custom Wordlists: Targeted Brute Forcing

### Core Concept

- **Limitation of Generic Lists:** Lists like `rockyou.txt` are broad and often fail against specific organizational naming conventions or personal password patterns.
    
- **The Custom Advantage:** Targeted wordlists use OSINT (Open Source Intelligence) to dramatically increase efficiency by focusing on data relevant to the specific target.
    

---

### Username Anarchy

- **Purpose:** Generates a massive variety of potential username formats based on a target's first and last name.
    
- **Installation:** `sudo apt install ruby -y && git clone https://github.com/urbanadventurer/username-anarchy.git`
    
- **Common Formats Generated:** `first.last`, `flast`, `last.f`, `firstlast[year]`, etc.
    
- **Usage Example:** `./username-anarchy Jane Smith > usernames.txt`
    

---

### CUPP (Common User Passwords Profiler)

- **Purpose:** An interactive tool that builds a password dictionary based on a victim's personal details.
    
- **OSINT Data Points:** Birthdays, nicknames, partner/pet names, company names, and hobbies.
    
- **Usage:** `cupp -i`
    
- **Output:** Creates a `.txt` file containing thousands of permutations, including leetspeak, reversed strings, and year-appended variations.
    

---

### Advanced Filtering with Grep

In scenarios with strict **Password Policies**, raw lists must be filtered to save time during the attack.

**Example Policy (AHI Corp):**

- Min 6 characters.
    
- 1 Uppercase, 1 Lowercase, 1 Number.
    
- 2 Special characters from `[!@#$%^&*]`.
    

**The Filtering Command:**

`grep -E '^.{6,}$' list.txt | grep -E '[A-Z]' | grep -E '[a-z]' | grep -E '[0-9]' | grep -E '([!@#$%^&*].*){2,}' > filtered.txt`

---

### Execution with Hydra

To attack a web login form using the custom lists:

`hydra -L usernames.txt -P filtered.txt <IP> -s <PORT> http-post-form "/:username=^USER^&password=^PASS^:Invalid credentials" -f`

- **-L/-P:** Path to custom username and password files.
    
- **http-post-form:** The module for web forms.
    
- **^USER^ / ^PASS^:** Placeholders for the wordlist entries.
    
- **:Invalid credentials:** The error message Hydra looks for to determine a failed attempt.
    
- **-f:** Stop immediately upon finding a valid pair.
