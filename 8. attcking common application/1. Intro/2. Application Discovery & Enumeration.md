# Application Discovery & Enumeration 

## 1. Objective

To build a complete **asset inventory** of an organization:

- Hosts (servers, workstations, network devices)
    
- Applications (web apps, internal tools, SaaS)
    
- Services and versions
    
- Patch levels and EOL software
    
- Shadow IT / unauthorized apps
    

---

## 2. Why Enumeration Matters

If an organization lacks visibility:

- Unknown applications = **unprotected attack surface**
    
- Misconfigurations remain unnoticed
    
- Default credentials may exist
    
- Vulnerable / outdated software may be exposed
    
- Rogue applications (“shadow IT”) increase risk
    

---

## 3. Key Security Checks During Discovery

During enumeration, identify:

- Installed vs cloud-hosted applications
    
- Patch status / versioning
    
- End-of-life software
    
- Default or weak credentials
    
- MFA enabled or not
    
- Admin panels restricted by IP or localhost
    
- Exposed internal services
    

---

## 4. Penetration Testing Approach (Workflow)

### Step 1: Initial Host Discovery

- Ping sweep / scope enumeration
    
- Identify live hosts
    

### Step 2: Port Scanning

Focus on common web ports:

```bash
nmap -p 80,443,8000,8080,8180,8888,10000 --open -iL scope_list
```

### Step 3: Service Identification

```bash
nmap -sV <target>
```

Find:

- Web servers (Apache, IIS, Nginx)
    
- Enterprise tools (Splunk, Jenkins, PRTG)
    
- Remote services (RDP, SSH)
    

---

## 5. Web Application Enumeration Problem

In large environments:

- Hundreds of hosts
    
- Multiple web services per host
    
- Manual checking becomes inefficient
    

➡ Solution: Automation tools

---

## 6. Screenshotting Tools (Web Discovery)

### 6.1 EyeWitness

Purpose:

- Takes screenshots of web apps
    
- Categorizes services
    
- Detects default credentials hints
    

Input:

- Nmap XML / Nessus / URL list
    

Example:

```bash
eyewitness --web -x web_discovery.xml -d report_dir
```

Key Features:

- Selenium-based screenshotting
    
- Fingerprinting applications
    
- HTML report generation
    

---

### 6.2 Aquatone

Purpose:

- Fast web screenshot automation
    
- Clusters similar pages
    
- Generates HTML report
    

Example:

```bash
cat web_discovery.xml | ./aquatone -nmap
```

Output includes:

- HTTP status codes
    
- Screenshots
    
- Grouped UI clusters
    

---

## 7. Output Analysis Strategy

When reviewing results:

### High Priority Targets

- Admin panels
    
- Jenkins / GitLab
    
- Tomcat / Web logic servers
    
- Splunk / monitoring tools
    

### Medium Priority

- CMS (WordPress, Drupal, Joomla)
    
- Support systems (osTicket)
    

### Low Priority

- Splash pages
    
- Default IIS/Apache pages
    

---

## 8. Host Prioritization (Important Skill)

Focus on:

- Dev environments (`dev.*`)
    
- Test systems (`qa`, `acc`)
    
- Internal tools exposed externally
    
- Git repositories (possible secrets)
    
- Admin dashboards
    

---

## 9. Common High-Value Applications

|Application|Why Important|
|---|---|
|Apache Tomcat|WAR upload → RCE|
|Jenkins|Script execution|
|GitLab|Code + secrets leakage|
|Splunk|Sensitive logs, auth bypass risks|
|PRTG|Admin misconfigurations|
|osTicket|Ticket data + auth abuse|

---

## 10. Methodology Mindset

A good pentester:

- Does NOT attack immediately
    
- First builds full **visibility map**
    
- Documents everything (hosts, ports, apps)
    
- Prioritizes targets strategically
    
- Uses scanners only as input, not final truth
