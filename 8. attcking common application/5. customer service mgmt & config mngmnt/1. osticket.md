# osTicket

## What Is osTicket?
osTicket is an **open-source support ticketing system** (comparable to Jira, OTRS, Request Tracker, Spiceworks). Integrates email, phone, and web-form inquiries into one interface. Written in **PHP**, uses a **MySQL** backend. Runs on Windows or Linux.

> [!info] Why this section matters
> osTicket is well-maintained with few real CVEs — this section is really about **support ticketing systems as a category**, and why they shouldn't be dismissed just because the software itself looks solid.

## Footprinting / Discovery / Enumeration
- EyeWitness/screenshot recon may reveal a cookie named **`OSTSESSID`**.
- Page footer usually shows the osTicket logo with **"powered by"**, sometimes with **"Support Ticket System"**.
- An Nmap scan only reveals the underlying webserver (Apache/IIS) — it won't fingerprint osTicket itself; footprinting relies on visual/cookie cues.

## The Three-Layer Model
| Layer             | Description                                                                                                                                                                                                                   |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1. User Input** | End users report problems. Since osTicket is open-source, tutorials/docs reveal exactly how access controls work (e.g. admin panel restricted to staff/admins) — useful for crafting a believable social-engineering pretext. |
| **2. Processing** | Staff reproduce issues in an isolated environment mirroring production.                                                                                                                                                       |
| **3. Solution**   | Deeper issues loop in other technical staff via email — a source of new email addresses/usernames for OSINT.                                                                                                                  |

## Attacking osTicket

### Known Vulnerabilities
Exploit-DB lists issues like remote file inclusion, SQLi, arbitrary file upload, XSS. Notably:
- **CVE-2020-24881** — SSRF in osTicket 1.14.1, potentially usable to reach internal resources or perform internal port scanning.
 [CVE-2020-24881](https://nvd.nist.gov/vuln/detail/CVE-2020-24881)
### The Real Value: Email Harvesting via Support Tickets
Support portals often reveal a **valid company email address** just by submitting a ticket — some setups even assign a **per-ticket internal email alias** (e.g. `940288@inlanefreight.local`) so users can track status via email.

**Why this matters:** many external services (Slack, GitLab, wikis, etc.) require a company email to register. If you can get a legitimate-looking company email from a support portal, you may be able to use it to self-register elsewhere and receive the confirmation email back through the ticket.

> [!tip] Related HTB content
> This technique is showcased in the HTB machine **Delivery**, inspired by a public blog post on the same idea.

### Worked Example — Sensitive Data Exposure

[Dehashed](http://dehashed.com/)

**Step 1 — OSINT credential dump (e.g. via Dehashed):**
```
sudo python3 dehashed.py -q inlanefreight.local -p

email: julie.clayton@inlanefreight.local | user: jclayton | pass: JulieC8765!
email: kevin@inlanefreight.local          | user: kgrimes  | pass: Fish1ng_s3ason!
```

**Step 2 — Subdomain enumeration** turns up several live hosts, notably:
- `support.inlanefreight.local` (osTicket instance)
- `vpn.inlanefreight.local` (Barracuda SSL VPN, **no MFA**)

**Step 3 — Credential stuffing against osTicket admin login:**
- `jclayton` / `JulieC8765!` → fails
- `kgrimes` / `Fish1ng_s3ason!` → fails
- **`kevin@inlanefreight.local`** (email instead of username) / `Fish1ng_s3ason!` → **success!**

> [!tip] Lesson
> Always try the **email** as the login identifier too, not just the username — some portals accept both.

**Step 4 — Digging through tickets:**
A closed ticket shows an employee locked out of VPN, asking for a reset. The agent:
1. Resets the password to the **standard new-joiner password**
2. The user asks for it to be read over the phone (good instinct)
3. The agent **sends it directly through the ticket portal anyway** — a real leak

> [!danger] Why this is valuable
> If the org uses a **standard default password for new joiners/resets** and doesn't force a change at next login, this password may well work for **other users too** — ideal for a password spray.

**Follow-up ideas:**
- Use tools like [linkedin2username](https://github.com/initstring/linkedin2username) to build an employee list from LinkedIn.
- Password-spray the leaked standard password against the VPN portal (or AD in general).
- Export the osTicket **address book** — emails/usernames are useful for further password spraying.

## Mitigations
- Limit which applications are exposed externally
- Enforce MFA on all external portals
- Security-awareness training — don't use corporate emails to sign up for third-party services
- Strong AD/app password policy — disallow `welcome`, `password`, company name, seasons/months, etc.
- Force password change after first login; expire passwords periodically

## Quick Recap
| Stage    | Technique                                         | Result                                     |
| -------- | ------------------------------------------------- | ------------------------------------------ |
| Recon    | Screenshots/cookie (`OSTSESSID`), footer branding | Confirms osTicket is in use                |
| OSINT    | Dehashed dump + subdomain enum                    | Candidate creds + live support/VPN hosts   |
| Login    | Try email *and* username as identifier            | Access to agent's ticket queue             |
| Harvest  | Read closed tickets                               | Leaked "standard" password for new joiners |
| Escalate | Password spray leaked password / build user list  | Potential access to VPN or other services  |
