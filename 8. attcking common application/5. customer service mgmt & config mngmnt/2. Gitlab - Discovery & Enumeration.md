# GitLab — Discovery & Enumeration

## What Is GitLab?
GitLab is a web-based **Git repository hosting** platform with wiki, issue tracking, and CI/CD pipeline functionality. Open-source, originally Ruby, current stack spans **Go, Ruby on Rails, Vue.js**. Free version available alongside a paid enterprise tier.

## Quick Facts
- Launched 2014; ~1,466 employees; $150M revenue (2020)
- 30M+ registered users across 66 countries
- Publishes internal procedures/OKRs publicly
- Notable users: Drupal, Goldman Sachs, HackerOne, Ticketmaster, Nvidia, Siemens

> [!tip] Why Git hosting matters in assessments
> Self-hosted GitLab/GitHub/BitBucket instances frequently contain accidentally-committed secrets — cleartext passwords, API keys, or SSH private keys — even in otherwise unremarkable repos.

## Access Model
GitLab supports three repo visibility levels:
- **Public** — no authentication needed
- **Internal** — visible to any authenticated user
- **Private** — restricted to specific users

Some instances allow **open self-registration** — worth checking, since registering can unlock internal repos.

> [!warning] Defaults worth knowing
> Two-factor authentication is **disabled by default**. Combined with weak/reused credentials from OSINT, this makes credential-based login attempts viable.

## Footprinting & Discovery
- Browsing to the GitLab URL redirects to the login page (GitLab branding is unmistakable).
- **Version fingerprinting** is only reliable via the `/help` page — but that requires being logged in.
  - If self-registration is open: register → log in → check `/help`.
  - If not: avoid blindly firing exploits; stick to hunting for secrets rather than guessing versions.
- Some notable historical GitLab vulnerabilities: GitLab 12.9.0, GitLab 11.4.7, GitLab CE 13.10.3 / 13.9.3 / 13.10.2.

## Enumeration

### Step 1 — Browse `/explore`
Lists public projects. Even "toy" or example-looking projects are worth digging through — production code with hardcoded creds or config secrets shows up in unexpected places.

### Step 2 — Check Other Public Surfaces
- Groups
- Snippets
- Help pages
- Built-in search functionality — try searching for `password`, `key`, `secret`, `api`, etc.

### Step 3 — Try Self-Registration
If enabled, register an account (`/users/sign_up`) to potentially unlock **internal** (not just public) projects.

### Username & Email Enumeration (Even Without Registration)
Even if the **Sign-up enabled** checkbox is off in settings, the `/users/sign_up` **page itself is still reachable**, and its validation still leaks information:

- Registering with an existing username (e.g. `root`) → *"Username is already taken"*
- Registering with an existing email → *"Email has already been taken"*

> [!important] Practical impact
> This lets you build a **valid list of company usernames/emails** purely from registration-form error messages — no successful login needed. As of the time of writing, this technique worked against the latest GitLab version.

### After Registering (example: `hacker:Welcome`)
Once logged in, revisit `/explore` — previously-hidden **internal** projects can now appear (e.g. an "Inlanefreight website" project). Depending on the project type (PHP app, scripts, configs), this can lead to:
- Source code review for vulnerabilities
- Hardcoded credentials or secrets
- Hidden/undocumented functionality

## Mitigations
- Enforce 2FA on all accounts
- Use Fail2Ban (or similar) to throttle brute-force login attempts
- Restrict access by IP where the instance must be reachable outside the internal network
- Review sign-up flows for information leakage (username/email enumeration via error messages)

## Quick Recap
| Stage              | Technique                       | Result                                             |
| ------------------ | ------------------------------- | -------------------------------------------------- |
| Discovery          | Browse GitLab URL               | Confirms instance + login page                     |
| Fingerprint        | `/help` page (requires login)   | Confirms exact version, maps to known CVEs         |
| Enumerate (unauth) | `/explore`                      | Public projects — hunt for secrets                 |
| Enumerate (unauth) | `/users/sign_up` error messages | Valid usernames/emails, even with sign-up disabled |
| Enumerate (auth)   | Register + `/explore` again     | Access to internal projects                        |
