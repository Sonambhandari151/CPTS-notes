# Splunk — Discovery & Enumeration

## What Is Splunk?
Splunk is a **log analytics tool** for gathering, analysing, and visualising data. It wasn't originally built as a SIEM, but is widely used for security monitoring and business analytics. Splunk deployments often house sensitive data — a compromise can be very high-value for an attacker.

## Quick Facts
- Founded 2003, profitable 2009, IPO 2012 on NASDAQ (`SPLK`)
- 7,500+ employees, ~$2.4B annual revenue
- Named to Fortune 1000 (2020); clients include 92 Fortune 100 companies
- **Splunkbase** — app/add-on marketplace, 2,000+ apps (as of 2021)

## Known Vulnerabilities
Historically light on CVEs:
| CVE | Description |
|---|---|
| CVE-2018-11409 | Information disclosure |
| CVE-2011-4642 | Authenticated RCE (very old versions) |

> [!tip] Real focus during assessments
> Splunk is rarely vulnerable via CVE — the actual attack surface is almost always **weak or null authentication**. Admin access = ability to deploy custom apps = fast path to RCE on the Splunk host (and potentially others).

## Discovery / Footprinting

- Common in **internal** networks; rarely exposed externally.
- Often runs as **root** (Linux) or **SYSTEM** (Windows) — meaning RCE on Splunk = high-privilege shell.
- Splunk web UI default port: **8000**
- Splunk REST API / management port: **8089**

### Default / Weak Credentials
- Older versions: `admin:changeme` (often displayed right on the login page)
- Newer versions: creds set during install — if defaults fail, try common weak passwords: `admin`, `Welcome`, `Welcome1`, `Password123`, etc.

### Nmap Discovery
```bash
sudo nmap -sV 10.129.201.50

PORT     STATE SERVICE       VERSION
8000/tcp open  ssl/http      Splunkd httpd
8089/tcp open  ssl/http      Splunkd httpd
```
Ports 8000 (web UI) and 8089 (management/REST API) are the key fingerprints.

## Enumeration

### The "Forgotten Trial" Problem
Splunk Enterprise trials **auto-convert to the free version after 60 days** — and the free version has **no authentication at all**. Admins spin up trials to test Splunk, forget about them, and the instance silently becomes wide open. Some orgs also deliberately run the free version due to budget constraints, not realising it means zero user/role management.

Once inside (whether logged in or via the unauthenticated free version), you can:
- Browse data, run reports, build dashboards
- Install apps from Splunkbase
- **Install custom applications** ← the key to RCE

### Code Execution Surfaces in Splunk
Splunk supports several ways to run code:
- Server-side Django apps
- REST endpoints
- **Scripted inputs** (most commonly abused)
- Alerting scripts

**Scripted inputs** exist to integrate Splunk with external data sources (APIs, file servers) that need custom access logic. Splunk runs the script and treats its STDOUT as input data. Since scripted inputs can run **Bash, PowerShell, or Batch** (and every Splunk install ships with **Python**), this is a direct code-execution primitive.

> [!important] The fast path to RCE
> Build a scripted input that tells Splunk to execute a Python (or PowerShell) reverse shell script. Covered in the follow-up "Attacking Splunk" section.

Splunk has also had public vulnerabilities like an SSRF allowing unauthorised REST API access. At time of writing: **47 CVEs total** — but vulnerability scans often return mostly non-exploitable findings, which is why understanding **built-in functionality abuse** matters more than chasing CVEs here.

## Quick Recap
| Stage      | Technique                      | Result                                         |
| ---------- | ------------------------------ | ---------------------------------------------- |
| Recon      | `nmap -sV`                     | Confirms Splunk on 8000/8089                   |
| Auth check | Default creds / weak passwords | Admin access, or free-tier = no auth needed    |
| Abuse      | Custom app w/ scripted input   | Native path to RCE with SYSTEM/root privileges |
